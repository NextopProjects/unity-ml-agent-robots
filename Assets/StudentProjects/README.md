# 자율 프로젝트 — 내 ML-Agents 환경 만들기

RobotArms · Humanoid 는 **정해진 길을 따라가는 실습**이었다.
여기서부터는 **과제를 직접 정하고, 환경을 직접 만들고, 학습이 안 되는 이유를 직접 찾는다.**

| | |
|---|---|
| 목표 | RollerBall 크기의 환경을 **처음부터 혼자** 만들어 학습시키고, 확장 하나를 더해 본다 |
| 크기 | 관측 15칸 이하 · 행동 4개 이하 · 에이전트 1종 |
| 학습 시간 | **첫 학습은 30분 안에 결과가 보여야 한다.** 안 보이면 과제를 줄인다 |
| 도구 | opencode 같은 AI 코딩 도구 사용 가능 — 단, 규칙이 있다 (아래 4번) |
| 결과물 | 설계서 1장 · 동작 영상 · 학습 그래프 · **실패 기록** · 5분 발표 |

> 판단 기준은 실습 때와 같다.
> **"이 요소를 빼면 ML-Agents 개념 하나를 못 배우는가?"** 아니면 넣지 않는다.
> 멋진 그래픽 · 복잡한 맵 · 정교한 물리는 점수에 들어가지 않는다.

---

## 1. 진행 순서 (4회차 기준)

| 회차 | 할 일 | 끝났다는 증거 |
|---|---|---|
| 1 | 과제 고르기 · **설계서** 작성 · 바닥과 물체 배치 | 설계서 표가 다 채워짐, 씬에 에이전트·목표가 놓임 |
| 2 | Agent 코드 · **Heuristic 으로 사람이 먼저 풀기** · 첫 학습 | 키보드로 성공 1회 영상, 보상 그래프가 오르기 시작 |
| 3 | 보상 · 종료 조건 고치기 · 병렬 영역으로 학습 속도 올리기 | 성공률(또는 평균 보상)이 정해 둔 기준을 넘음 |
| 4 | **확장 하나**(아래 표의 "다음 단계") · 발표 준비 | 확장 전/후 그래프 비교 |

실습 원칙을 그대로 지킨다.

1. **사람이 키보드로 못 하면 AI 도 못 한다.** 학습 전에 `Behavior Type = Heuristic Only` 로 직접 풀어 본다.
2. **한 번에 하나만 바꾼다.** 보상과 관측을 같이 바꾸면 무엇 때문에 나아졌는지 모른다.
3. **숫자는 재서 적는다.** "잘 되는 것 같다"가 아니라 "20판 중 17판 성공".
4. **학습이 안 되면 보상보다 환경을 먼저 의심한다.** 목표가 닿을 수 없는 곳에 생기지 않는가?

## 2. 과제 고르기

과제마다 자료가 네 가지 있다. **플레이 초안으로 게임을 먼저 만져 보고 → 기획서로 설계를 보고 → 안내서로 만든다.**

| 자료 | 위치 | 무엇을 보나 |
|---|---|---|
| **플레이 초안** (HTML) | `Play~/index.html` — 더블클릭해 브라우저로 | 게임이 어떻게 흘러가고, 결정마다 관측 · 행동 · 보상이 어떻게 오가는지 직접 조작하며 본다. 사람 / 무작위(학습 전) / 규칙(학습 후 예시) 모드, 불리는 ML-Agents 메서드, C# 코드 뼈대 |
| **개발 기획서** (PDF, 21쪽) | `Games/<과제>.pdf` | 프로젝트 개요 → 게임 디자인(컨셉 · 플레이 방식 · 단계별 플레이 과정 · 점수와 승패 · 등장 요소 · 사람 조작) → 강화학습 설계(게임 → 강화학습 대응 · 관측 · 행동 · 보상 · 보상이 만드는 플레이 · 에피소드) → 학습 계획(학습 환경 · 개발 단계 · 예상 문제). 숫자는 **예시 설계** |
| **개발 기획서** (md) | `Games/<과제>-기획서.md` | PDF 와 같은 내용을 글과 표로 (같은 데이터에서 만든다) |
| **만드는 법 안내서** (md) | `Games/<과제>.md` | 장면 구성 · 설계 · 만드는 순서 · 함정 · opencode 에 맡길 때 — 막혀서 구체적인 구성이 필요할 때 |

| 난이도 | 과제 (안내서 링크) |
|---|---|

> 플레이 초안은 브라우저용 단순 물리다. 힘 · 속도 · 기준 숫자는 기획서와 같지만 Unity 물리와 똑같이 움직이지는 않는다.
> '규칙' 모드는 학습된 신경망이 아니라 손으로 짠 규칙이다 — 주차(G)처럼 손 규칙으로도 잘 안 되는 과제가 바로 강화학습이 필요한 곳이다.

난이도별로 하나를 고른다. 자기 아이디어도 좋지만 **아래 표와 같은 칸(관측 · 행동 · 보상 · 끝)을 채울 수 있어야** 한다.
"새로 배우는 개념"이 겹치지 않게 조원끼리 나눠 고르면 발표 때 서로 배울 것이 많다.

학습 시간은 **예상치**다 (병렬 영역 9개 이상 · 노트북 CPU 기준). 실제로 잰 시간을 설계서에 적는다.

### ★ 입문 — RollerBall 을 조금 바꾼 것 (예상 10~30분)

| 과제 | 에이전트가 할 일 | 관측(예) | 행동 | 보상 · 끝 | 새로 배우는 개념 | 다음 단계 |
|---|---|---|---|---|---|---|
| **A. 동전 모으기** | 바닥의 동전을 계속 먹는다 (먹으면 다른 자리에 다시 생김) | 내 속도, 동전까지 상대 위치 (4) | 연속 2 (힘 x, z) | 동전 +1 · 떨어지면 끝 · MaxStep 으로 끝 | **판을 끝내지 않는 반복 과제** · 에피소드 길이 해석 | 동전 3개 동시에 · 가장 가까운 것 관측 |
| **B. 멈춰서 도착** | 목표 칸 안에 **멈춰** 선다 | RollerBall 8 | 연속 2 | 칸 안 + 속도 < 0.2 → +1 | **성공 조건이 보상을 만든다** (지나치기 vs 멈추기) | 정지 시간 1초 이상 요구 |
| **C. 이산 이동** | 격자 위에서 목표까지 간다 | 내 위치, 목표 위치 (4) | **이산 1 (5갈래: 정지·상하좌우)** | 도착 +1 · 스텝마다 −0.001 | **이산 행동** · 시간 벌점 | 벽 칸 추가 + **행동 마스킹** |
| **D. 막대 세우기** | 수레를 좌우로 움직여 경첩 막대를 세운다 | 수레 위치·속도, 막대 각도·각속도 (4) | 연속 1 | 서 있는 동안 스텝마다 +0.01 · 45° 넘으면 끝 | **"버티기" 보상** · MaxStep 필요성 | 막대 위에서 무작위로 밀기 (Humanoid 3장처럼) |

### ★★ 중급 — 개념 하나를 새로 써야 하는 것 (예상 30~90분)

| 과제 | 에이전트가 할 일 | 관측(예) | 행동 | 보상 · 끝 | 새로 배우는 개념 | 다음 단계 |
|---|---|---|---|---|---|---|
| **E. 장애물 피해 도착** | 무작위 기둥 사이로 목표까지 | 내 속도, 목표 방향 + **Ray Perception Sensor 3D** | 연속 2 | 도착 +1 · 충돌 −0.5 끝 | **센서 컴포넌트** (관측을 코드로 안 적는다) | 움직이는 장애물 |
| **F. 상자 밀어 넣기** | 상자를 밀어 골 칸에 넣는다 | 내 위치, 상자 위치, 골 위치 (9) | 연속 2 | 상자–골 거리 줄면 + (상한) · 골인 +1 | **진전 보상과 상한** (RobotArms 4장) | 상자 2개 · 골 2칸 |
| **G. 주차** | 앞뒤·조향으로 칸에 **방향까지 맞춰** 선다 | 상대 위치 2, 방향 차 sin·cos 2, 속도 2 (6) | 연속 2 (가속, 조향) | 위치·방향 오차 작음 + 정지 → +1 | **각도는 sin·cos 으로** · 비홀로노믹 이동 | 다른 차 사이 좁은 칸 · 후진 주차 |
| **H. 착륙선** | 추력으로 패드에 살짝 내린다 | 높이·위치, 속도, 기울기, 남은 연료 (7) | 연속 2 (주 추력, 좌우 추력) | 착지 속도 < 1 → +1 · 세게 닿으면 −1 · 연료 쓸 때 소량 − | **벌점 크기 조절** (벌점이 크면 "아예 안 움직이기"를 배운다) | 바람(무작위 옆 힘) |
| **I. 공 받아치기** | 떨어지는 공을 패들로 받아 위로 올린다 | 패들 위치, 공 위치·속도 (7) | 연속 1~2 | 받을 때마다 +0.1 · 공이 떨어지면 끝 | **Decision Period** 와 반응 속도 · 관측 쌓기(Stacked Vectors) | 공 2개 |

### ★★★ 도전 — 둘 이상의 에이전트 / 단계 과제 (예상 1~3시간, 첫 결과는 30분 안에)

| 과제 | 에이전트가 할 일 | 새로 배우는 개념 | 줄여서 시작하는 법 |
|---|---|---|---|
| **J. 술래잡기** | 도망자 vs 술래 | **두 Behavior · 셀프 플레이** | 술래를 먼저 "곧장 쫓아오는 코드"로 고정하고 도망자만 학습 |
| **K. 2관절 팔로 버튼 누르기** | 평면 2관절 팔이 무작위 버튼을 누른다 | RobotArms 3장을 **혼자 다시 만들기** · 도달 범위 검증 | 관절 2개 · 버튼 높이 고정 |
| **L. 커리큘럼으로 멀리** | A~I 중 하나를 "목표 거리 점점 멀리"로 | **커리큘럼** (`environment_parameters`) · 성공률로 난이도 조절 (Humanoid 6장) | 고정 2단계(가까이 → 멀리)부터 |
| **M. 시연으로 배우기** | 사람 플레이를 녹화해 학습을 돕는다 | **Demonstration Recorder · GAIL / BC** | 시연 20판 녹화 → 같은 과제에서 PPO 만 vs PPO+GAIL 비교 |

> RobotArms · Humanoid 를 개조하는 과제는 **권하지 않는다.** 학습 한 번이 수 시간이라 4회차 안에 실험을 몇 번 못 돌린다.
> 하고 싶다면 "이미 학습된 모델에 관측 하나만 바꾸면?" 처럼 질문 하나로 좁힌다.

## 3. 설계서 — 코드 쓰기 전에 이 표부터 (1장)

```
과제 이름 :
한 문장   : 에이전트는 ______ 하면 성공이다.
사람이 해 봤나 : 키보드로 __판 중 __판 성공 (조작 키: ______)

관측 (총 __칸)               | 왜 필요한가 (빼면 무엇을 모르는가)
  1.                         |
  2.                         |
행동 (연속 __ / 이산 __)     | 값 → 무슨 일이 일어나나 (-1 / 0 / +1)
  1.                         |
보상                         | 언제 · 얼마 · 한 판에 최대 몇 번
  +                          |
  −                          |
판이 끝나는 때               | 성공 / 실패 / MaxStep = __
무작위로 바꾸는 것           | (매 판 같은 자리면 자리를 외운다)
성공 기준                    | 예: 같은 씨앗으로 20판 중 15판 성공
예상 학습 시간 / 실제        |   분 /   분 (max_steps = __ , 영역 __개)
```

**관측 칸마다 "왜"를 못 적으면 그 칸은 지운다.** 관측이 적을수록 학습이 빠르다.

## 4. opencode(AI 코딩 도구) 사용 규칙

AI 에게 맡겨도 되는 것과 **직접 해야 하는 것**을 나눈다. 이 프로젝트에서 배울 것은 코드 문법이 아니라 **관측 · 행동 · 보상을 설계하는 판단**이기 때문이다.

| AI 에게 맡겨도 된다 | 직접 한다 |
|---|---|
| 씬 배치 · 머티리얼 같은 반복 작업 | **설계서** (관측 · 행동 · 보상 · 종료) |
| `Heuristic` 키 매핑, 영역 복제 에디터 스크립트 | 보상 숫자 정하기 · 바꾸기 |
| 컴파일 에러 · API 이름 찾기 | 학습 결과 해석 (그래프가 왜 이런가) |
| yaml 기본 틀 | 실패 기록 쓰기 |

규칙

1. **설계서를 먼저 쓰고, 그 표를 AI 에게 준다.** "공 굴리는 거 만들어 줘"가 아니라 "이 관측 7칸 · 행동 2개 · 이 보상으로 Agent 를 만들어 줘".
2. **AI 가 쓴 줄은 전부 설명할 수 있어야 한다.** 발표 때 아무 줄이나 짚어서 묻는다. 설명 못 하는 줄은 지운다.
3. **보상을 AI 가 바꾸게 두지 않는다.** "학습이 잘 되게 고쳐 줘"는 금지. 무엇을 왜 바꿀지 내가 정하고, 바꾼 이유를 실패 기록에 적는다.
4. AI 가 만든 코드도 **실습 코드 원칙**을 따르게 한다: 짧게, 한 번 쓰는 값은 그 자리에 숫자 + 주석, `// = N` 관측 개수 주석.

프로젝트 폴더에 `AGENTS.md` 를 두면 opencode 가 매번 읽는다. 아래를 복사해 내 과제에 맞게 고친다.

```markdown
# AGENTS.md
Unity 6 + ML-Agents 4.0 학습용 프로젝트. 나는 강화학습을 배우는 학생이다.
- 참고 구현: Assets/RollerBall/RollerAgent.cs — 이 정도 길이와 구조를 유지한다.
- 설계는 DESIGN.md 에 있다. 관측 · 행동 · 보상 · 종료 조건은 거기 적힌 대로만 쓴다. 임의로 추가하지 않는다.
- 보상 값을 바꾸자고 제안만 하고, 직접 바꾸지 않는다.
- 새 Input System 을 쓴다 (Keyboard.current). 구 Input.GetKey 금지.
- 주석은 // 로 "왜"를 적는다. 관측 끝에 // = N 으로 개수를 적는다.
- 위치는 localPosition 을 쓴다 (영역을 복제해도 동작하도록).
```

## 5. 학습 시간 줄이는 법

| 방법 | 효과 | 주의 |
|---|---|---|
| **영역 복제** (같은 Behavior Name) | 9개면 경험이 약 9배 빨리 쌓인다 | 모든 위치는 `localPosition`. RollerBall 코드도 그렇다 |
| 관측 줄이기 · `normalize` | 네트워크가 작아도 된다 | 크기가 들쭉날쭉한 값(속도 등)은 나눠서 −1~1 근처로 |
| `max_steps` 작게 시작 (5만 → 50만) | 망한 설정을 빨리 버린다 | 보상이 아예 안 오르면 늘리지 말고 환경을 본다 |
| 빌드 + `--no-graphics` · `--time-scale 20` | 에디터보다 빠르다 | 빌드할 때 바뀐 ProjectSettings 는 되돌린다 |
| `MaxStep` 두기 | 끝나지 않는 실패 판이 없어진다 | 0 이면 판이 영원히 안 끝날 수 있다 |

시작 yaml (RollerBall 보다 버퍼를 키운 버전):

```yaml
behaviors:
  MyAgent:                 # Behavior Parameters 의 Behavior Name 과 같아야 한다
    trainer_type: ppo
    hyperparameters:
      batch_size: 256
      buffer_size: 4096
      learning_rate: 3.0e-4
      beta: 5.0e-3
      num_epoch: 3
    network_settings:
      normalize: true
      hidden_units: 128
      num_layers: 2
    reward_signals:
      extrinsic: { gamma: 0.99, strength: 1.0 }
    max_steps: 200000
    time_horizon: 64
    summary_freq: 5000
```

```
run_env.bat
mlagents-learn Assets/StudentProjects/<내폴더>/config.yaml --run-id=<이름>
tensorboard --logdir results
```

## 6. 실패 기록 — 가장 중요한 결과물

학습은 거의 항상 **엉뚱한 쪽으로** 먼저 간다. 그게 정상이고, 그걸 찾아 고치는 것이 이 프로젝트의 핵심이다.
Humanoid 6장 문서의 "학습이 엉뚱한 쪽으로 간 기록"과 같은 형식으로 적는다.

```
#회차  | 무엇을 봤나 (숫자로)               | 원인 추측           | 바꾼 것 하나        | 결과 (숫자로)
1      | 보상 0 에서 안 오름, 20만 스텝      | 목표가 너무 멀다     | 목표 범위 8→4      | 3만 스텝부터 오름
2      | 목표 근처에서 빙빙 돈다             | 지나쳐도 다시 오면 됨 | 정지 조건 추가      | ...
```

자주 나오는 증상은 루트의 `CLAUDE.md` "자주 밟는 함정" 표에 이미 있다. 거기서 먼저 찾아본다
(보상 폭주 · 잡았다 놨다 반복 · 자리를 외움 · 아무것도 안 했는데 성공 …).

## 7. 평가

| 항목 | 비중 | 보는 것 |
|---|---|---|
| 설계서 | 20% | 관측 칸마다 이유가 있는가 · 무작위화가 있는가 |
| 동작 | 25% | Heuristic 성공 영상 + 학습된 모델 성공률 (같은 씨앗, 20판) |
| 실패 기록 | 30% | **한 번에 하나씩** 바꿨는가 · 전후를 숫자로 비교했는가 |
| 확장 하나 | 15% | 확장 전/후 그래프 비교, 새 개념을 설명할 수 있는가 |
| 코드 이해 | 10% | 발표 중 무작위 줄 질문에 답하는가 (AI 가 쓴 줄 포함) |

학습이 끝까지 성공하지 못해도 **왜 안 되는지를 숫자로 좁혀 갔다면** 좋은 점수를 받는다.
반대로 잘 되는데 이유를 설명 못 하면 점수가 낮다.
