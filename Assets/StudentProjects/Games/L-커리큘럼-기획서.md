## 2. 게임 디자인

### 2-1. 게임 컨셉

**가까운 목표부터 멈추는 법을 익히고, 잘하면 목표가 점점 멀어진다**

|  |  |
|---|---|
| **핵심 재미** | 실력이 늘면 판이 어려워진다 — 게임의 레벨처럼 |
| **잘한 플레이** | 어느 단계에서든 가속 · 감속 · 정지를 지킨다 |
| **못한 플레이** | 단계가 오르자마자 무너지거나, 첫 단계에 갇힌다 |

### 2-2. 플레이 방식

한 판은 이렇게 흘러간다. 판이 끝날 때까지 **상황 보기 → 조작**을 반복한다.

```
[판 시작] 지금 단계의 거리로 목표
   ↓
[상황 보기] 거리 · 속도
   ↓
[조작] 밀기 / 브레이크
   ↓
[결과] 정지 +1 · 단계 판정
   ↺ (판이 끝날 때까지 상황 보기 → 조작 반복)
```

### 2-3. 플레이 과정 (단계별)

#### ① 단계 읽기 — 판 시작에 지금 난이도를 받는다

**게임에서 일어나는 일**

- 파이썬이 정한 '목표 거리'를 읽는다
- 그 거리 안에서 목표 원을 놓는다
- 처음 단계는 가까이 (2)

플레이어의 판단: *"이번 목표는 가깝다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 목표 − 공 (가까움), 속도 0 |
| 행동 | 첫 결정 전 |
| 보상 | 0 — GetWithDefault("goal_distance") |

#### ② 이동 · 감속 — B 와 같은 운전

**게임에서 일어나는 일**

- 목표 쪽으로 밀고
- 가까워지면 반대로 밀어 줄인다
- 보상은 아직 없다

플레이어의 판단: *"가까우니 일찍 줄이자"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 거리 줄고 속도 커짐 |
| 행동 | 목표 쪽 → 반대 힘 |
| 보상 | 0 |

#### ③ 정지 +1 — 원 안에서 멈추면 성공

**게임에서 일어나는 일**

- 원 안에서 멈춘다
- +1 받고 판 끝
- 성공 기록이 쌓인다

플레이어의 판단: *"성공!"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 거리 ≈ 0, 속도 ≈ 0 |
| 행동 | 브레이크 |
| 보상 | +1 — 판 끝 |

#### ④ 단계 오름 — 평균 보상이 문턱을 넘으면

**게임에서 일어나는 일**

- 최근 판의 평균 보상이 0.8 을 넘는다
- 다음 판부터 목표가 더 멀리 (4 → 6)
- 못 하면 그 단계에 머문다

플레이어의 판단: *"목표가 멀어졌다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 목표 − 공 (멀어짐) |
| 행동 | — |
| 보상 | 보상 구조는 그대로 — 거리만 바뀐다 |

### 2-4. 점수와 승패

판의 승패는 B 와 같다 — 커리큘럼은 '다음 판의 난이도'를 정한다

**정지 성공**
- 원 안 · 속도 < 0.2 → +1
- 성공이 쌓이면 단계 ↑

**실패**
- 떨어짐 · 500 스텝 초과
- 단계가 그대로 머문다

| 조건 | 판정 방법 (코드에서) | 결과 |
|---|---|---|
| 정지 성공 | 거리 < 0.7 · 속력 < 0.2 | +1 · 판 끝 |
| 단계 오름 | 최근 100판 평균 보상 > 0.8 (yaml) | 다음 판부터 목표 거리 ↑ |
| 실패 | y < 0 · Max Step 500 | 판 끝 |

### 2-5. 등장 요소

매 판 바뀌는 것이 있어야 에이전트가 자리를 외우지 않는다.

| # | 오브젝트 | 역할 | 컴포넌트 | 매 판 |
|---|---|---|---|---|
| 1 | 단계 1 (Near) | 목표 거리 2 | yaml lesson — value 2.0 | 문턱 넘으면 ↑ |
| 2 | 단계 2 (Mid) | 목표 거리 4 | yaml lesson — value 4.0 | 문턱 넘으면 ↑ |
| 3 | 단계 3 (Far) | 목표 거리 6 | yaml lesson — value 6.0 · 코드 기본값 | 마지막 |
| - | Agent · Target · Floor | B 와 같은 장면 | Rigidbody · Agent / 원판 / Plane | 거리만 바뀜 |

### 2-6. 사람 조작 (Heuristic)

| 키 | 하는 일 |
|---|---|
| W | +z 힘 |
| A | −x 힘 |
| S | −z 힘 |
| D | +x 힘 |

- **왜 먼저 사람이 하나** — 난이도 값을 손으로 바꿔 각 단계를 직접 풀어 본다. 가장 먼 단계를 사람이 못 하면 단계 설계가 틀린 것

- **기록해 둘 것** — 단계별(거리 2 · 4 · 6) 10판 중 성공 수를 적는다

## 3. 강화학습 설계

### 3-1. 게임 → 강화학습

결정할 때마다 관측을 보고 행동을 고르고, 그 결과로 보상을 받는다.

| 강화학습 |  | 이 게임에서 |
|---|---|---|
| Agent | 에이전트 | 공 (B 와 같음) |
| Environment | 환경 | 바닥 · 목표 + 지금 난이도 값 |
| Observation | 관측 | B 와 같음 — 난이도는 알려 주지 않는다 |
| Action | 행동 | B 와 같음 (연속 2) |
| Reward | 보상 | B 와 같음 — 원 안 정지 +1 |
| Episode | 에피소드 | B 와 같음 + 판 시작에 난이도 읽기 |

### 3-2. 관측 설계 (Observation) — 총 4칸

| 항목 | 칸 | 왜 필요한가 |
|---|---|---|
| 목표 − 공 (x, z) | 2 | B 와 같음 |
| 공의 속도 (x, z) | 2 | B 와 같음 |

칸 수를 Behavior Parameters 의 Space Size 와 맞춘다. 커리큘럼 실험 중에는 관측 · 행동 · 보상을 바꾸지 않는다 — 바꾸면 원인을 모른다

### 3-3. 행동 설계 (Action) — 연속 2

| 번호 | 값 | 하는 일 | 키보드 |
|---|---|---|---|
| 0 | −1 ~ +1 | x 방향 힘 × 10 | A / D |
| 1 | −1 ~ +1 | z 방향 힘 × 10 | W / S |

이번 실험의 변수는 '난이도 순서' 하나뿐이다

### 3-4. 보상 설계 (Reward)

한 판의 시간 순서:

```
단계 읽기 ── 이동 ── 감속 ── 정지(+1)  → 시간
```

| 사건 | 보상 | 판은? |
|---|---|---|
| 원 안 정지 | +1 | 판 끝 |
| 떨어짐 · 500 스텝 | 0 | 판 끝 |
| (단계 오름) | 보상 아님 | yaml 의 completion_criteria 가 판정 |

넘어가는 문턱은 쉬운 단계의 실제 평균 보상을 보고 정한다

### 3-5. 보상이 만드는 플레이

평균 보상 (한 판) — **예시 값, 실측 아님**:

| 학습 스텝 | 커리큘럼 (단계 1→2→3) | 처음부터 거리 6 |
|---|---|---|
| 0 | 0 | 0 |
| 60k | 0.7 | 0.02 |
| 120k | 0.5 | 0.1 |
| 180k | 0.85 | 0.3 |
| 240k | 0.75 | 0.5 |
| 300k | 0.85 | 0.68 |

- **이 보상이 유도하는 행동** — 보상은 그대로, 판의 거리만 점점 멀리 → 쉬운 판에서 익힌 감속을 먼 거리로 넓힌다

- **넣지 않은 보상과 이유** — 단계가 오를 때 보너스 보상 — 보상 크기가 바뀌어 그래프 비교가 깨진다. 단계는 보상이 아니라 환경이다

### 3-6. 에피소드 설계 (Episode)

| 단계 | 내용 |
|---|---|
| **시작할 때 (OnEpisodeBegin)** | goal_distance 읽기 (기본값 6)<br>그 거리 안에 목표 원<br>공 무작위, 속도 0 |
| **진행 (결정마다)** | B 와 같음<br>관측 4칸 → 행동 2개<br>정지 판정 |
| **끝 (EndEpisode)** | 정지 +1 · 떨어짐 · 500 스텝<br>→ 파이썬이 평균 보상으로<br>다음 단계 판정 |

> 코드의 기본값을 가장 어려운 값(6)으로 — 커리큘럼 없이 돌리면 그대로 비교 실험이 된다

## 4. 학습 계획

### 4-1. 학습 환경 구성

영역을 복제해 한 두뇌가 동시에 여러 판을 경험한다.

| 설정 | 예시 값 | 뜻 |
|---|---|---|
| Behavior Name | StopAtTarget | B 와 같게 |
| environment_parameters | goal_distance | C# 의 이름과 같게 |
| lesson 값 | 2 → 4 → 6 | 숫자 하나만 |
| completion_criteria | reward > 0.8, 100판 | 쉬운 단계를 보고 정한다 |
| max_steps (yaml) | 300,000 | 있음 · 없음 같은 값 |
| 예상 시간 | 30~60분 × 2 | 예상치 — 직접 잰다 |

### 4-2. 개발 단계

완료 기준을 넘어야 다음 단계로 간다.

| 단계 | 만들 것 | 완료 기준 |
|---|---|---|
| **1. 바탕 과제 준비** | B 멈춰서 도착 완성<br>목표 거리를<br>GetWithDefault 로 | 기본값으로 예전과 똑같이 동작 |
| **2. 기준선 학습** | 커리큘럼 없이<br>거리 6 으로 학습<br>스텝 수 고정 | 기준선 그래프 저장 |
| **3. 커리큘럼 학습** | yaml 에 lesson 3개<br>같은 스텝 수로 학습<br>Lesson 그래프 확인 | 단계가 2 → 3 까지 오른다 |
| **4. 비교 · 완성** | 거리 6 에서 20판씩<br>두 모델 평가<br>그래프 나란히 | 비교표 · 시연 영상 |

### 4-3. 예상 문제와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 단계가 안 넘어간다 | 문턱이 도달 불가능한 값 | 쉬운 단계의 실제 평균을 보고 정함 |
| 넘어가자마자 무너진다 | yaml 커리큘럼은 안 내려온다 | min_lesson_length 를 늘리거나 코드로 조절 |
| 기본값만 쓴다 | C# · yaml 이름 철자 다름 | "goal_distance" 를 양쪽에서 확인 |

> 한 번에 하나만 바꾸고, 바꾼 이유와 결과를 숫자로 기록한다.
