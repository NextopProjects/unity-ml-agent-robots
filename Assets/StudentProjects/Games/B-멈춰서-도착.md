# B. 멈춰서 도착 ★

> 공이 목표 칸 **안에 멈춰** 선다. 지나가기만 하면 성공이 아니다.

| | |
|---|---|
| 예상 학습 시간 | 15~30분 (영역 9개) — 예상치 |
| 새로 배우는 개념 | **성공 조건이 곧 행동을 만든다** — 조건 하나 바꾸면 전혀 다른 운전을 배운다 |
| 출발점 | `Assets/RollerBall` 복사 |

---

## 1. 목표 (성공 기준)

- 20판 중 **16판 이상** 목표 칸 안에서 멈춘다 (MaxStep 안에).
- RollerBall 그대로(멈춤 조건 없음) 학습한 모델과 **도착 순간 속도**를 비교해 표로 적는다.

## 2. RollerBall 과 비교

| | RollerBall | 멈춰서 도착 |
|---|---|---|
| 성공 | 목표와 거리 < 1.42 | 거리 < 0.7 **그리고 속력 < 0.2** |
| 배우는 운전 | 최고 속도로 돌진 | 가속 → **감속** → 정지 |
| MaxStep | 0 | **500** (목표 근처를 빙빙 도는 판을 끊는다) |

## 3. 장면 구성

```
StopArea
├── Floor     Plane 10×10
├── Agent     Sphere (0,0.5,0), Rigidbody, StopAgent ...
└── Target    Cylinder scale (1.4,0.01,1.4) — 바닥에 그린 원판. Collider 제거
```

- Target 은 **콜라이더를 지운다.** 공이 원판에 걸려 멈추면 "스스로 멈춘 것"이 아니다.
- 반지름 0.7 원판 = 성공 칸이 눈에 보이게.

## 4. 설계

| 관측 (4) | 왜 |
|---|---|
| 목표 − 나 (x, z) | 방향과 남은 거리 |
| 내 속도 (x, z) | **멈추려면 지금 속도를 알아야 한다.** 이 과제의 핵심 관측 |

행동: 연속 2 (x, z 힘) — RollerBall 과 같음.

| 보상 · 끝 | |
|---|---|
| 칸 안 + 속력 < 0.2 | **+1, 판 끝** |
| 떨어짐 | 판 끝 |
| MaxStep 500 | 판 끝 |

무작위: 목표 x, z ∈ [-4, 4], 공 시작 위치도 매 판 무작위 (공과 목표 2 이상 떨어지게).

## 5. 만드는 순서

1. RollerBall 씬 복사 → 이름 바꾸기 → Target 을 원판으로.
2. Heuristic 으로 **멈춰 보기.** 사람도 생각보다 어렵다. 속력 < 0.2 가 너무 빡빡하면 0.3 으로 (값을 바꾸면 기록).
3. 성공 조건을 바꾼다. 화면에 현재 속력을 띄우면(OnGUI 한 줄) 사람이 연습하기 쉽다.
4. 관측 4칸 · MaxStep 500 → 첫 학습.
5. **비교 실험:** 성공 조건만 RollerBall 식(거리만)으로 바꿔 한 번 더 학습 → 도착 속력 비교.

## 6. 자주 밟는 함정

| 증상 | 원인 |
|---|---|
| 목표 위를 왔다 갔다 하며 안 멈춘다 | 학습 초반엔 정상. 오래가면 속력 기준이 너무 빡빡하다 |
| 칸 가장자리에 걸쳐서 성공 | 반지름 기준을 공 중심으로 재는지 확인 |
| 보상이 0 에서 안 오른다 | 목표가 너무 멀다. 처음엔 [-2, 2] 로 좁혀서 오르는지 본다 (환경 먼저 의심) |

## 7. 다음 단계

  → "조건을 시간으로 늘리면" 보상이 늦어진다. 학습 시간이 얼마나 늘어나는지 잰다.
