## 2. 게임 디자인

### 2-1. 게임 컨셉

**광선 센서로 기둥을 보며 피해서 목표까지 간다**

|  |  |
|---|---|
| **핵심 재미** | 매 판 바뀌는 장애물 사이로 길을 찾는다 |
| **잘한 플레이** | 기둥 사이 틈을 골라 부드럽게 돌아 목표에 닿는다 |
| **못한 플레이** | 기둥에 정면으로 부딪히거나 겁먹고 제자리에 머문다 |

### 2-2. 플레이 방식

한 판은 이렇게 흘러간다. 판이 끝날 때까지 **상황 보기 → 조작**을 반복한다.

```
[판 시작] 기둥 · 목표 무작위
   ↓
[상황 보기] 목표 방향 · 광선
   ↓
[조작] 피하며 밀기
   ↓
[결과] 도착 +1 / 충돌 −
   ↺ (판이 끝날 때까지 상황 보기 → 조작 반복)
```

### 2-3. 플레이 과정 (단계별)

#### ① 판 시작 — 기둥 4개와 목표가 무작위로

**게임에서 일어나는 일**

- 공 · 목표 · 기둥 4개 배치
- 서로 1.5 이상 떨어지게
- 막힌 길이 없게

플레이어의 판단: *"어느 틈으로 가지?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 목표 방향 + 광선 7줄 |
| 행동 | 첫 결정 전 |
| 보상 | 0 — OnEpisodeBegin |

#### ② 센서로 보기 — 광선이 기둥에 맞으면 안다

**게임에서 일어나는 일**

- 광선 7줄을 부채꼴로 쏜다
- 기둥에 맞은 광선은 거리를 알려 준다
- 목표 방향은 숫자로 따로 본다

플레이어의 판단: *"정면에 기둥이 있다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 광선: 정면 기둥 거리 짧음 |
| 행동 | 아래쪽으로 비켜 밀기 |
| 보상 | 0 |

#### ③ 도착 +1 — 틈으로 빠져나가 목표에 닿는다

**게임에서 일어나는 일**

- 기둥 사이 틈으로 지나간다
- 목표에 닿으면 +1
- 판이 끝난다

플레이어의 판단: *"틈이 보였다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 목표 거리 ≈ 0 |
| 행동 | 목표 쪽 힘 |
| 보상 | +1 — 판 끝 |

#### ④ 충돌 −0.5 — 기둥에 부딪히면 판이 끝난다

**게임에서 일어나는 일**

- 기둥에 정면으로 부딪힌다
- −0.5 받고 판이 끝난다
- 새 판, 새 기둥 자리

플레이어의 판단: *"너무 늦게 피했다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | — |
| 행동 | — |
| 보상 | −0.5 — EndEpisode |

### 2-4. 점수와 승패

목표에 닿으면 이기고, 기둥에 닿으면 진다

**성공**
- 목표에 닿으면 +1
- 판 끝

**실패**
- 기둥 충돌 −0.5, 판 끝
- 떨어짐 · 1000 스텝 초과

| 조건 | 판정 방법 (코드에서) | 결과 |
|---|---|---|
| 도착 | 목표와 거리 < 0.8 | +1 · 판 끝 |
| 충돌 | OnCollisionEnter, 태그 Obstacle | −0.5 · 판 끝 |
| 시간 초과 · 떨어짐 | Max Step 1000 · y < 0 | 판 끝 |

### 2-5. 등장 요소

매 판 바뀌는 것이 있어야 에이전트가 자리를 외우지 않는다.

| # | 오브젝트 | 역할 | 컴포넌트 | 매 판 |
|---|---|---|---|---|
| 1 | Floor | 바닥 | Plane | 고정 |
| 2 | Agent | 공 = 에이전트 | Rigidbody · Agent · Ray Perception Sensor 3D | 무작위 |
| 3 | Pillar × 4 | 장애물 | Cylinder, 태그 Obstacle | 무작위 |
| 4 | Target | 목표 | Cube, 태그 Goal | 무작위 |

### 2-6. 사람 조작 (Heuristic)

| 키 | 하는 일 |
|---|---|
| W | +z 힘 |
| A | −x 힘 |
| S | −z 힘 |
| D | +x 힘 |

- **왜 먼저 사람이 하나** — 사람도 화면을 보고 피한다. 에이전트는 화면 대신 광선을 본다 — Scene 뷰에서 광선이 기둥에 맞아 색이 바뀌는지 꼭 확인

- **기록해 둘 것** — 10판 중 성공 · 충돌 판 수를 적는다

## 3. 강화학습 설계

### 3-1. 게임 → 강화학습

결정할 때마다 관측을 보고 행동을 고르고, 그 결과로 보상을 받는다.

| 강화학습 |  | 이 게임에서 |
|---|---|---|
| Agent | 에이전트 | 공 (광선 센서 포함) |
| Environment | 환경 | 바닥 · 기둥 · 목표 — ObstacleArea |
| Observation | 관측 | 목표 방향 · 속도 (코드) + 광선 (센서) |
| Action | 행동 | x · z 방향 힘 (연속 2) |
| Reward | 보상 | 도착 +1, 충돌 −0.5 |
| Episode | 에피소드 | 도착 · 충돌 · 떨어짐 · 1000 스텝 |

### 3-2. 관측 설계 (Observation) — 총 4칸

| 항목 | 칸 | 왜 필요한가 |
|---|---|---|
| 목표 − 공 (x, z) | 2 | 기둥에 가려도 목표 방향을 안다 |
| 공의 속도 (x, z) | 2 | 피하려면 지금 움직임을 알아야 |
| 광선 7줄 (센서) | 자동 | 기둥 · 목표가 어디 있는지 — Space Size 에 세지 않는다 |

칸 수를 Behavior Parameters 의 Space Size 와 맞춘다. 센서를 끈 모델과 충돌률을 비교하면 센서의 몫이 숫자로 보인다

### 3-3. 행동 설계 (Action) — 연속 2

| 번호 | 값 | 하는 일 | 키보드 |
|---|---|---|---|
| 0 | −1 ~ +1 | x 방향 힘 × 10 | A / D |
| 1 | −1 ~ +1 | z 방향 힘 × 10 | W / S |

공이 구르면 광선도 돈다 — Freeze Rotation 으로 미끄러지게 하거나 센서를 회전 없는 자식에

### 3-4. 보상 설계 (Reward)

한 판의 시간 순서:

```
판 시작 ── 피함 ── 피함 ── 도착(+1)  → 시간
```

| 사건 | 보상 | 판은? |
|---|---|---|
| 목표에 닿음 | +1 | 판 끝 (성공) |
| 기둥 충돌 | −0.5 | 판 끝 (실패) |
| 떨어짐 · 1000 스텝 | 0 | 판 끝 |

충돌 벌점이 크면 '아예 안 움직이기'를 배운다 — −0.5 에서 시작해 비교

### 3-5. 보상이 만드는 플레이

한 판의 누적 보상 — **예시 값, 실측 아님**:

| 스텝 | 피해서 도착 | 가만히 있기 | 충돌 |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 200 | 0 | 0 | -0.5 |
| 400 | 1 | 0 | -0.5 |
| 600 | 1 | 0 | -0.5 |
| 800 | 1 | 0 | -0.5 |
| 1000 | 1 | 0 | -0.5 |

- **이 보상이 유도하는 행동** — 도착 +1 이 충돌 −0.5 보다 크다 → 위험해도 피해서 가는 쪽이 이득

- **넣지 않은 보상과 이유** — 충돌 −5 같은 큰 벌점 — 가만히 있으면 0 이라 '움직이지 않기'가 가장 안전한 답이 된다

### 3-6. 에피소드 설계 (Episode)

| 단계 | 내용 |
|---|---|
| **시작할 때 (OnEpisodeBegin)** | 공 · 목표 · 기둥 4개 무작위<br>서로 1.5 이상 떨어지게<br>공 속도 0 |
| **진행 (결정마다)** | 관측 4칸 + 광선<br>행동 2개<br>충돌 · 도착 확인 |
| **끝 (EndEpisode)** | 도착 → +1<br>충돌 → −0.5<br>떨어짐 · Max Step 1000 |

> 기둥 자리가 매 판 바뀌어야 자리를 외우지 않고 '보고 피하기'를 배운다

## 4. 학습 계획

### 4-1. 학습 환경 구성

영역을 복제해 한 두뇌가 동시에 여러 판을 경험한다.

| 설정 | 예시 값 | 뜻 |
|---|---|---|
| Behavior Name | ObstacleDodge | yaml behaviors 키와 같게 |
| Decision Period | 5 | 5 물리 스텝마다 결정 |
| Max Step | 1000 | 약 20초 |
| 영역 수 | 9 (3 × 3) | 한 두뇌로 묶인다 |
| max_steps (yaml) | 500,000 | 처음엔 기둥 없이 5만 |
| 예상 시간 | 30~60분 | 예상치 — 직접 잰다 |

### 4-2. 개발 단계

완료 기준을 넘어야 다음 단계로 간다.

| 단계 | 만들 것 | 완료 기준 |
|---|---|---|
| **1. 장면 · 조작** | 바닥 · 기둥 · 목표<br>태그 Obstacle · Goal<br>키보드 조작 | 키보드로 피해서 도착 5판 |
| **2. 에이전트 연결** | 관측 4칸 · 행동 2개<br>광선 센서 붙이기<br>충돌 · 도착 판정 | 광선이 기둥에 맞는 것을 확인 |
| **3. 첫 학습** | 기둥 없이 먼저<br>그 다음 기둥 4개<br>충돌률 확인 | 도착 보상이 오르기 시작 |
| **4. 본 학습 · 완성** | 영역 9개 복제<br>50만 스텝 학습<br>모델 연결 | 15/20 성공, 시연 영상 |

### 4-3. 예상 문제와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 광선이 아무것도 못 봄 | 태그 철자 · 광선 높이 | Detectable Tags 와 오브젝트 태그 확인 |
| 광선이 빙글빙글 돈다 | 굴러가는 공에 센서 | Freeze Rotation 또는 회전 없는 자식 |
| 처음부터 충돌 | 기둥과 공이 겹쳐 생김 | 배치 간격 규칙 1.5 이상 |
