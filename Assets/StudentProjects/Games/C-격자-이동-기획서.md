## 2. 게임 디자인

### 2-1. 게임 컨셉

**말을 한 칸씩 움직여 목표 칸까지 가장 짧은 길로 간다**

|  |  |
|---|---|
| **핵심 재미** | 한 번에 한 칸 — 걸음 수가 곧 점수다 |
| **잘한 플레이** | 돌아가지 않고 최단 거리로 곧장 간다 |
| **못한 플레이** | 제자리걸음 · 벽에 박기 · 왔던 길 되돌아가기 |

### 2-2. 플레이 방식

한 판은 이렇게 흘러간다. 판이 끝날 때까지 **상황 보기 → 조작**을 반복한다.

```
[판 시작] 말 · 목표 칸 무작위
   ↓
[상황 보기] 내 칸 · 목표 칸
   ↓
[고르기] 상하좌우 · 가만히
   ↓
[결과] 한 칸 이동, 도착 +1
   ↺ (판이 끝날 때까지 상황 보기 → 조작 반복)
```

### 2-3. 플레이 과정 (단계별)

#### ① 판 시작 — 말과 목표 칸이 무작위 칸에

**게임에서 일어나는 일**

- 말을 무작위 칸에 둔다
- 목표 칸을 겹치지 않게 둔다
- 걸음 수 0

플레이어의 판단: *"목표까지 몇 칸이지?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 내 칸 (0,4), 목표 칸 (4,0) |
| 행동 | 첫 결정 전 |
| 보상 | 0 — OnEpisodeBegin |

#### ② 한 칸씩 이동 — 다섯 가지 중 하나를 고른다

**게임에서 일어나는 일**

- → 를 고르면 오른쪽으로 한 칸
- 걸음마다 작은 벌점
- 격자 밖은 움직이지 않음

플레이어의 판단: *"어느 쪽이 더 가까워지지?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 내 칸 (2,4) |
| 행동 | 이산 1 → 오른쪽 |
| 보상 | −0.001 (걸음마다) |

#### ③ 도착 +1 — 목표 칸에 들어가면 성공

**게임에서 일어나는 일**

- 목표 칸에 들어선다
- +1 받고 판이 끝난다
- 걸음이 적을수록 총점이 높다

플레이어의 판단: *"최단 거리였나?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 내 칸 = 목표 칸 |
| 행동 | ↑ |
| 보상 | +1 — 판 끝 |

#### ④ 판 끝 — 시간 초과 — 100 걸음 안에 못 가면

**게임에서 일어나는 일**

- 같은 칸을 맴돈다
- 100 걸음이 지나면 끝
- 벌점만 쌓인 채 새 판

플레이어의 판단: *"돌기만 했다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | — |
| 행동 | — |
| 보상 | −0.1 (벌점 합) — 판 끝 |

### 2-4. 점수와 승패

도착하면 이기고, 걸음이 적을수록 점수가 높다

**도착**
- 목표 칸에 들어가면 +1
- 걸음 벌점이 적을수록 고득점

**시간 초과**
- 100 걸음이 지나면 끝
- 그동안의 벌점만 남는다

| 조건 | 판정 방법 (코드에서) | 결과 |
|---|---|---|
| 도착 | 내 칸 == 목표 칸 | +1 · 판 끝 |
| 한 걸음 | 행동을 받을 때마다 | −0.001 |
| 시간 초과 | StepCount = Max Step (100) | 판 끝 (자동) |

### 2-5. 등장 요소

매 판 바뀌는 것이 있어야 에이전트가 자리를 외우지 않는다.

| # | 오브젝트 | 역할 | 컴포넌트 | 매 판 |
|---|---|---|---|---|
| 1 | Agent | 말 = 에이전트 | Cube — Rigidbody 없음 | 무작위 칸 |
| 2 | Target | 목표 칸 | Cube (얇게) | 무작위 칸 |
| 3 | Wall | 벽 칸 (확장) | Cube | 선택 |
| - | Floor · GridArea | 격자 바닥 · 영역 묶음 | Plane 7 × 7 · 빈 오브젝트 | - |

### 2-6. 사람 조작 (Heuristic)

| 키 | 하는 일 |
|---|---|
| ↑ | +z 한 칸 |
| ← | −x 한 칸 |
| ↓ | −z 한 칸 |
| → | +x 한 칸 |

- **왜 먼저 사람이 하나** — 키를 한 번 누르면 정확히 한 칸만 가야 한다. 이 감각이 이상하면 행동 설계가 틀린 것이다

- **기록해 둘 것** — 10판 동안 걸음 수와 최단 거리(|dx| + |dz|)를 나란히 적는다

## 3. 강화학습 설계

### 3-1. 게임 → 강화학습

결정할 때마다 관측을 보고 행동을 고르고, 그 결과로 보상을 받는다.

| 강화학습 |  | 이 게임에서 |
|---|---|---|
| Agent | 에이전트 | 말 |
| Environment | 환경 | 격자 · 목표 칸 — GridArea |
| Observation | 관측 | 내 칸, 목표 칸 (격자 크기로 나눔) |
| Action | 행동 | 이산 1가지, 5개 중 하나 |
| Reward | 보상 | 도착 +1, 걸음마다 −0.001 |
| Episode | 에피소드 | 도착 또는 100 걸음까지 |

### 3-2. 관측 설계 (Observation) — 총 4칸

| 항목 | 칸 | 왜 필요한가 |
|---|---|---|
| 내 칸 (x, z) ÷ 3 | 2 | 지금 어디인가 (−1 ~ 1 로 맞춤) |
| 목표 칸 (x, z) ÷ 3 | 2 | 어디로 가야 하나 |

칸 수를 Behavior Parameters 의 Space Size 와 맞춘다. '목표 − 내 칸' 2칸만 줘도 될까? 두 방식을 학습해 비교한다

### 3-3. 행동 설계 (Action) — 이산 5

| 번호 | 값 | 하는 일 | 키보드 |
|---|---|---|---|
| 0 | 정지 | 가만히 | — |
| 1 / 2 | +x / −x | 오른쪽 · 왼쪽 한 칸 | → / ← |
| 3 / 4 | +z / −z | 위 · 아래 한 칸 | ↑ / ↓ |

Behavior Parameters: Discrete Branches 1, Branch 0 Size 5

### 3-4. 보상 설계 (Reward)

한 판의 시간 순서:

```
판 시작 ── 걸음(−) ── 걸음(−) ── 걸음(−) ── 도착(+1)  → 시간
```

| 사건 | 보상 | 판은? |
|---|---|---|
| 목표 칸 도착 | +1 | 판 끝 (성공) |
| 한 걸음 | −0.001 | 계속 |
| 100 걸음 지남 | 0 | 판 끝 |

걸음 벌점의 합(최대 −0.1)이 도착 보상(+1)보다 훨씬 작아야 한다

### 3-5. 보상이 만드는 플레이

한 판의 누적 보상 — **예시 값, 실측 아님**:

| 스텝 | 최단 거리로 도착 | 돌아서 도착 | 못 감 (시간 초과) |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 20 | 0.992 | -0.02 | -0.02 |
| 40 | 0.992 | 0.96 | -0.04 |
| 60 | 0.992 | 0.96 | -0.06 |
| 80 | 0.992 | 0.96 | -0.08 |
| 100 | 0.992 | 0.96 | -0.1 |

- **이 보상이 유도하는 행동** — 도착은 +1, 걸음은 비용 → 같은 도착이라도 짧은 길이 더 높은 점수

- **넣지 않은 보상과 이유** — 큰 걸음 벌점 (예: −0.05) — 100 걸음이면 −5 가 되어 도착보다 '빨리 끝내기'가 중요해진다

### 3-6. 에피소드 설계 (Episode)

| 단계 | 내용 |
|---|---|
| **시작할 때 (OnEpisodeBegin)** | 말: 무작위 칸<br>목표: 겹치지 않는 무작위 칸<br>칸 좌표는 정수 −3 ~ 3 |
| **진행 (결정마다)** | 관측 4칸 → 행동 1개<br>한 칸 이동 (밖이면 무시)<br>걸음마다 −0.001 |
| **끝 (EndEpisode)** | 도착 → +1<br>Max Step 100<br>(Decision Period 1) |

> 물리가 없어 한 결정 = 한 칸. Decision Period 를 1 로 둔다

## 4. 학습 계획

### 4-1. 학습 환경 구성

영역을 복제해 한 두뇌가 동시에 여러 판을 경험한다.

| 설정 | 예시 값 | 뜻 |
|---|---|---|
| Behavior Name | GridWalker | yaml behaviors 키와 같게 |
| Decision Period | 1 | 한 결정 = 한 칸 |
| Max Step | 100 | 100 걸음 |
| 영역 수 | 9 (3 × 3) | 한 두뇌로 묶인다 |
| max_steps (yaml) | 100,000 | 물리가 없어 빠르다 |
| 예상 시간 | 5~15분 | 예상치 — 직접 잰다 |

### 4-2. 개발 단계

완료 기준을 넘어야 다음 단계로 간다.

| 단계 | 만들 것 | 완료 기준 |
|---|---|---|
| **1. 장면 · 조작** | 7 × 7 격자 · 말 · 목표<br>화살표 키 한 칸 이동<br>격자 밖 막기 | 키 한 번 = 정확히 한 칸 |
| **2. 에이전트 연결** | 관측 4칸 · 이산 5<br>도착 · 걸음 벌점<br>Max Step 100 | 도착 · 시간 초과로 판이 끝난다 |
| **3. 첫 학습** | yaml 작성<br>영역 1개, 3만 스텝<br>그래프 확인 | 성공률이 오르기 시작 |
| **4. 본 학습 · 완성** | 영역 9개 복제<br>10만 스텝 학습<br>모델 연결 | 19/20 도착, 걸음 ≤ 최단 × 1.3 |

### 4-3. 예상 문제와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 한 번 눌렀는데 여러 칸 | isPressed 로 키를 읽음 | wasPressedThisFrame 으로 읽는다 |
| 제자리에 멈춰 있다 | 걸음 벌점이 없음 | 걸음마다 −0.001 을 넣는다 |
| 벌점을 키웠더니 이상함 | 벌점 합 > 도착 보상 | 벌점 합이 +1 보다 훨씬 작게 |

> 한 번에 하나만 바꾸고, 바꾼 이유와 결과를 숫자로 기록한다.
