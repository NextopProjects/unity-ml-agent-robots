| 항목 | 내용 |

| 실패 | 1500 스텝 안에 못 넣음 |

## 2. 게임 디자인

### 2-1. 게임 컨셉

**상자 뒤로 돌아가 골 쪽으로 밀어 넣는다 — 내가 아니라 상자가 가야 한다**

|  |  |
|---|---|
| **핵심 재미** | 어느 쪽에서 밀어야 원하는 방향으로 갈까 — 각도 맞추기 |
| **잘한 플레이** | 상자 뒤편으로 돌아가 골과 일직선에서 민다 |
| **못한 플레이** | 옆에서 밀어 엉뚱한 쪽으로 보내거나 벽 구석에 박는다 |

### 2-2. 플레이 방식

한 판은 이렇게 흘러간다. 판이 끝날 때까지 **상황 보기 → 조작**을 반복한다.

```
[판 시작] 공 · 상자 · 골 무작위
   ↓
[상황 보기] 상자 · 골 방향
   ↓
[조작] 돌아가서 밀기
   ↓
[결과] 가까워지면 + · 골인 +1
   ↺ (판이 끝날 때까지 상황 보기 → 조작 반복)
```

### 2-3. 플레이 과정 (단계별)

#### ① 판 시작 — 공 · 상자 · 골이 무작위로

**게임에서 일어나는 일**

- 상자를 벽에서 1.5 이상
- 골을 상자와 2 이상 떨어지게
- 제한 1500 스텝

플레이어의 판단: *"상자를 어느 쪽에서 밀지?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 상자 방향, 골 − 상자 방향 |
| 행동 | 첫 결정 전 |
| 보상 | 0 — OnEpisodeBegin |

#### ② 상자 뒤로 — 골 반대편으로 돌아간다

**게임에서 일어나는 일**

- 상자의 골 반대편으로 이동
- 아직 상자는 안 움직였다
- 보상도 아직 없다

플레이어의 판단: *"상자와 골을 일직선에"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 상자 − 공 짧아짐 |
| 행동 | 상자 뒤쪽으로 힘 |
| 보상 | 0 |

#### ③ 밀기 — 진전 보상 — 상자가 골에 가까워질 때마다 조금씩

**게임에서 일어나는 일**

- 상자를 골 쪽으로 민다
- 가까워진 만큼 작은 보상
- 한 스텝 보상은 ±0.02 로 자른다

플레이어의 판단: *"방향이 틀어지면 다시 돌아가자"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 골 − 상자 거리 줄어듦 |
| 행동 | 골 쪽 힘 |
| 보상 | +진전 × 0.5 (상한 0.02) |

#### ④ 골인 +1 — 상자 중심이 골 칸 안에

**게임에서 일어나는 일**

- 상자 중심이 골 칸에 들어간다
- +1 받고 판이 끝난다
- 1500 스텝 안에 못 넣으면 실패

플레이어의 판단: *"들어갔다!"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 골 − 상자 ≈ 0 |
| 행동 | — |
| 보상 | +1 — SetReward, EndEpisode |

### 2-4. 점수와 승패

상자가 골에 들어가면 이긴다. 시간 안에 못 넣으면 진다

**골인**
- 상자 중심이 골 칸 안
- +1, 판 끝

**시간 초과**
- 1500 스텝 안에 못 넣음
- 진전 보상만 남고 판 끝

| 조건 | 판정 방법 (코드에서) | 결과 |
|---|---|---|
| 골인 | 상자 중심이 골 칸 (2 × 2) 안 | +1 · 판 끝 |
| 상자 진전 | 이전 거리 − 지금 거리 (상자 ↔ 골) | × 0.5, ±0.02 로 자름 |
| 시간 초과 | StepCount = Max Step (1500) | 판 끝 (자동) |

### 2-5. 등장 요소

매 판 바뀌는 것이 있어야 에이전트가 자리를 외우지 않는다.

| # | 오브젝트 | 역할 | 컴포넌트 | 매 판 |
|---|---|---|---|---|
| 1 | Walls | 벽 4개 (높이 0.5) | Cube × 4 | 고정 |
| 2 | Goal | 골 칸 (그림) | 얇은 Cube — 콜라이더 제거 | 무작위 |
| 3 | Box | 밀 상자 | Rigidbody (mass 1) | 무작위 (벽에서 1.5) |
| 4 | Agent | 공 = 에이전트 | Rigidbody · Agent | 무작위 |

### 2-6. 사람 조작 (Heuristic)

| 키 | 하는 일 |
|---|---|
| W | +z 힘 |
| A | −x 힘 |
| S | −z 힘 |
| D | +x 힘 |

- **왜 먼저 사람이 하나** — 상자 무게 · 마찰이 맞지 않으면 사람도 못 민다. 벽 구석에 낀 상자는 어떻게 되는지도 직접 본다

- **기록해 둘 것** — 키보드로 5판 넣어 보고 걸린 스텝 수를 적는다. 못 넣은 판은 왜 못 넣었는지

## 3. 강화학습 설계

### 3-1. 게임 → 강화학습

결정할 때마다 관측을 보고 행동을 고르고, 그 결과로 보상을 받는다.

| 강화학습 |  | 이 게임에서 |
|---|---|---|
| Agent | 에이전트 | 공 |
| Environment | 환경 | 벽 · 상자 · 골 — PushArea |
| Observation | 관측 | 상자 방향, 골 − 상자 방향, 속도들 |
| Action | 행동 | x · z 방향 힘 (연속 2) |
| Reward | 보상 | 상자 진전 (상한) + 골인 +1 |
| Episode | 에피소드 | 골인 또는 1500 스텝까지 |

### 3-2. 관측 설계 (Observation) — 총 8칸

| 항목 | 칸 | 왜 필요한가 |
|---|---|---|
| 상자 − 공 (x, z) | 2 | 상자로 가는 방향 |
| 골 − 상자 (x, z) | 2 | 상자를 밀 방향 |
| 공의 속도 (x, z) | 2 | 내 움직임 |
| 상자 속도 (x, z) | 2 | 밀고 있는가, 굴러가는가 |

칸 수를 Behavior Parameters 의 Space Size 와 맞춘다. 두 단계(상자로 가기 · 밀기)에 필요한 정보를 나눠 적으면 관측이 정해진다

### 3-3. 행동 설계 (Action) — 연속 2

| 번호 | 값 | 하는 일 | 키보드 |
|---|---|---|---|
| 0 | −1 ~ +1 | x 방향 힘 × 10 | A / D |
| 1 | −1 ~ +1 | z 방향 힘 × 10 | W / S |

힘이 약하면 상자가 안 밀리고, 세면 튕겨 나간다 — 키보드로 밀어 보며 정한다

### 3-4. 보상 설계 (Reward)

한 판의 시간 순서:

```
판 시작 ── 돌아가기 ── 밀기(+) ── 밀기(+) ── 골인(+1)  → 시간
```

| 사건 | 보상 | 판은? |
|---|---|---|
| 상자가 골에 가까워짐 | +진전 × 0.5 | 계속 (한 스텝 ±0.02 상한) |
| 상자 골인 | +1 | 판 끝 (성공) |
| 1500 스텝 지남 | 0 | 판 끝 |

끝 보상만으로는 첫 성공이 거의 오지 않는다 — 진전 보상이 길잡이

### 3-5. 보상이 만드는 플레이

한 판의 누적 보상 — **예시 값, 실측 아님**:

| 스텝 | 밀어서 골인 | 상자 옆 맴돌기 | 엉뚱하게 밀기 |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 300 | 0.1 | 0.02 | -0.1 |
| 600 | 0.4 | 0.03 | -0.25 |
| 900 | 1.5 | 0.03 | -0.3 |
| 1200 | 1.5 | 0.04 | -0.3 |
| 1500 | 1.5 | 0.04 | -0.3 |

- **이 보상이 유도하는 행동** — 상자가 골에 가까워질 때만 점수 → 상자 뒤로 돌아가 골 쪽으로 미는 플레이

- **넣지 않은 보상과 이유** — 공 ↔ 상자 거리 보상 — 상자에 붙어만 있고 밀지 않는 쪽으로 배울 수 있다

### 3-6. 에피소드 설계 (Episode)

| 단계 | 내용 |
|---|---|
| **시작할 때 (OnEpisodeBegin)** | 공 · 상자 · 골 무작위<br>상자는 벽에서 1.5 이상<br>이전 거리 기록 초기화 |
| **진행 (결정마다)** | 관측 8칸 → 행동 2개<br>상자 진전만큼 + (상한)<br>골인 확인 |
| **끝 (EndEpisode)** | 골인 → +1<br>Max Step 1500<br>(벽이 있어 안 떨어진다) |

> 판 시작에 '이전 거리'를 다시 재지 않으면 첫 스텝에 큰 보상이 튄다

## 4. 학습 계획

### 4-1. 학습 환경 구성

영역을 복제해 한 두뇌가 동시에 여러 판을 경험한다.

| 설정 | 예시 값 | 뜻 |
|---|---|---|
| Behavior Name | BoxPusher | yaml behaviors 키와 같게 |
| Decision Period | 5 | 5 물리 스텝마다 결정 |
| Max Step | 1500 | 약 30초 |
| 영역 수 | 9 (3 × 3) | 한 두뇌로 묶인다 |
| max_steps (yaml) | 1,000,000 | 처음엔 골을 크게 |
| 예상 시간 | 40~90분 | 예상치 — 직접 잰다 |

### 4-2. 개발 단계

완료 기준을 넘어야 다음 단계로 간다.

| 단계 | 만들 것 | 완료 기준 |
|---|---|---|
| **1. 장면 · 조작** | 벽 · 공 · 상자 · 골<br>상자 무게 조절<br>키보드 조작 | 키보드로 골인 5판 |
| **2. 에이전트 연결** | 관측 8칸 · 행동 2개<br>진전 보상 + 상한<br>골인 판정 | 보상 값이 튀지 않는다 |
| **3. 첫 학습** | 끝 보상만 vs 진전 보상<br>두 번 학습 비교<br>골 크게 시작 | 진전 보상 쪽이 먼저 성공 |
| **4. 본 학습 · 완성** | 영역 9개 복제<br>100만 스텝 학습<br>모델 연결 | 14/20 골인, 시연 영상 |

### 4-3. 예상 문제와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 상자 옆에서 맴돈다 | 진전 보상이 없거나 작음 | 상자 ↔ 골 진전 보상 × 0.5 |
| 보상이 크게 출렁인다 | 진전 보상에 상한 없음 | 한 스텝 ±0.02 로 자른다 |
| 아무것도 안 했는데 성공 | 상자가 골 안에서 생김 | 상자 ↔ 골 2 이상 떨어뜨린다 |
