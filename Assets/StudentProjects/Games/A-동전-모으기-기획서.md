## 2. 게임 디자인

### 2-1. 게임 컨셉

**공을 굴려, 계속 새로 생기는 동전을 시간 안에 최대한 많이 먹는다**

|  |  |
|---|---|
| **핵심 재미** | 먹는 순간 다음 동전이 생긴다 — 끝없이 이어지는 추격 |
| **잘한 플레이** | 동전 쪽으로 곧장 가되, 지나치지 않게 미리 줄인다 |
| **못한 플레이** | 동전을 지나쳐 빙빙 돌거나 가장자리로 굴러떨어진다 |

### 2-2. 플레이 방식

한 판은 이렇게 흘러간다. 판이 끝날 때까지 **상황 보기 → 조작**을 반복한다.

```
[판 시작] 공은 가운데 · 동전은 무작위
   ↓
[상황 보기] 동전 위치 · 내 속도
   ↓
[조작] 방향키로 공을 민다
   ↓
[결과] 먹으면 +1 · 동전이 새 자리로
   ↺ (판이 끝날 때까지 상황 보기 → 조작 반복)
```

### 2-3. 플레이 과정 (단계별)

#### ① 판 시작 — 공은 가운데, 동전은 무작위 자리

**게임에서 일어나는 일**

- 떨어졌던 판이면 공을 가운데로 되돌린다
- 동전을 바닥 [−4, 4] 의 무작위 자리에 놓는다
- 점수는 0 에서 시작한다

플레이어의 판단: *"동전이 어느 쪽에 있지?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 동전 − 공 = 오른쪽 위, 속도 0 |
| 행동 | 아직 없음 (첫 결정 전) |
| 보상 | 0 — OnEpisodeBegin |

#### ② 동전 쪽으로 — 방향키로 밀고, 가까워지면 줄인다

**게임에서 일어나는 일**

- 방향키(행동)로 공을 동전 쪽으로 민다
- 공이 굴러가며 속도가 붙는다
- 가까워지면 반대로 밀어 속도를 줄인다

플레이어의 판단: *"언제부터 줄여야 지나치지 않을까?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 거리는 줄고 속도는 커진다 |
| 행동 | 동전 쪽 힘 → 가까우면 반대 힘 |
| 보상 | 0 — 먹기 전엔 점수 없음 |

#### ③ 먹음 +1 — 판은 계속, 동전은 새 자리로

**게임에서 일어나는 일**

- 공과 동전의 거리가 0.8 보다 가까워진다
- 점수 +1, 동전이 새 자리로 옮겨 간다
- 판은 끝나지 않고 그대로 이어진다

플레이어의 판단: *"다음 동전은 어디지? 방향을 바꾸자"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 동전 위치가 갑자기 바뀐다 |
| 행동 | 새 방향으로 힘 |
| 보상 | +1 — AddReward |

#### ④ 판 끝 — 떨어지거나, 1000 스텝이 지나면

**게임에서 일어나는 일**

- 공이 바닥 밖으로 떨어지면 끝 (y < 0)
- 또는 1000 스텝이 지나면 끝
- 새 판이 시작된다 → ① 로

플레이어의 판단: *"가장자리에서는 조심해야 했다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | — |
| 행동 | — |
| 보상 | 0 — EndEpisode, 점수 확정 |

### 2-4. 점수와 승패

이 게임에는 '이기기'가 없다 — 판이 끝날 때의 점수가 곧 성적이다

**점수가 오르는 때**
- 동전에 닿으면 +1점
- 판은 계속된다 — 많이 먹을수록 좋다

**판이 끝나는 때**
- 떨어지면 끝 — 실패
- 1000 스텝이 지나면 끝 — 시간 종료

| 조건 | 판정 방법 (코드에서) | 결과 |
|---|---|---|
| 동전 먹기 | 공과 동전의 거리 < 0.8 | +1점 · 동전 새 자리 · 판 계속 |
| 떨어짐 | 공의 높이 y < 0 | 판 끝 — 남은 시간의 점수를 잃는다 |
| 시간 종료 | StepCount = Max Step (1000) | 판 끝 — ML-Agents 가 자동으로 |

### 2-5. 등장 요소

매 판 바뀌는 것이 있어야 에이전트가 자리를 외우지 않는다.

| # | 오브젝트 | 역할 | 컴포넌트 | 매 판 |
|---|---|---|---|---|
| 1 | Floor | 바닥 (10 × 10) | Plane | 고정 |
| 2 | Agent | 공 = 에이전트 | Rigidbody · Agent · Behavior Parameters · Decision Requester | 떨어지면 가운데로 |
| 3 | Coin | 목표 | Collider (Is Trigger) | 먹을 때마다 |
| - | CoinArea | 영역 묶음 | 빈 오브젝트 — 복제 단위 | - |

### 2-6. 사람 조작 (Heuristic)

| 키 | 하는 일 |
|---|---|
| W | +z 힘 |
| A | −x 힘 |
| S | −z 힘 |
| D | +x 힘 |

- **왜 먼저 사람이 하나** — 사람이 키보드로 못 먹으면 AI 도 못 먹는다. 힘의 크기 · 바닥 크기가 적당한지 여기서 정한다

- **기록해 둘 것** — 1000 스텝 동안 사람이 먹은 개수를 3판 재서 평균을 적는다 — 학습 결과와 비교할 기준선

## 3. 강화학습 설계

### 3-1. 게임 → 강화학습

결정할 때마다 관측을 보고 행동을 고르고, 그 결과로 보상을 받는다.

| 강화학습 |  | 이 게임에서 |
|---|---|---|
| Agent | 에이전트 | 공 |
| Environment | 환경 | 바닥 · 동전 · 물리 — CoinArea 한 개 |
| Observation | 관측 | 동전까지의 상대 위치, 공의 속도 |
| Action | 행동 | x · z 방향으로 미는 힘 (연속 2) |
| Reward | 보상 | 동전을 먹을 때 +1 |
| Episode | 에피소드 | 1000 스텝 또는 떨어질 때까지 (먹어도 계속) |

### 3-2. 관측 설계 (Observation) — 총 4칸

| 항목 | 칸 | 왜 필요한가 |
|---|---|---|
| 동전 − 공 (x, z) | 2 | 어느 쪽으로, 얼마나 가야 하나. 상대 위치라 공의 절대 위치는 필요 없다 |
| 공의 속도 (x, z) | 2 | 언제 줄여야 지나치지 않는가 |

칸 수를 Behavior Parameters 의 Space Size 와 맞춘다. 공의 절대 위치를 더 넣으면? 가장자리를 피하는 데 도움이 될까 — 넣고 빼서 비교해 본다

### 3-3. 행동 설계 (Action) — 연속 2

| 번호 | 값 | 하는 일 | 키보드 |
|---|---|---|---|
| 0 | −1 ~ +1 | x 방향 힘 × 10 | A / D |
| 1 | −1 ~ +1 | z 방향 힘 × 10 | W / S |

힘 배율 10 은 시작값이다. 키보드로 굴려 보고 '조작이 편한 값'으로 정한다

### 3-4. 보상 설계 (Reward)

한 판의 시간 순서:

```
판 시작 ── 동전 먹음(+1) ── 동전 먹음(+1) ── 동전 먹음(+1) ── 떨어짐(끝)  → 시간
```

| 사건 | 보상 | 판은? |
|---|---|---|
| 동전에 닿음 | +1 | 계속 (동전만 새 자리로) |
| 바닥에서 떨어짐 | 0 | 판 끝 |
| 1000 스텝 지남 | 0 | 판 끝 |

벌점이 하나도 없다. 떨어지면 '더 먹을 기회'를 잃는 것이 곧 벌이다

### 3-5. 보상이 만드는 플레이

한 판의 누적 보상 — **예시 값, 실측 아님**:

| 스텝 | 잘한 플레이 | 맴도는 플레이 | 떨어진 판 |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 200 | 2 | 1 | 2 |
| 400 | 4 | 1 | 2 |
| 600 | 6 | 2 | 2 |
| 800 | 8 | 3 | 2 |
| 1000 | 10 | 3 | 2 |

- **이 보상이 유도하는 행동** — 빨리, 많이 먹을수록 점수가 커진다 → 곧장 가서 지나치지 않고, 떨어지지 않는 플레이

- **넣지 않은 보상과 이유** — 동전에 가까워질 때마다 주는 보상 — 동전 주위를 맴돌며 점수를 버는 길이 생긴다. 이 게임은 먹을 때만 준다

### 3-6. 에피소드 설계 (Episode)

| 단계 | 내용 |
|---|---|
| **시작할 때 (OnEpisodeBegin)** | 떨어졌으면 공을 가운데로<br>동전은 바닥 [−4, 4] 무작위<br>공과 1.5 이상 떨어진 자리에만 |
| **진행 (결정마다)** | 관측 4칸 → 행동 2개<br>동전을 먹으면 +1, 동전만 옮김<br>판은 끝내지 않는다 |
| **끝 (EndEpisode)** | 떨어짐 (y < 0)<br>Max Step 1000<br>성공으로는 끝나지 않는다 |

> Max Step 이 없으면 판이 영원히 안 끝난다 — 반복 과제는 시간이 판을 끝낸다

## 4. 학습 계획

### 4-1. 학습 환경 구성

영역을 복제해 한 두뇌가 동시에 여러 판을 경험한다.

| 설정 | 예시 값 | 뜻 |
|---|---|---|
| Behavior Name | CoinCollector | yaml 의 behaviors 키와 같게 |
| Decision Period | 5 | 5 물리 스텝마다 한 번 결정 |
| Max Step | 1000 | 한 판의 길이 (약 20초) |
| 영역 수 | 9 (3 × 3) | 같은 Behavior Name 이면 한 두뇌 |
| max_steps (yaml) | 200,000 | 처음엔 50,000 으로 짧게 |
| 예상 시간 | 10~20분 | 예상치 — 실제로 재서 적는다 |

### 4-2. 개발 단계

완료 기준을 넘어야 다음 단계로 간다.

| 단계 | 만들 것 | 완료 기준 |
|---|---|---|
| **1. 장면 · 조작** | 바닥 · 공 · 동전 배치<br>키보드 조작 (Heuristic)<br>동전 먹기 · 다시 생기기 | 키보드로 플레이, 사람 기록 3판 |
| **2. 에이전트 연결** | 관측 4칸 · 행동 2개<br>보상 · Max Step<br>판 시작 무작위화 | 판이 정상적으로 시작 · 끝난다 |
| **3. 첫 학습** | yaml 작성<br>영역 1개, 5만 스텝<br>TensorBoard 확인 | 누적 보상이 오르기 시작 |
| **4. 본 학습 · 완성** | 영역 9개 복제<br>20만 스텝 학습<br>모델(.onnx) 연결 | 20판 평균 ≥ 사람 기록, 시연 영상 |

### 4-3. 예상 문제와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 판이 끝나지 않는다 | Max Step 이 0 | Max Step 1000 을 넣는다 |
| 시작하자마자 +1 | 동전이 공 바로 옆에 생김 | 공과 1.5 이상 떨어진 자리에만 만든다 |
| 에피소드 길이가 평평 | 반복 과제라 늘 1000 — 정상 | Cumulative Reward 그래프를 본다 |
