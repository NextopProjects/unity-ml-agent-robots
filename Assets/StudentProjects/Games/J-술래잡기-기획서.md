## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 장르 | 추격 · 대결 (2인) |
| 플레이어 | 도망자 (1단계) → 도망자와 술래 (2단계) |
| 목표 | 도망자: 오래 버티기 / 술래: 빨리 잡기 |
| 실패 | 도망자가 잡힘 (술래의 승리) |
| 학습 대상 | 상대의 움직임을 보고 피하기 · 몰기 |
| 새 개념 | Behavior 2개 동시 학습 · 셀프 플레이 |
| 예상 학습 | 1단계 30~60분 · 2단계 1~3시간 (예상치) |

장면: 벽으로 둘러싼 바닥, 도망자와 술래

## 2. 게임 디자인

### 2-1. 게임 컨셉

**술래를 피해 30초를 버틴다 — 다음엔 술래도 함께 배운다**

|  |  |
|---|---|
| **핵심 재미** | 상대가 나를 이기려고 움직인다 — 정답이 계속 바뀐다 |
| **잘한 플레이** | 도망자: 구석을 피해 넓은 곳으로 / 술래: 구석으로 몰기 |
| **못한 플레이** | 도망자가 구석에 갇히거나 술래가 헛돈다 |

### 2-2. 플레이 방식

한 판은 이렇게 흘러간다. 판이 끝날 때까지 **상황 보기 → 조작**을 반복한다.

```
[판 시작] 두 명 무작위 자리
   ↓
[상황 보기] 상대 위치 · 움직임
   ↓
[조작] 피하기 / 쫓기
   ↓
[결과] 잡히면 끝
   ↺ (판이 끝날 때까지 상황 보기 → 조작 반복)
```

### 2-3. 플레이 과정 (단계별)

#### ① 판 시작 — 도망자와 술래가 떨어져서

**게임에서 일어나는 일**

- 두 명을 멀리 떨어진 자리에
- 술래는 도망자보다 1.2배 빠름
- 제한 1500 스텝 (약 30초)

플레이어의 판단: *"술래는 어디서 오지?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 술래 − 나, 두 속도 |
| 행동 | 첫 결정 전 |
| 보상 | 0 — OnEpisodeBegin |

#### ② 피하기 — 넓은 쪽으로 돌아 도망

**게임에서 일어나는 일**

- 술래가 곧장 쫓아온다
- 도망자는 벽을 피해 돈다
- 버티는 동안 조금씩 점수

플레이어의 판단: *"구석으로 가면 안 된다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 술래가 가까워짐, 벽 거리 |
| 행동 | 옆으로 돌아 도망 |
| 보상 | +0.001 / 스텝 (도망자) |

#### ③ 끝까지 버팀 — 1500 스텝을 버티면 도망자 승

**게임에서 일어나는 일**

- 시간이 끝날 때까지 안 잡힘
- 도망자의 승리
- 술래는 그만큼 벌점

플레이어의 판단: *"버텼다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | — |
| 행동 | — |
| 보상 | 도망자 +1.5 누적 · 술래 −1.5 |

#### ④ 잡힘 — 거리 < 1 이면 판 끝

**게임에서 일어나는 일**

- 술래가 도망자를 잡는다
- 도망자 −1 · 술래 +1
- 두 명 모두 새 판

플레이어의 판단: *"구석에 몰렸다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | — |
| 행동 | — |
| 보상 | 도망자 −1 · 술래 +1 — 둘 다 EndEpisode |

### 2-4. 점수와 승패

도망자는 시간을 버티면 이기고, 술래는 잡으면 이긴다

**도망자 승**
- 1500 스텝 동안 안 잡힘
- 버틴 스텝마다 +0.001

**술래 승**
- 거리 < 1 이면 잡힘
- 도망자 −1 · 술래 +1

| 조건 | 판정 방법 (코드에서) | 결과 |
|---|---|---|
| 잡힘 | 도망자 ↔ 술래 거리 < 1 | 도망자 −1 · 술래 +1 · 둘 다 판 끝 |
| 버팀 | 매 스텝 | 도망자 +0.001 · 술래 −0.001 |
| 시간 종료 | StepCount = Max Step (1500) | 둘 다 판 끝 (도망자 승) |

### 2-5. 등장 요소

매 판 바뀌는 것이 있어야 에이전트가 자리를 외우지 않는다.

| # | 오브젝트 | 역할 | 컴포넌트 | 매 판 |
|---|---|---|---|---|
| 1 | Runner | 도망자 | Rigidbody · Agent (Behavior "Runner") | 무작위 |
| 2 | Chaser | 술래 | 1단계 코드 / 2단계 Agent ("Chaser") | 무작위 |
| 3 | Walls · Floor | 벽 · 바닥 | Cube × 4 · Plane | 고정 |
| - | TagArea | 판 관리 (둘 다 끝내기) | 빈 오브젝트 + 스크립트 | - |

### 2-6. 사람 조작 (Heuristic)

| 키 | 하는 일 |
|---|---|
| W | +z 힘 |
| A | −x 힘 |
| S | −z 힘 |
| D | +x 힘 |

- **왜 먼저 사람이 하나** — 술래 속도를 정하는 단계다. 같으면 영원히 못 잡고, 너무 빠르면 못 피한다 — 사람이 도망쳐 보고 정한다

- **기록해 둘 것** — 코드 술래를 상대로 사람이 버틴 스텝 수 5판

## 3. 강화학습 설계

### 3-1. 게임 → 강화학습

결정할 때마다 관측을 보고 행동을 고르고, 그 결과로 보상을 받는다.

| 강화학습 |  | 이 게임에서 |
|---|---|---|
| Agent | 에이전트 | 도망자 (2단계엔 술래도) |
| Environment | 환경 | 벽 · 바닥 · 상대 — TagArea |
| Observation | 관측 | 상대 위치 · 속도, 내 속도, 벽 거리 |
| Action | 행동 | x · z 방향 힘 (연속 2) |
| Reward | 보상 | 도망자 버티기 + · 잡히면 −1 (술래는 반대) |
| Episode | 에피소드 | 잡힘 또는 1500 스텝 — 둘 다 같이 끝 |

### 3-2. 관측 설계 (Observation) — 총 8칸

| 항목 | 칸 | 왜 필요한가 |
|---|---|---|
| 술래 − 나 (x, z) ÷ 10 | 2 | 도망칠 방향 |
| 내 속도 · 술래 속도 | 4 | 술래가 어디로 오고 있나 |
| 내 위치 (x, z) ÷ 5 | 2 | 벽 · 구석이 가까운가 |

칸 수를 Behavior Parameters 의 Space Size 와 맞춘다. 벽 정보(내 위치)를 빼면? 구석에 몰리는지 비교

### 3-3. 행동 설계 (Action) — 연속 2

| 번호 | 값 | 하는 일 | 키보드 |
|---|---|---|---|
| 0 | −1 ~ +1 | x 방향 힘 × 10 | A / D |
| 1 | −1 ~ +1 | z 방향 힘 × 10 (술래 × 12) | W / S |

두 몸을 같게, 속도만 다르게 — 그래야 '전략'만 비교된다

### 3-4. 보상 설계 (Reward)

한 판의 시간 순서:

```
판 시작 ── 버팀(+) ── 버팀(+) ── 버팀(+) ── 잡힘(−1)  → 시간
```

| 사건 | 보상 | 판은? |
|---|---|---|
| 버틴 스텝 (도망자) | +0.001 | 계속 (술래 −0.001) |
| 잡힘 | 도망자 −1 · 술래 +1 | 둘 다 판 끝 |
| 1500 스텝 | 0 | 둘 다 판 끝 |

상대가 배우면 내 그래프가 내려갈 수 있다 — 고정된 상대와 붙여 평가한다

### 3-5. 보상이 만드는 플레이

한 판의 누적 보상 — **예시 값, 실측 아님**:

| 스텝 | 끝까지 버팀 | 중간에 잡힘 | 구석에 몰려 바로 |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 300 | 0.3 | 0.3 | -0.9 |
| 600 | 0.6 | -0.55 | -0.9 |
| 900 | 0.9 | -0.55 | -0.9 |
| 1200 | 1.2 | -0.55 | -0.9 |
| 1500 | 1.5 | -0.55 | -0.9 |

- **이 보상이 유도하는 행동** — 도망자는 오래 버틸수록, 술래는 빨리 잡을수록 점수 — 한쪽의 점수가 다른 쪽의 벌

- **넣지 않은 보상과 이유** — 술래와 멀어질수록 주는 보상 — 벽에 붙어 멀리 있기만 하다 구석에 갇힌다. 버틴 시간만 센다

### 3-6. 에피소드 설계 (Episode)

| 단계 | 내용 |
|---|---|
| **시작할 때 (OnEpisodeBegin)** | 두 명 무작위, 5 이상 떨어지게<br>속도 0<br>TagArea 가 둘을 같이 리셋 |
| **진행 (결정마다)** | 각자 관측 8칸 → 행동 2개<br>버틴 스텝 보상<br>잡힘 확인 |
| **끝 (EndEpisode)** | 잡힘 → 둘 다 끝<br>Max Step 1500<br>한쪽만 끝내지 않는다 |

> 한쪽만 EndEpisode 하면 다른 쪽은 판이 이어진다 — 영역 스크립트가 둘을 같이 끝낸다

## 4. 학습 계획

### 4-1. 학습 환경 구성

영역을 복제해 한 두뇌가 동시에 여러 판을 경험한다.

| 설정 | 예시 값 | 뜻 |
|---|---|---|
| Behavior Name | Runner · Chaser | yaml 에 키 두 개 |
| Decision Period | 5 | 5 물리 스텝마다 결정 |
| Max Step | 1500 | 약 30초 |
| 영역 수 | 9 (3 × 3) | 둘 다 복제 |
| max_steps (yaml) | 1단계 50만 · 2단계 200만 | 2단계는 길다 |
| 예상 시간 | 1~3시간 | 예상치 — 직접 잰다 |

### 4-2. 개발 단계

완료 기준을 넘어야 다음 단계로 간다.

| 단계 | 만들 것 | 완료 기준 |
|---|---|---|
| **1. 장면 · 조작** | 벽 · 도망자 · 술래<br>코드 술래 (곧장 쫓기)<br>키보드로 도망 | 술래 속도 결정, 사람 기록 |
| **2. 도망자 학습** | 관측 8칸 · 행동 2개<br>버티기 보상 · 잡힘 −1<br>코드 술래 상대 | 평균 버틴 시간이 사람 이상 |
| **3. 술래도 Agent 로** | Behavior 2개<br>yaml 키 2개<br>둘 다 같이 학습 | 두 그래프가 오르내리며 학습 |
| **4. 엇갈려 붙이기 · 완성** | 코드 / 학습 × 2<br>모델 4개 대결표<br>시연 | 대결표 완성, 시연 영상 |

### 4-3. 예상 문제와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 한쪽만 새 판이 된다 | EndEpisode 를 한쪽만 부름 | TagArea 가 둘 다 끝낸다 |
| 도망자가 구석에서 안 나옴 | 벽 정보가 관측에 없음 | 내 위치를 관측에 넣는다 |
| 그래프가 오르락내리락 | 상대도 배우는 중 — 정상 | 고정된 상대와 붙여 평가 |

> 한 번에 하나만 바꾸고, 바꾼 이유와 결과를 숫자로 기록한다.
