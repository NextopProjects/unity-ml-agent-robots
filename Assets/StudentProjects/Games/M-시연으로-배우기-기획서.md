## 2. 게임 디자인

### 2-1. 게임 컨셉

**사람이 먼저 보여 주고, 에이전트는 그 시범에서 출발해 스스로 다듬는다**

|  |  |
|---|---|
| **핵심 재미** | 내 플레이가 AI 의 교과서가 된다 |
| **잘한 시연** | 같은 상황에서 늘 같은 방식 — 상자 뒤로 돌아가 민다 |
| **나쁜 시연** | 들쭉날쭉한 조작 — AI 가 습관까지 따라 한다 |

### 2-2. 플레이 방식

한 판은 이렇게 흘러간다. 판이 끝날 때까지 **상황 보기 → 조작**을 반복한다.

```
[사람 플레이] Heuristic 으로 성공 20판
   ↓
[녹화] .demo 파일 저장
   ↓
[학습] PPO + BC 또는 GAIL
   ↓
[에이전트 플레이] 시범보다 잘하기
   ↺ (판이 끝날 때까지 상황 보기 → 조작 반복)
```

### 2-3. 플레이 과정 (단계별)

#### ① 사람이 플레이 — 키보드로 성공 판을 녹화

**게임에서 일어나는 일**

- Behavior Type = Heuristic Only
- Demonstration Recorder 켜기
- 상자를 골에 넣는 판 20개

플레이어의 판단: *"늘 같은 방식으로 밀자"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 관측 8칸이 매 스텝 기록 |
| 행동 | 사람의 키보드 = 행동 |
| 보상 | 보상도 함께 기록 |

#### ② 시연 기록 — 관측과 행동의 쌍이 파일로

**게임에서 일어나는 일**

- Play 를 멈추면 .demo 파일 생성
- 판 수 · 평균 보상 확인
- Record 를 끈다

플레이어의 판단: *"성공 판이 충분한가?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | (관측, 행동) 쌍 수천 개 |
| 행동 | — |
| 보상 | 평균 보상 ≈ 1 |

#### ③ 따라 하며 시작 — BC — 사람의 선택을 흉내

**게임에서 일어나는 일**

- 학습 초반엔 시연을 따라 한다
- 첫 성공이 훨씬 빨리 온다
- 흉내 비중은 점점 줄인다

플레이어의 판단: *"사람처럼 상자 뒤로 간다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 관측 8칸 |
| 행동 | 시연과 비슷한 행동 |
| 보상 | 환경 보상 + 흉내 손실 |

#### ④ 스스로 다듬기 — PPO 가 시범보다 낫게 만든다

**게임에서 일어나는 일**

- 흉내 비중이 줄고 보상이 주도
- 사람보다 빠른 길을 찾기도
- 골인 +1

플레이어의 판단: *"시범에서 출발해 더 잘한다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 관측 8칸 |
| 행동 | 보상이 높은 쪽으로 다듬어짐 |
| 보상 | +1 — 골인 |

### 2-4. 점수와 승패

판의 승패는 F 와 같다 — 이 프로젝트의 성과는 '얼마나 빨리 배우는가'

**골인**
- 상자가 골 안 → +1
- 시연 덕에 첫 성공이 빠르다

**시간 초과**
- 1500 스텝 안에 못 넣음
- 나쁜 시연은 나쁜 습관을 옮긴다

| 조건 | 판정 방법 (코드에서) | 결과 |
|---|---|---|
| 골인 | 상자 중심이 골 칸 안 | +1 · 판 끝 |
| 상자 진전 | 상자 ↔ 골 거리 감소 | × 0.5, ±0.02 상한 (F 와 같음) |
| (BC · GAIL) | yaml 의 behavioral_cloning · gail | 보상이 아니라 학습 신호 — 따로 실험 |

### 2-5. 등장 요소

매 판 바뀌는 것이 있어야 에이전트가 자리를 외우지 않는다.

| # | 오브젝트 | 역할 | 컴포넌트 | 매 판 |
|---|---|---|---|---|
| 1 | 사람 · 키보드 | 시연하는 사람 | Heuristic (F 와 같은 키) | - |
| 2 | Demonstration Recorder | 녹화기 | Agent 오브젝트에 붙임 | 녹화 때만 켬 |
| 3 | PPO + BC / GAIL | 학습 설정 | yaml — demo_path | 실험마다 하나 |
| 4 | Agent · Box · Goal | F 와 같은 장면 | Rigidbody · Agent ... | F 와 같음 |

### 2-6. 사람 조작 (Heuristic)

| 키 | 하는 일 |
|---|---|
| W | +z 힘 |
| A | −x 힘 |
| S | −z 힘 |
| D | +x 힘 |

- **왜 먼저 사람이 하나** — 이 프로젝트에서는 사람의 플레이가 곧 학습 데이터다. 일관되게 조작해야 따라 하기 쉽다

- **기록해 둘 것** — 녹화한 판 수 · 성공 판 수 · 평균 보상 (.demo 파일 Inspector 에서 확인)

## 3. 강화학습 설계

### 3-1. 게임 → 강화학습

결정할 때마다 관측을 보고 행동을 고르고, 그 결과로 보상을 받는다.

| 강화학습 |  | 이 게임에서 |
|---|---|---|
| Agent | 에이전트 | 공 (F 와 같음) |
| Environment | 환경 | 벽 · 상자 · 골 (F 와 같음) |
| Observation | 관측 | F 와 같은 8칸 — 녹화 때와 같아야 한다 |
| Action | 행동 | F 와 같음 — 사람의 키 입력이 시연 행동 |
| Reward | 보상 | F 와 같음 + (BC 손실 또는 GAIL 보상) |
| Episode | 에피소드 | F 와 같음 |

### 3-2. 관측 설계 (Observation) — 총 8칸

| 항목 | 칸 | 왜 필요한가 |
|---|---|---|
| 상자 − 공 · 골 − 상자 | 4 | F 와 같음 |
| 공 · 상자 속도 | 4 | F 와 같음 |

칸 수를 Behavior Parameters 의 Space Size 와 맞춘다. 관측을 바꾸면 시연을 다시 녹화해야 한다 — 녹화 전에 관측을 굳힌다

### 3-3. 행동 설계 (Action) — 연속 2

| 번호 | 값 | 하는 일 | 키보드 |
|---|---|---|---|
| 0 | −1 ~ +1 | x 방향 힘 × 10 | A / D |
| 1 | −1 ~ +1 | z 방향 힘 × 10 | W / S |

잘 만든 Heuristic 이 곧 좋은 시연 녹화기다 — 키 입력이 행동과 같은 형태인가

### 3-4. 보상 설계 (Reward)

한 판의 시간 순서:

```
판 시작 ── 돌아가기 ── 밀기(+) ── 골인(+1)  → 시간
```

| 사건 | 보상 | 판은? |
|---|---|---|
| 환경 보상 (F 와 같음) | 진전 + 골인 +1 | 늘 켜 둠 |
| BC (따라 하기) | strength 0.5 | 처음 5만 스텝만 |
| GAIL (닮으면 보상) | strength 0.1 | BC 와 따로 실험 |

한 번에 하나씩 — PPO 만 / +BC / +GAIL 을 따로 학습해 비교한다

### 3-5. 보상이 만드는 플레이

평균 보상 (한 판) — **예시 값, 실측 아님**:

| 학습 스텝 | PPO + BC | PPO 만 | 서툰 시연 + BC |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 200k | 0.8 | 0.05 | 0.3 |
| 400k | 1.2 | 0.3 | 0.4 |
| 600k | 1.35 | 0.9 | 0.6 |
| 800k | 1.4 | 1.2 | 0.9 |
| 1M | 1.45 | 1.35 | 1.1 |

- **이 보상이 유도하는 행동** — 시연이 출발점, 환경 보상이 결승점 → 사람의 방식으로 시작해 보상으로 다듬기

- **넣지 않은 보상과 이유** — GAIL strength 를 환경 보상보다 크게 — 골에 넣기보다 '사람처럼 보이기'를 우선한다

### 3-6. 에피소드 설계 (Episode)

| 단계 | 내용 |
|---|---|
| **녹화 (Heuristic Only)** | Record 켜기<br>성공 판 약 20개<br>Play 멈춤 → .demo |
| **학습 (Default)** | Record 끄기<br>yaml 에 demo_path<br>PPO / +BC / +GAIL |
| **판 (F 와 같음)** | 시작: 무작위 배치<br>골인 +1 · 진전 보상<br>Max Step 1500 |

> 녹화를 켠 채 학습하면 .demo 가 계속 커진다 — 녹화가 끝나면 Record 를 끈다

## 4. 학습 계획

### 4-1. 학습 환경 구성

영역을 복제해 한 두뇌가 동시에 여러 판을 경험한다.

| 설정 | 예시 값 | 뜻 |
|---|---|---|
| Behavior Name | BoxPusher | F 와 같게 |
| demo_path | Demos/push_good.demo | 녹화 폴더 경로 |
| behavioral_cloning | strength 0.5 · steps 5만 | 초반만 따라 하기 |
| gail | strength 0.1 | 따로 실험 |
| max_steps (yaml) | 1,000,000 | 세 실험 같은 값 |
| 예상 시간 | 40~90분 × 3 | 예상치 — 직접 잰다 |

### 4-2. 개발 단계

완료 기준을 넘어야 다음 단계로 간다.

| 단계 | 만들 것 | 완료 기준 |
|---|---|---|
| **1. 바탕 과제 준비** | F 상자 밀기 완성<br>Heuristic 점검<br>관측 굳히기 | 키보드로 골인 안정적 |
| **2. 시연 녹화** | Recorder 붙이기<br>성공 20판 녹화<br>Record 끄기 | .demo · 평균 보상 ≈ 1 |
| **3. 세 가지 학습** | PPO 만<br>+BC · +GAIL<br>같은 스텝 수 | 세 그래프 저장 |
| **4. 비교 · 완성** | 첫 성공 스텝 비교<br>(선택) 서툰 시연<br>시연 영상 | 비교표 · 시연 영상 |

### 4-3. 예상 문제와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 학습 시작 시 demo 에러 | 관측 · 행동 크기가 녹화 때와 다름 | 관측을 바꿨으면 다시 녹화 |
| 사람 수준에서 멈춘다 | BC 비중이 너무 오래 큼 | behavioral_cloning steps 를 줄인다 |
| 흉내 점수만 오른다 | GAIL 이 환경 보상보다 큼 | gail strength 0.1 이하로 |

> 한 번에 하나만 바꾸고, 바꾼 이유와 결과를 숫자로 기록한다.
