## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 장르 | 균형 · 버티기 |
| 플레이어 | 레일 위를 좌우로 움직이는 수레 |
| 목표 | 제한 시간 끝까지 막대가 서 있게 |
| 실패 | 막대가 30° 넘게 기울거나 수레가 레일 끝 |
| 학습 대상 | 기우는 쪽으로 수레를 받쳐 주는 반응 |
| 새 개념 | 도착점이 없는 버티기 보상 |
| 예상 학습 | 영역 9개 · 10~30분 (예상치) |

장면: 레일 위 수레 하나와 수레에 달린 긴 막대

## 2. 게임 디자인

### 2-1. 게임 컨셉

**막대가 넘어지려는 쪽으로 수레를 움직여 끝까지 세워 둔다**

|  |  |
|---|---|
| **핵심 재미** | 손바닥 위 빗자루 세우기 — 늦으면 바로 넘어진다 |
| **잘한 플레이** | 작게, 자주 움직여 막대를 거의 수직으로 유지 |
| **못한 플레이** | 크게 휘두르다 넘어뜨리거나 레일 끝으로 달려간다 |

### 2-2. 플레이 방식

한 판은 이렇게 흘러간다. 판이 끝날 때까지 **상황 보기 → 조작**을 반복한다.

```
[판 시작] 막대 ±5° 무작위
   ↓
[상황 보기] 기울기 · 기우는 빠르기
   ↓
[조작] 수레를 좌우로
   ↓
[결과] 서 있으면 점수
   ↺ (판이 끝날 때까지 상황 보기 → 조작 반복)
```

### 2-3. 플레이 과정 (단계별)

#### ① 판 시작 — 막대가 살짝 기운 채 시작

**게임에서 일어나는 일**

- 수레를 가운데로, 속도 0
- 막대를 ±5° 무작위로 기울인다
- 점수 0, 제한 1000 스텝

플레이어의 판단: *"어느 쪽으로 기울었지?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 기울기 +4°, 각속도 0 |
| 행동 | 첫 결정 전 |
| 보상 | 0 — OnEpisodeBegin |

#### ② 기울어짐 — 기우는 쪽으로 수레를 받친다

**게임에서 일어나는 일**

- 막대가 오른쪽으로 기운다
- 수레를 오른쪽으로 민다
- 막대 아래가 따라가 다시 선다

플레이어의 판단: *"넘어지는 쪽으로 따라가자"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 기울기 +15°, 오른쪽으로 기우는 중 |
| 행동 | 오른쪽 힘 |
| 보상 | +0.01 (살아 있음) |

#### ③ 버티기 — 서 있는 동안 계속 점수

**게임에서 일어나는 일**

- 막대가 거의 수직
- 작게 좌우로 조절한다
- 매 스텝 +0.01

플레이어의 판단: *"작게, 자주 움직이자"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 기울기 ≈ 0, 각속도 ≈ 0 |
| 행동 | 작은 힘 |
| 보상 | +0.01 × 스텝 수 |

#### ④ 판 끝 — 넘어짐 — 30° 넘게 기울거나 레일 끝

**게임에서 일어나는 일**

- 막대가 30° 넘게 기운다
- 또는 수레가 레일 끝을 벗어남
- 더는 점수를 못 받고 새 판

플레이어의 판단: *"늦었다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 기울기 > 30° |
| 행동 | — |
| 보상 | 0 — EndEpisode |

### 2-4. 점수와 승패

이기는 순간이 없다 — 오래 버틸수록 점수가 높다 (1000 스텝 = 만점)

**점수가 쌓이는 때**
- 서 있는 스텝마다 +0.01
- 1000 스텝 버티면 만점 10

**판이 끝나는 때**
- 막대가 30° 넘게 기욺
- 수레가 레일 끝 (|x| > 4)

| 조건 | 판정 방법 (코드에서) | 결과 |
|---|---|---|
| 버팀 | 매 스텝 (넘어지지 않았으면) | +0.01 |
| 넘어짐 | \|막대 기울기\| > 30° | 판 끝 |
| 레일 이탈 | \|수레 x\| > 4 | 판 끝 |

### 2-5. 등장 요소

매 판 바뀌는 것이 있어야 에이전트가 자리를 외우지 않는다.

| # | 오브젝트 | 역할 | 컴포넌트 | 매 판 |
|---|---|---|---|---|
| 1 | Rail | 레일 (그림) | Cube — 콜라이더 제거 | 고정 |
| 2 | Cart | 수레 = 에이전트 | Rigidbody (x 만 이동) · Agent | 가운데로 |
| 3 | Pole | 막대 | Rigidbody · HingeJoint (수레에 연결) | ±5° 무작위 |
| - | PoleArea | 영역 묶음 | 빈 오브젝트 — 복제 단위 | - |

### 2-6. 사람 조작 (Heuristic)

| 키 | 하는 일 |
|---|---|
| A | 왼쪽 힘 |
| D | 오른쪽 힘 |

- **왜 먼저 사람이 하나** — 사람이 몇 초 버티는지가 난이도의 기준이다. 너무 어려우면 막대를 길게 (긴 막대가 천천히 넘어진다)

- **기록해 둘 것** — 키보드로 5판 버틴 스텝 수를 적는다. 막대 길이 · 무게를 바꿨다면 그 값도 적는다

## 3. 강화학습 설계

### 3-1. 게임 → 강화학습

결정할 때마다 관측을 보고 행동을 고르고, 그 결과로 보상을 받는다.

| 강화학습 |  | 이 게임에서 |
|---|---|---|
| Agent | 에이전트 | 수레 |
| Environment | 환경 | 레일 · 막대 · 관절 — PoleArea |
| Observation | 관측 | 수레 위치 · 속도, 막대 기울기 · 각속도 |
| Action | 행동 | 수레를 미는 힘 (연속 1) |
| Reward | 보상 | 서 있는 스텝마다 +0.01 |
| Episode | 에피소드 | 넘어짐 · 레일 이탈 · 1000 스텝 |

### 3-2. 관측 설계 (Observation) — 총 4칸

| 항목 | 칸 | 왜 필요한가 |
|---|---|---|
| 수레 x ÷ 4 | 1 | 레일 끝이 가까운가 |
| 수레 속도 | 1 | 얼마나 세게 움직이는 중인가 |
| 막대 기울기 (라디안) | 1 | 얼마나 기울었나 — 방향 벡터로 잰다 |
| 막대 각속도 | 1 | 넘어지는 중인가, 돌아오는 중인가 |

칸 수를 Behavior Parameters 의 Space Size 와 맞춘다. 각속도를 빼면? 같은 기울기라도 넘어지는 중인지 모른다 — 빼서 확인

### 3-3. 행동 설계 (Action) — 연속 1

| 번호 | 값 | 하는 일 | 키보드 |
|---|---|---|---|
| 0 | −1 ~ +1 | 수레 x 방향 힘 × 10 | A / D |

빠른 과제라 Decision Period 를 짧게 (1~2). 길면 반응이 늦는다

### 3-4. 보상 설계 (Reward)

한 판의 시간 순서:

```
판 시작 ── 버팀(+) ── 버팀(+) ── 버팀(+) ── 넘어짐(끝)  → 시간
```

| 사건 | 보상 | 판은? |
|---|---|---|
| 서 있는 스텝 | +0.01 | 계속 |
| 30° 넘게 기욺 | 0 | 판 끝 |
| 레일 끝 벗어남 | 0 | 판 끝 |

넘어짐에 벌점이 없다 — '이미 못 받는 보상'이 곧 벌이다

### 3-5. 보상이 만드는 플레이

한 판의 누적 보상 — **예시 값, 실측 아님**:

| 스텝 | 끝까지 버팀 | 중간에 넘어짐 | 바로 넘어짐 |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 200 | 2 | 2 | 0.4 |
| 400 | 4 | 3.5 | 0.4 |
| 600 | 6 | 3.5 | 0.4 |
| 800 | 8 | 3.5 | 0.4 |
| 1000 | 10 | 3.5 | 0.4 |

- **이 보상이 유도하는 행동** — 오래 살아 있을수록 점수 → 넘어지지 않게 작게, 자주 조절하는 플레이

- **넣지 않은 보상과 이유** — 넘어질 때 큰 벌점 (−10) — 판 초반에 일부러 빨리 끝내는 것이 '손해가 적은' 길이 될 수 있다

### 3-6. 에피소드 설계 (Episode)

| 단계 | 내용 |
|---|---|
| **시작할 때 (OnEpisodeBegin)** | 수레: 가운데, 속도 0<br>막대: ±5° 무작위<br>막대 속도 · 각속도 0 |
| **진행 (결정마다)** | 관측 4칸 → 행동 1개<br>서 있으면 +0.01<br>기울기 · 위치 확인 |
| **끝 (EndEpisode)** | 기울기 > 30°<br>\|수레 x\| > 4<br>Max Step 1000 |

> 되돌릴 때 속도 · 각속도를 0 으로 — 안 그러면 쓰러지던 힘이 남는다

## 4. 학습 계획

### 4-1. 학습 환경 구성

영역을 복제해 한 두뇌가 동시에 여러 판을 경험한다.

| 설정 | 예시 값 | 뜻 |
|---|---|---|
| Behavior Name | PoleBalance | yaml behaviors 키와 같게 |
| Decision Period | 2 | 빠른 과제 — 자주 결정 |
| Max Step | 1000 | 약 20초 = 만점 |
| 영역 수 | 9 (3 × 3) | 한 두뇌로 묶인다 |
| max_steps (yaml) | 300,000 | 처음엔 50,000 |
| 예상 시간 | 10~30분 | 예상치 — 직접 잰다 |

### 4-2. 개발 단계

완료 기준을 넘어야 다음 단계로 간다.

| 단계 | 만들 것 | 완료 기준 |
|---|---|---|
| **1. 장면 · 조작** | 레일 · 수레 · 막대<br>HingeJoint 연결<br>A / D 조작 | 막대가 혼자 넘어지고, 손으로 버틸 수 있다 |
| **2. 에이전트 연결** | 관측 4칸 · 행동 1개<br>버티기 보상<br>넘어짐 판정 | 넘어지면 판이 끝나고 다시 선다 |
| **3. 첫 학습** | yaml 작성<br>영역 1개, 5만 스텝<br>길이 그래프 | 에피소드 길이가 늘기 시작 |
| **4. 본 학습 · 완성** | 영역 9개 복제<br>30만 스텝 학습<br>모델 연결 | 18/20 판 1000 스텝 버팀 |

### 4-3. 예상 문제와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 막대가 수레와 따로 논다 | 막대를 수레의 자식으로 넣음 | 둘 다 Rigidbody, 관절로만 연결 |
| 시작하자마자 끝난다 | 되돌릴 때 각속도를 안 지움 | 속도 · 각속도를 0 으로 |
| 레일 끝으로 달려간다 | 수레 위치를 안 봄 | 수레 x 를 관측에 넣는다 |

> 한 번에 하나만 바꾸고, 바꾼 이유와 결과를 숫자로 기록한다.
