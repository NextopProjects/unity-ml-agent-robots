## 2. 게임 디자인

### 2-1. 게임 컨셉

**두 관절을 돌려 팔 끝을 무작위 버튼 위에 가져간다**

|  |  |
|---|---|
| **핵심 재미** | 관절 두 개를 동시에 — 같은 점에 가는 자세가 둘이다 |
| **잘한 플레이** | 두 관절을 함께 돌려 곧장 버튼에 닿는다 |
| **못한 플레이** | 한 관절씩 돌며 헤매거나 버튼 주위를 맴돈다 |

### 2-2. 플레이 방식

한 판은 이렇게 흘러간다. 판이 끝날 때까지 **상황 보기 → 조작**을 반복한다.

```
[판 시작] 버튼 무작위 (범위 안)
   ↓
[상황 보기] 관절 각도 · 버튼 방향
   ↓
[조작] 관절 1 · 2 돌리기
   ↓
[결과] 닿으면 +1
   ↺ (판이 끝날 때까지 상황 보기 → 조작 반복)
```

### 2-3. 플레이 과정 (단계별)

#### ① 판 시작 — 버튼이 닿을 수 있는 범위 안에

**게임에서 일어나는 일**

- 팔을 처음 자세로
- 버튼을 '잰 범위' 안쪽에만
- 제한 500 스텝

플레이어의 판단: *"어느 관절부터 돌리지?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 관절 각도 2, 버튼 − 팔 끝 |
| 행동 | 첫 결정 전 |
| 보상 | 0 — OnEpisodeBegin |

#### ② 관절 돌리기 — 두 관절을 함께 돌린다

**게임에서 일어나는 일**

- 관절 1 · 2 를 동시에 돌린다
- 팔 끝이 버튼에 가까워진다
- 가까워진 만큼 작은 보상

플레이어의 판단: *"어깨를 더 돌리자"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 버튼까지 거리 줄어듦 |
| 행동 | 관절1 − · 관절2 + |
| 보상 | +진전 (±0.02 상한) |

#### ③ 닿음 +1 — 팔 끝이 버튼 0.15 안에

**게임에서 일어나는 일**

- 팔 끝이 버튼에 닿는다
- +1 받고 판 끝
- 새 판, 새 버튼 자리

플레이어의 판단: *"닿았다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 거리 ≈ 0 |
| 행동 | — |
| 보상 | +1 — 판 끝 |

#### ④ 판 끝 — 시간 초과 — 500 스텝 동안 못 닿으면

**게임에서 일어나는 일**

- 버튼 주위를 맴돈다
- 500 스텝이 지나면 끝
- 진전 보상만 남는다

플레이어의 판단: *"왔다 갔다만 했다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | — |
| 행동 | — |
| 보상 | 진전 보상만 — 판 끝 |

### 2-4. 점수와 승패

버튼에 닿으면 이긴다 — 단, 버튼은 반드시 닿을 수 있는 곳에

**닿음**
- 팔 끝 ↔ 버튼 < 0.15
- +1, 판 끝

**시간 초과**
- 500 스텝 안에 못 닿음
- 진전 보상만 남음

| 조건 | 판정 방법 (코드에서) | 결과 |
|---|---|---|
| 닿음 | 팔 끝(Tip) ↔ 버튼 거리 < 0.15 | +1 · 판 끝 |
| 진전 | 이전 거리 − 지금 거리 | 그대로, ±0.02 상한 |
| 시간 초과 | StepCount = Max Step (500) | 판 끝 (자동) |

### 2-5. 등장 요소

매 판 바뀌는 것이 있어야 에이전트가 자리를 외우지 않는다.

| # | 오브젝트 | 역할 | 컴포넌트 | 매 판 |
|---|---|---|---|---|
| 1 | Base · J1 | 받침 · 관절 1 (Y 회전) | 빈 오브젝트 (scale 1) | 고정 |
| 2 | J2 · Tip | 관절 2 · 팔 끝 | 빈 오브젝트 (scale 1) + 링크 Cube | 처음 자세 |
| 3 | Button | 버튼 | Cylinder — 콜라이더 제거 | 범위 안 무작위 |
| 4 | (범위) | 닿는 범위 0.4 ~ 1.8 | 직접 계산 — 정기구학 | - |

### 2-6. 사람 조작 (Heuristic)

| 키 | 하는 일 |
|---|---|
| Q | 관절 1 + |
| W | 관절 2 + |
| A | 관절 1 − |
| S | 관절 2 − |

- **왜 먼저 사람이 하나** — Scene 뷰에서 관절을 손으로 돌려 보고, 키보드로 버튼 10개를 눌러 본다. 안 닿는 자리가 있으면 범위 계산이 틀린 것

- **기록해 둘 것** — 관절 각도를 1° 씩 돌려 잰 '실제 닿는 거리 범위'를 숫자로 적는다

## 3. 강화학습 설계

### 3-1. 게임 → 강화학습

결정할 때마다 관측을 보고 행동을 고르고, 그 결과로 보상을 받는다.

| 강화학습 |  | 이 게임에서 |
|---|---|---|
| Agent | 에이전트 | 2관절 팔 |
| Environment | 환경 | 책상 · 버튼 — ArmArea |
| Observation | 관측 | 관절 각도 2, 버튼 − 팔 끝, 버튼 위치 |
| Action | 행동 | 관절 1 · 2 회전 속도 (연속 2) |
| Reward | 보상 | 진전 (상한) + 닿으면 +1 |
| Episode | 에피소드 | 닿음 또는 500 스텝 |

### 3-2. 관측 설계 (Observation) — 총 6칸

| 항목 | 칸 | 왜 필요한가 |
|---|---|---|
| 관절 각도 2개 ÷ 최대 | 2 | 지금 자세 |
| 버튼 − 팔 끝 (x, z) | 2 | 남은 방향과 거리 |
| 버튼 위치 (x, z) | 2 | 자세를 고르는 데 도움 — 빼서 비교 |

칸 수를 Behavior Parameters 의 Space Size 와 맞춘다. 각도는 eulerAngles 로 읽지 말고 내 변수로 들고 있는다 (360 근처에서 튄다)

### 3-3. 행동 설계 (Action) — 연속 2

| 번호 | 값 | 하는 일 | 키보드 |
|---|---|---|---|
| 0 | −1 ~ +1 | 관절 1 회전 × 90°/초 | Q / A |
| 1 | −1 ~ +1 | 관절 2 회전 × 90°/초 | W / S |

물리 없이 각도를 직접 넣는다. 관절 범위 밖으로 가지 않게 자른다

### 3-4. 보상 설계 (Reward)

한 판의 시간 순서:

```
판 시작 ── 접근(+) ── 접근(+) ── 닿음(+1)  → 시간
```

| 사건 | 보상 | 판은? |
|---|---|---|
| 팔 끝이 가까워짐 | +진전 | 계속 (±0.02 상한) |
| 버튼에 닿음 | +1 | 판 끝 |
| 500 스텝 지남 | 0 | 판 끝 |

RobotArms 의 '진전 보상 상한'이 여기서도 필요한지 직접 확인한다

### 3-5. 보상이 만드는 플레이

한 판의 누적 보상 — **예시 값, 실측 아님**:

| 스텝 | 곧장 닿음 | 맴돌기 | 닿을 수 없는 버튼 |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 100 | 0.6 | 0.3 | 0.3 |
| 200 | 1.8 | 0.3 | 0.3 |
| 300 | 1.8 | 0.35 | 0.3 |
| 400 | 1.8 | 0.4 | 0.3 |
| 500 | 1.8 | 0.4 | 0.3 |

- **이 보상이 유도하는 행동** — 가까워질수록 조금씩, 닿으면 크게 → 두 관절을 함께 돌려 곧장 가는 동작

- **넣지 않은 보상과 이유** — 범위 밖 버튼 — 어떤 보상을 줘도 배울 수 없다. 보상보다 환경(도달 범위)을 먼저 의심한다

### 3-6. 에피소드 설계 (Episode)

| 단계 | 내용 |
|---|---|
| **시작할 때 (OnEpisodeBegin)** | 팔: 처음 자세<br>버튼: 잰 범위 안쪽에만<br>이전 거리 기록 |
| **진행 (결정마다)** | 관측 6칸 → 행동 2개<br>각도 범위로 자르기<br>진전 보상 (상한) |
| **끝 (EndEpisode)** | 닿음 → +1<br>Max Step 500<br>(물리 없음) |

> 버튼 범위는 계산한 도달 범위의 안쪽에 여유를 둔다 — 예: 잰 범위 0.4~1.8 → 0.6~1.6

## 4. 학습 계획

### 4-1. 학습 환경 구성

영역을 복제해 한 두뇌가 동시에 여러 판을 경험한다.

| 설정 | 예시 값 | 뜻 |
|---|---|---|
| Behavior Name | TwoJointArm | yaml behaviors 키와 같게 |
| Decision Period | 5 | 5 물리 스텝마다 결정 |
| Max Step | 500 | 약 10초 |
| 영역 수 | 9 (3 × 3) | 한 두뇌로 묶인다 |
| max_steps (yaml) | 300,000 | 처음엔 버튼 범위를 좁게 |
| 예상 시간 | 30~60분 | 예상치 — 직접 잰다 |

### 4-2. 개발 단계

완료 기준을 넘어야 다음 단계로 간다.

| 단계 | 만들 것 | 완료 기준 |
|---|---|---|
| **1. 장면 · 조작** | 받침 · 관절 · 링크<br>버튼 · 키보드 조작<br>관절 범위 자르기 | 키보드로 버튼 10개 누름 |
| **2. 도달 범위 검증** | 각도 1° 씩 전수 스캔<br>최소 · 최대 거리<br>버튼 범위 결정 | 범위를 숫자로 기록 |
| **3. 에이전트 · 첫 학습** | 관측 6칸 · 행동 2개<br>진전 보상 + 닿음<br>영역 1개 학습 | 성공률이 오르기 시작 |
| **4. 본 학습 · 완성** | 영역 9개 복제<br>30만 스텝 학습<br>RobotArms 와 비교 | 18/20 닿음, 시연 영상 |

### 4-3. 예상 문제와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 팔이 납작하게 찌그러짐 | 스케일 있는 물체 아래 관절 | 관절 · 팔 끝은 scale 1 빈 오브젝트 |
| 안 되는 판이 섞여 있다 | 버튼이 닿을 수 없는 곳에 | 잰 범위 안쪽에만 생기게 |
| 각도가 360 근처로 튄다 | eulerAngles 로 읽음 | 각도를 내 변수로 들고 있는다 |
