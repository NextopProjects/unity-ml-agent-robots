## 2. 게임 디자인

### 2-1. 게임 컨셉

**추력으로 떨어지는 속도를 줄이며 패드 위에 살짝 내려앉는다**

|  |  |
|---|---|
| **핵심 재미** | 가만있으면 떨어진다 — 연료와 속도 사이의 줄타기 |
| **잘한 플레이** | 패드 위로 옮겨 가며 서서히 줄여 똑바로 닿는다 |
| **못한 플레이** | 그대로 추락하거나, 공중에서 버티기만 하거나, 기울어 닿는다 |

### 2-2. 플레이 방식

한 판은 이렇게 흘러간다. 판이 끝날 때까지 **상황 보기 → 조작**을 반복한다.

```
[판 시작] 높이 8 · 위치 무작위
   ↓
[상황 보기] 속도 · 기울기 · 패드
   ↓
[조작] 추력 · 기울이기
   ↓
[결과] 살짝 착지 +1
   ↺ (판이 끝날 때까지 상황 보기 → 조작 반복)
```

### 2-3. 플레이 과정 (단계별)

#### ① 판 시작 — 공중에서 떨어지기 시작

**게임에서 일어나는 일**

- 높이 8, 가로 위치 무작위
- 패드도 무작위 자리
- 연료 가득

플레이어의 판단: *"패드는 오른쪽 아래다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 패드 방향, 속도 0, 연료 1 |
| 행동 | 첫 결정 전 |
| 보상 | 0 — OnEpisodeBegin |

#### ② 추력으로 감속 — 아래로 뿜어 속도를 줄인다

**게임에서 일어나는 일**

- 주 추력으로 낙하 속도를 줄인다
- 살짝 기울여 패드 쪽으로
- 추력을 쓰면 연료가 준다

플레이어의 판단: *"너무 빨리 떨어지고 있다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 아래 속도 큼, 연료 0.7 |
| 행동 | 주 추력 + · 오른쪽 기울이기 |
| 보상 | −0.001 × 추력 (연료) |

#### ③ 살짝 착지 +1 — 패드 위, 느리게, 똑바로

**게임에서 일어나는 일**

- 패드 위에서 속도 < 1
- 기울기 < 15°
- +1 받고 판 끝

플레이어의 판단: *"부드럽게 닿았다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 높이 ≈ 0, 속도 작음 |
| 행동 | 추력 조금 |
| 보상 | +1 — 판 끝 |

#### ④ 충돌 −1 — 세게 · 기울어 · 패드 밖

**게임에서 일어나는 일**

- 빠르게 땅에 부딪힌다
- 또는 기울어 닿는다
- −1 받고 판 끝

플레이어의 판단: *"줄이는 게 늦었다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | — |
| 행동 | — |
| 보상 | −1 — EndEpisode |

### 2-4. 점수와 승패

패드 위에 살짝 내리면 이기고, 세게 닿거나 밖으로 나가면 진다

**착지 성공**
- 패드 · 속도 < 1 · 기울기 < 15°
- +1, 판 끝

**충돌 · 이탈**
- 세게 · 기울어 닿음 −1
- 화면 밖 −1 · 시간 초과

| 조건 | 판정 방법 (코드에서) | 결과 |
|---|---|---|
| 착지 성공 | OnCollisionEnter(Pad) · 상대 속도 < 1 · 기울기 < 15° | +1 · 판 끝 |
| 충돌 | 그 외의 착지 (땅 · 세게 · 기울어) | −1 · 판 끝 |
| 이탈 · 시간 | 높이 > 15 또는 \|x\| > 10 · Max Step 1500 | −1 · 판 끝 / 판 끝 |

### 2-5. 등장 요소

매 판 바뀌는 것이 있어야 에이전트가 자리를 외우지 않는다.

| # | 오브젝트 | 역할 | 컴포넌트 | 매 판 |
|---|---|---|---|---|
| 1 | Lander | 착륙선 = 에이전트 | Rigidbody (Z 고정 · Z 축 회전만) · Agent | x 무작위, 높이 8 |
| 2 | Pad | 착륙 패드 | Cube, 태그 Pad | x 무작위 |
| 3 | Ground | 땅 | Cube (넓게) | 고정 |
| - | LanderArea | 영역 묶음 | 빈 오브젝트 — 복제 단위 | - |

### 2-6. 사람 조작 (Heuristic)

| 키 | 하는 일 |
|---|---|
| ↑ | 주 추력 |
| ← | 왼쪽 기울이기 |
| → | 오른쪽 기울이기 |

- **왜 먼저 사람이 하나** — 추력 · 토크 비율이 난이도를 정한다. 키보드로 10번 중 몇 번 내리는지 먼저 재고, 0번이면 값을 고친다

- **기록해 둘 것** — 10번 착륙 시도 중 성공 수와 착지 속도를 적는다

## 3. 강화학습 설계

### 3-1. 게임 → 강화학습

결정할 때마다 관측을 보고 행동을 고르고, 그 결과로 보상을 받는다.

| 강화학습 |  | 이 게임에서 |
|---|---|---|
| Agent | 에이전트 | 착륙선 |
| Environment | 환경 | 땅 · 패드 · 중력 — LanderArea |
| Observation | 관측 | 패드 방향, 속도, 기울기 sin · cos, 연료 |
| Action | 행동 | 주 추력 · 기울이기 (연속 2) |
| Reward | 보상 | 착지 +1, 충돌 −1, 연료 소량 − |
| Episode | 에피소드 | 착지 · 충돌 · 이탈 · 1500 스텝 |

### 3-2. 관측 설계 (Observation) — 총 7칸

| 항목 | 칸 | 왜 필요한가 |
|---|---|---|
| 패드 − 나 (x, y) ÷ 10 | 2 | 어디로 내려가야 하나 |
| 속도 (x, y) ÷ 5 | 2 | 착지 속도가 성공을 가른다 |
| 기울기 sin, cos | 2 | 똑바로 서 있는가 |
| 남은 연료 0 ~ 1 | 1 | 아껴야 하는가 |

칸 수를 Behavior Parameters 의 Space Size 와 맞춘다. 연료 관측을 빼면? 연료가 떨어질 때 갑자기 추락하는지 비교

### 3-3. 행동 설계 (Action) — 연속 2

| 번호 | 값 | 하는 일 | 키보드 |
|---|---|---|---|
| 0 | −1 ~ +1 → 0 ~ 1 | 주 추력 × 15 N (몸 기준 위) | ↑ |
| 1 | −1 ~ +1 | 기울이기 토크 × 0.3 | ← / → |

중력 9.81 · 질량 1 → 버티려면 9.81 N. 15 N 이면 여유가 있다 — 이 비율이 난이도

### 3-4. 보상 설계 (Reward)

한 판의 시간 순서:

```
판 시작 ── 추력(−) ── 추력(−) ── 착지(+1)  → 시간
```

| 사건 | 보상 | 판은? |
|---|---|---|
| 착지 성공 | +1 | 판 끝 |
| 충돌 · 이탈 | −1 | 판 끝 |
| 추력 사용 | −0.001 × 추력 | 계속 |

벌점은 0 에서 시작해 하나씩 더한다. 연료 벌점이 크면 아예 안 뿜는다

### 3-5. 보상이 만드는 플레이

한 판의 누적 보상 — **예시 값, 실측 아님**:

| 스텝 | 살짝 착지 | 공중에서 버티기 | 추락 |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 300 | -0.1 | -0.16 | -1 |
| 600 | 0.82 | -0.32 | -1 |
| 900 | 0.82 | -0.48 | -1 |
| 1200 | 0.82 | -0.64 | -1 |
| 1500 | 0.82 | -0.8 | -1 |

- **이 보상이 유도하는 행동** — 착지 +1 이 연료 비용보다 크다 → 아끼되, 필요한 만큼 뿜어 내려앉는 플레이

- **넣지 않은 보상과 이유** — 충돌 −10 처럼 큰 벌점 — 내려가 봐야 손해라 공중에서 시간만 끄는 쪽으로 배운다

### 3-6. 에피소드 설계 (Episode)

| 단계 | 내용 |
|---|---|
| **시작할 때 (OnEpisodeBegin)** | 높이 8, x [−6, 6]<br>패드 x [−6, 6]<br>속도 · 회전 0, 연료 1 |
| **진행 (결정마다)** | 관측 7칸 → 행동 2개<br>추력만큼 연료 · 벌점<br>이탈 확인 |
| **끝 (EndEpisode)** | 착지 성공 +1 · 충돌 −1<br>높이 > 15 · \|x\| > 10<br>Max Step 1500 |

> 위로 도망가 시간 끄는 판을 막으려면 화면 밖 경계가 꼭 필요하다

## 4. 학습 계획

### 4-1. 학습 환경 구성

영역을 복제해 한 두뇌가 동시에 여러 판을 경험한다.

| 설정 | 예시 값 | 뜻 |
|---|---|---|
| Behavior Name | Lander | yaml behaviors 키와 같게 |
| Decision Period | 5 | 5 물리 스텝마다 결정 |
| Max Step | 1500 | 약 30초 |
| 영역 수 | 9 (3 × 3) | 한 두뇌로 묶인다 |
| max_steps (yaml) | 1,000,000 | 처음엔 패드를 넓게 |
| 예상 시간 | 40~90분 | 예상치 — 직접 잰다 |

### 4-2. 개발 단계

완료 기준을 넘어야 다음 단계로 간다.

| 단계 | 만들 것 | 완료 기준 |
|---|---|---|
| **1. 장면 · 조작** | 땅 · 패드 · 착륙선<br>추력 · 토크 조절<br>키보드 조작 | 키보드로 10번 중 3번 이상 착지 |
| **2. 에이전트 연결** | 관측 7칸 · 행동 2개<br>착지 · 충돌 판정<br>연료 벌점 0 | 착지 · 충돌로 판이 끝난다 |
| **3. 첫 학습** | 넓은 패드 · 낮은 높이<br>영역 1개, 10만 스텝<br>착지 속도 확인 | 착지 성공이 나오기 시작 |
| **4. 본 학습 · 완성** | 연료 벌점 추가<br>영역 9개 · 100만 스텝<br>모델 연결 | 15/20 착지, 시연 영상 |

### 4-3. 예상 문제와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 공중에 둥둥 떠 있다 | 충돌 벌점이 너무 큼 | 충돌 −1 로 줄이고 화면 밖 경계 |
| 추력을 안 쓰고 추락 | 연료 벌점이 너무 큼 | 연료 벌점을 0 에서 시작 |
| 앞뒤로 돈다 | 다른 축 회전을 안 막음 | Freeze Rotation X, Y · Position Z |

> 한 번에 하나만 바꾸고, 바꾼 이유와 결과를 숫자로 기록한다.
