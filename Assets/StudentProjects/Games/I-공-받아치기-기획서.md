## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 장르 | 반사 신경 · 받아치기 |
| 플레이어 | 좌우로 움직이는 패들 |
| 목표 | 공을 바닥에 떨어뜨리지 않고 많이 받는다 |
| 실패 | 공이 바닥에 닿는다 |
| 학습 대상 | 떨어질 자리를 예측해 미리 가기 |
| 새 개념 | Decision Period · 관측 쌓기 |
| 예상 학습 | 영역 9개 · 30~60분 (예상치) |

장면: 옆에서 본 바닥, 패들, 튀어 오르는 공

## 2. 게임 디자인

### 2-1. 게임 컨셉

**공이 떨어질 자리로 패들을 옮겨 계속 받아친다**

|  |  |
|---|---|
| **핵심 재미** | 공이 어디로 떨어질지 미리 읽고 먼저 가 있는다 |
| **잘한 플레이** | 공 아래로 미리 가서 작은 움직임으로 받는다 |
| **못한 플레이** | 공을 쫓아가다 늦거나 엉뚱한 쪽으로 간다 |

### 2-2. 플레이 방식

한 판은 이렇게 흘러간다. 판이 끝날 때까지 **상황 보기 → 조작**을 반복한다.

```
[판 시작] 공 높이 4 · 위치 무작위
   ↓
[상황 보기] 공 위치 · 속도
   ↓
[조작] 패들 좌우 이동
   ↓
[결과] 받으면 +0.1
   ↺ (판이 끝날 때까지 상황 보기 → 조작 반복)
```

### 2-3. 플레이 과정 (단계별)

#### ① 공이 떨어진다 — 높이 4에서 무작위로

**게임에서 일어나는 일**

- 공을 높이 4, 무작위 x 에
- 옆으로 조금 움직이며 떨어진다
- 패들은 가운데

플레이어의 판단: *"어디로 떨어질까?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 공 위치 · 속도 |
| 행동 | 첫 결정 전 |
| 보상 | 0 — OnEpisodeBegin |

#### ② 미리 가기 — 떨어질 자리로 패들을 옮긴다

**게임에서 일어나는 일**

- 떨어질 자리를 예측한다
- 패들을 그쪽으로 옮긴다
- 결정이 늦으면 놓친다

플레이어의 판단: *"왼쪽으로 가야 한다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 공이 왼쪽 아래로 이동 중 |
| 행동 | 왼쪽으로 이동 |
| 보상 | 0 |

#### ③ 받아침 +0.1 — 패들에 닿으면 다시 위로

**게임에서 일어나는 일**

- 공이 패들에 맞고 튀어 오른다
- +0.1, 판은 계속
- 다음 낙하를 다시 예측

플레이어의 판단: *"받았다, 다음!"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 공 속도가 위로 바뀜 |
| 행동 | 작은 이동 |
| 보상 | +0.1 (한 번만) |

#### ④ 놓침 — 판 끝 — 공이 바닥에 닿으면

**게임에서 일어나는 일**

- 패들이 늦어 공이 바닥에 닿는다
- 판이 끝난다
- 받은 횟수가 이 판의 점수

플레이어의 판단: *"늦었다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | — |
| 행동 | — |
| 보상 | 0 — EndEpisode |

### 2-4. 점수와 승패

이기는 순간은 없다 — 받은 횟수가 점수다

**점수**
- 패들에 닿을 때마다 +0.1
- 판은 계속된다

**판 끝**
- 공이 바닥에 닿음
- 또는 3000 스텝 지남

| 조건 | 판정 방법 (코드에서) | 결과 |
|---|---|---|
| 받아침 | OnCollisionEnter(패들), 직전에 받은 뒤 공이 0.5 이상 떠올랐을 때 | +0.1 · 계속 |
| 놓침 | 공이 바닥(태그 Floor)에 닿음 | 판 끝 |
| 시간 종료 | StepCount = Max Step (3000) | 판 끝 (자동) |

### 2-5. 등장 요소

매 판 바뀌는 것이 있어야 에이전트가 자리를 외우지 않는다.

| # | 오브젝트 | 역할 | 컴포넌트 | 매 판 |
|---|---|---|---|---|
| 1 | Ball | 공 | Rigidbody · 튀는 Physic Material | 높이 4, x 무작위 |
| 2 | Paddle | 패들 = 에이전트 | kinematic Rigidbody · Agent | 가운데로 |
| 3 | Floor | 바닥 | Plane, 태그 Floor | 고정 |
| - | PaddleArea | 영역 묶음 | 빈 오브젝트 — 복제 단위 | - |

### 2-6. 사람 조작 (Heuristic)

| 키 | 하는 일 |
|---|---|
| W | +z 이동 |
| A | −x 이동 |
| S | −z 이동 |
| D | +x 이동 |

- **왜 먼저 사람이 하나** — 패들 속도가 너무 느리면 사람도 못 받는다. 패들은 MovePosition 으로 — 위치를 직접 바꾸면 공을 쳐도 힘이 안 전해진다

- **기록해 둘 것** — 키보드로 5판 받아친 횟수를 적는다

## 3. 강화학습 설계

### 3-1. 게임 → 강화학습

결정할 때마다 관측을 보고 행동을 고르고, 그 결과로 보상을 받는다.

| 강화학습 |  | 이 게임에서 |
|---|---|---|
| Agent | 에이전트 | 패들 |
| Environment | 환경 | 공 · 바닥 · 중력 — PaddleArea |
| Observation | 관측 | 공의 상대 위치 · 높이 · 속도, 패들 위치 |
| Action | 행동 | 패들 이동 x · z (연속 2) |
| Reward | 보상 | 받을 때마다 +0.1 |
| Episode | 에피소드 | 놓칠 때까지 (최대 3000 스텝) |

### 3-2. 관측 설계 (Observation) — 총 7칸

| 항목 | 칸 | 왜 필요한가 |
|---|---|---|
| 공 − 패들 (x, z) | 2 | 공 아래로 가야 한다 |
| 공 높이 | 1 | 언제 닿나 |
| 공 속도 (x, y, z) | 3 | 어디에 떨어질지 예측 |
| 패들 x ÷ 3 | 1 | 바닥 끝이 가까운가 |

칸 수를 Behavior Parameters 의 Space Size 와 맞춘다. 속도를 빼고 Stacked Vectors 3 으로 대신하면? 위치 변화로 속도를 알아내는지 비교

### 3-3. 행동 설계 (Action) — 연속 2

| 번호 | 값 | 하는 일 | 키보드 |
|---|---|---|---|
| 0 | −1 ~ +1 | 패들 x 이동 × 4 m/s | A / D |
| 1 | −1 ~ +1 | 패들 z 이동 × 4 m/s | W / S |

Decision Period 1 / 5 / 10 을 비교 — 결정이 늦으면 놓친다

### 3-4. 보상 설계 (Reward)

한 판의 시간 순서:

```
판 시작 ── 받음(+0.1) ── 받음(+0.1) ── 받음(+0.1) ── 놓침(끝)  → 시간
```

| 사건 | 보상 | 판은? |
|---|---|---|
| 패들로 받음 | +0.1 | 계속 (한 번 닿을 때 한 번만) |
| 바닥에 닿음 | 0 | 판 끝 |
| 3000 스텝 지남 | 0 | 판 끝 |

한 번 닿을 때 충돌 이벤트가 여러 번 올 수 있다 — 보상은 한 번만

### 3-5. 보상이 만드는 플레이

한 판의 누적 보상 — **예시 값, 실측 아님**:

| 스텝 | 계속 받아침 | 가끔 놓침 | 바로 놓침 |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 600 | 0.6 | 0.5 | 0 |
| 1200 | 1.2 | 0.5 | 0 |
| 1800 | 1.8 | 0.5 | 0 |
| 2400 | 2.4 | 0.5 | 0 |
| 3000 | 3 | 0.5 | 0 |

- **이 보상이 유도하는 행동** — 받을 때마다 점수, 놓치면 끝 → 미리 가서 받는 플레이

- **넣지 않은 보상과 이유** — 공과 패들이 가까울수록 주는 보상 — 공 아래에 붙어 있기만 해도 점수가 나와, 받아치는 순간이 덜 중요해진다

### 3-6. 에피소드 설계 (Episode)

| 단계 | 내용 |
|---|---|
| **시작할 때 (OnEpisodeBegin)** | 공: 높이 4, x · z [−2, 2]<br>옆 속도 조금<br>패들: 가운데 |
| **진행 (결정마다)** | 관측 7칸 → 행동 2개<br>MovePosition 으로 이동<br>받으면 +0.1 (한 번) |
| **끝 (EndEpisode)** | 공이 바닥에 닿음<br>Max Step 3000<br>(받아도 끝나지 않는다) |

> 받아도 판을 끝내지 않는 반복 구조 — 점수는 받은 횟수로 읽는다

## 4. 학습 계획

### 4-1. 학습 환경 구성

영역을 복제해 한 두뇌가 동시에 여러 판을 경험한다.

| 설정 | 예시 값 | 뜻 |
|---|---|---|
| Behavior Name | PaddleKeeper | yaml behaviors 키와 같게 |
| Decision Period | 2 | 빠른 과제 — 자주 결정 |
| Max Step | 3000 | 약 60초 |
| 영역 수 | 9 (3 × 3) | 한 두뇌로 묶인다 |
| max_steps (yaml) | 500,000 | 처음엔 바닥을 좁게 |
| 예상 시간 | 30~60분 | 예상치 — 직접 잰다 |

### 4-2. 개발 단계

완료 기준을 넘어야 다음 단계로 간다.

| 단계 | 만들 것 | 완료 기준 |
|---|---|---|
| **1. 장면 · 조작** | 바닥 · 패들 · 공<br>튀는 재질 조절<br>키보드 조작 | 가만둬도 튀고, 손으로 받아친다 |
| **2. 에이전트 연결** | 관측 7칸 · 행동 2개<br>받기 +0.1 (한 번만)<br>놓침 판정 | 보상이 한 번씩만 들어온다 |
| **3. 첫 학습** | yaml 작성<br>영역 1개, 10만 스텝<br>받은 횟수 확인 | 누적 보상이 오르기 시작 |
| **4. 본 학습 · 완성** | 영역 9개 복제<br>50만 스텝 학습<br>모델 연결 | 판 평균 20회 이상, 시연 영상 |

### 4-3. 예상 문제와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 공이 패들을 통과 | 위치를 직접 바꿈 | kinematic + MovePosition |
| 한 번에 보상 여러 번 | 충돌 이벤트가 연속으로 옴 | 공이 떠오르기 전엔 다시 안 줌 |
| 공이 점점 높이 튄다 | Bounciness 1 이상 | 0.8 ~ 0.9 로 낮춘다 |

> 한 번에 하나만 바꾸고, 바꾼 이유와 결과를 숫자로 기록한다.
