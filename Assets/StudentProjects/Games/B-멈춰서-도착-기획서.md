## 2. 게임 디자인

### 2-1. 게임 컨셉

**공을 굴려 목표 원 안에 정확히 멈춰 세운다 — 지나치면 소용없다**

|  |  |
|---|---|
| **핵심 재미** | 빨리 가고 싶지만 세게 가면 못 멈춘다 — 브레이크 타이밍 |
| **잘한 플레이** | 멀리서는 빠르게, 가까워지면 줄여 원 가운데에 선다 |
| **못한 플레이** | 원을 지나쳐 왔다 갔다 하거나 끝내 멈추지 못한다 |

### 2-2. 플레이 방식

한 판은 이렇게 흘러간다. 판이 끝날 때까지 **상황 보기 → 조작**을 반복한다.

```
[판 시작] 공 · 목표 무작위
   ↓
[상황 보기] 남은 거리 · 속도
   ↓
[조작] 밀기 / 반대로 밀기
   ↓
[결과] 원 안에서 멈추면 +1
   ↺ (판이 끝날 때까지 상황 보기 → 조작 반복)
```

### 2-3. 플레이 과정 (단계별)

#### ① 판 시작 — 공과 목표 원이 무작위 자리에

**게임에서 일어나는 일**

- 공을 무작위 자리에, 속도 0
- 목표 원을 공과 2 이상 떨어진 곳에
- 점수 0, 제한 500 스텝

플레이어의 판단: *"목표까지 얼마나 멀지?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 목표 − 공 = 오른쪽 위, 속도 0 |
| 행동 | 첫 결정 전 |
| 보상 | 0 — OnEpisodeBegin |

#### ② 가속 — 멀리 있을 때는 빠르게

**게임에서 일어나는 일**

- 목표 쪽으로 계속 민다
- 속도가 점점 붙는다
- 아직 보상은 없다

플레이어의 판단: *"얼마나 빨라도 멈출 수 있을까?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 거리는 줄고 속도는 커진다 |
| 행동 | 목표 쪽 힘 |
| 보상 | 0 |

#### ③ 감속 · 정지 +1 — 가까워지면 반대로 밀어 멈춘다

**게임에서 일어나는 일**

- 원 근처에서 반대 방향으로 민다
- 원 안 + 속도 < 0.2 → 성공
- +1 받고 판이 끝난다

플레이어의 판단: *"지금 줄여야 한다!"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 거리 ≈ 0, 속도 ≈ 0 |
| 행동 | 반대 방향 힘 (브레이크) |
| 보상 | +1 — SetReward, EndEpisode |

#### ④ 판 끝 — 실패 — 떨어지거나 500 스텝이 지나면

**게임에서 일어나는 일**

- 원을 지나쳐 바닥 밖으로 떨어짐
- 또는 맴돌다 500 스텝 초과
- 보상 없이 새 판

플레이어의 판단: *"너무 빨랐다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | — |
| 행동 | — |
| 보상 | 0 — EndEpisode |

### 2-4. 점수와 승패

멈춰야만 성공 — 지나가는 것은 성공이 아니다

**성공**
- 원 안에서 속도 < 0.2
- +1 받고 판 끝

**실패 · 판 끝**
- 바닥 밖으로 떨어짐
- 500 스텝 동안 못 멈춤

| 조건 | 판정 방법 (코드에서) | 결과 |
|---|---|---|
| 도착 · 정지 | 거리 < 0.7 그리고 속력 < 0.2 | +1 · 판 끝 |
| 떨어짐 | 공의 높이 y < 0 | 판 끝 (보상 0) |
| 시간 초과 | StepCount = Max Step (500) | 판 끝 (자동) |

### 2-5. 등장 요소

매 판 바뀌는 것이 있어야 에이전트가 자리를 외우지 않는다.

| # | 오브젝트 | 역할 | 컴포넌트 | 매 판 |
|---|---|---|---|---|
| 1 | Floor | 바닥 (10 × 10) | Plane | 고정 |
| 2 | Agent | 공 = 에이전트 | Rigidbody · Agent · Behavior Parameters | 무작위 자리 |
| 3 | Target | 목표 원 (그림) | Cylinder — 콜라이더 제거 | 무작위 자리 |
| - | StopArea | 영역 묶음 | 빈 오브젝트 — 복제 단위 | - |

### 2-6. 사람 조작 (Heuristic)

| 키 | 하는 일 |
|---|---|
| W | +z 힘 |
| A | −x 힘 |
| S | −z 힘 |
| D | +x 힘 |

- **왜 먼저 사람이 하나** — 사람도 멈추기 어렵다. 힘이 너무 세면 멈출 수 없다 — 키보드로 멈출 수 있는 힘과 정지 기준을 여기서 정한다

- **기록해 둘 것** — 10판 중 몇 판 멈췄는지, 성공한 판은 몇 스텝 걸렸는지 적는다

## 3. 강화학습 설계

### 3-1. 게임 → 강화학습

결정할 때마다 관측을 보고 행동을 고르고, 그 결과로 보상을 받는다.

| 강화학습 |  | 이 게임에서 |
|---|---|---|
| Agent | 에이전트 | 공 |
| Environment | 환경 | 바닥 · 목표 원 — StopArea |
| Observation | 관측 | 목표까지의 상대 위치, 공의 속도 |
| Action | 행동 | x · z 방향 힘 (연속 2) |
| Reward | 보상 | 원 안에서 멈추면 +1 |
| Episode | 에피소드 | 멈춤 · 떨어짐 · 500 스텝 중 먼저 |

### 3-2. 관측 설계 (Observation) — 총 4칸

| 항목 | 칸 | 왜 필요한가 |
|---|---|---|
| 목표 − 공 (x, z) | 2 | 방향과 남은 거리 |
| 공의 속도 (x, z) | 2 | 멈출 수 있는가 — 이 과제의 핵심 정보 |

칸 수를 Behavior Parameters 의 Space Size 와 맞춘다. 속도를 빼고 학습해 보면? 멈추지 못하는 것을 직접 확인할 수 있다

### 3-3. 행동 설계 (Action) — 연속 2

| 번호 | 값 | 하는 일 | 키보드 |
|---|---|---|---|
| 0 | −1 ~ +1 | x 방향 힘 × 10 | A / D |
| 1 | −1 ~ +1 | z 방향 힘 × 10 | W / S |

반대 방향 힘이 곧 브레이크다. 힘이 세면 멈추기 어렵다 — 손으로 조절

### 3-4. 보상 설계 (Reward)

한 판의 시간 순서:

```
판 시작 ── 가속 ── 감속 ── 원 안 정지(+1)  → 시간
```

| 사건 | 보상 | 판은? |
|---|---|---|
| 원 안 · 속도 < 0.2 | +1 | 판 끝 (성공) |
| 바닥에서 떨어짐 | 0 | 판 끝 |
| 500 스텝 지남 | 0 | 판 끝 |

보상은 단 하나 — '지나가기'에는 아무것도 주지 않는다

### 3-5. 보상이 만드는 플레이

한 판의 누적 보상 — **예시 값, 실측 아님**:

| 스텝 | 멈춰서 성공 | 지나쳐 맴돌기 | 떨어진 판 |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 100 | 0 | 0 | 0 |
| 200 | 1 | 0 | 0 |
| 300 | 1 | 0 | 0 |
| 400 | 1 | 0 | 0 |
| 500 | 1 | 0 | 0 |

- **이 보상이 유도하는 행동** — 원 안에서 멈춰야만 +1 → 가까워지면 미리 줄이는 운전

- **넣지 않은 보상과 이유** — '닿기만 하면 +1' — 최고 속도로 돌진해 지나가는 운전을 배운다. 비교 실험으로 직접 확인해 볼 만하다

### 3-6. 에피소드 설계 (Episode)

| 단계 | 내용 |
|---|---|
| **시작할 때 (OnEpisodeBegin)** | 공: 무작위 자리, 속도 0<br>목표: 무작위, 공과 2 이상<br>둘 다 바닥 [−4, 4] 안 |
| **진행 (결정마다)** | 관측 4칸 → 행동 2개<br>멈춤 조건을 매 스텝 확인<br>보상은 성공할 때만 |
| **끝 (EndEpisode)** | 원 안 정지 → +1<br>떨어짐 (y < 0)<br>Max Step 500 |

> Max Step 이 없으면 원 근처를 영원히 맴도는 판이 생긴다

## 4. 학습 계획

### 4-1. 학습 환경 구성

영역을 복제해 한 두뇌가 동시에 여러 판을 경험한다.

| 설정 | 예시 값 | 뜻 |
|---|---|---|
| Behavior Name | StopAtTarget | yaml behaviors 키와 같게 |
| Decision Period | 5 | 5 물리 스텝마다 결정 |
| Max Step | 500 | 한 판 최대 약 10초 |
| 영역 수 | 9 (3 × 3) | 한 두뇌로 묶인다 |
| max_steps (yaml) | 300,000 | 처음엔 50,000 |
| 예상 시간 | 15~30분 | 예상치 — 직접 잰다 |

### 4-2. 개발 단계

완료 기준을 넘어야 다음 단계로 간다.

| 단계 | 만들 것 | 완료 기준 |
|---|---|---|
| **1. 장면 · 조작** | 바닥 · 공 · 목표 원<br>키보드 조작<br>속도 표시(OnGUI) | 키보드로 멈춰서 성공 5판 |
| **2. 에이전트 연결** | 관측 4칸 · 행동 2개<br>멈춤 판정 · 보상<br>Max Step 500 | 성공 · 실패로 판이 끝난다 |
| **3. 첫 학습** | yaml 작성<br>영역 1개, 5만 스텝<br>성공률 확인 | 보상이 0 에서 오르기 시작 |
| **4. 본 학습 · 완성** | 영역 9개 복제<br>30만 스텝 학습<br>모델 연결 | 20판 중 16판 정지, 시연 영상 |

### 4-3. 예상 문제와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 원 위를 왔다 갔다 | 멈춤 기준이 너무 빡빡함 | 속력 0.2 → 0.3 으로 풀고 기록 |
| 보상이 0 에서 안 오름 | 목표가 너무 멀다 | 처음엔 목표를 [−2, 2] 로 좁힌다 |
| 가장자리에서 성공 | 거리를 공 중심으로 안 잼 | 공 중심 ↔ 원 중심 거리로 판정 |
