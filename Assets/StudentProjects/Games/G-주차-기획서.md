## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 장르 | 운전 · 정밀 주차 |
| 플레이어 | 앞뒤 + 조향만 가능한 자동차 |
| 목표 | 칸 안에 방향을 맞춰 멈춘다 |
| 실패 | 바닥 밖 · 2000 스텝 초과 |
| 학습 대상 | 옆으로 못 가는 몸으로 위치 · 방향 맞추기 |
| 새 개념 | 내 기준 좌표 · 각도의 sin · cos |
| 예상 학습 | 영역 9개 · 40~90분 (예상치) |

장면: 넓은 바닥, 자동차 하나, 방향이 있는 주차 칸

## 2. 게임 디자인

### 2-1. 게임 컨셉

**핸들을 꺾어 돌아 들어가 칸 안에 방향까지 맞춰 세운다**

|  |  |
|---|---|
| **핵심 재미** | 옆으로는 못 간다 — 크게 돌아 각도를 맞춰야 한다 |
| **잘한 플레이** | 넓게 돌아 칸 입구와 일직선을 만든 뒤 들어가 멈춘다 |
| **못한 플레이** | 칸 근처에서 앞뒤로 덜컹이거나 비뚤게 멈춘다 |

### 2-2. 플레이 방식

한 판은 이렇게 흘러간다. 판이 끝날 때까지 **상황 보기 → 조작**을 반복한다.

```
[판 시작] 차 · 칸 위치와 방향 무작위
   ↓
[상황 보기] 내 기준 칸 위치 · 방향 차
   ↓
[조작] 가속 · 조향
   ↓
[결과] 맞춰 서면 +1
   ↺ (판이 끝날 때까지 상황 보기 → 조작 반복)
```

### 2-3. 플레이 과정 (단계별)

#### ① 판 시작 — 차와 칸의 자리 · 방향이 무작위

**게임에서 일어나는 일**

- 차를 무작위 자리 · 방향에
- 칸도 무작위, 차와 4 이상
- 제한 2000 스텝

플레이어의 판단: *"칸이 내 기준 어디지?"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 칸 = 내 앞 오른쪽, 방향 차 −60° |
| 행동 | 첫 결정 전 |
| 보상 | 0 — OnEpisodeBegin |

#### ② 돌아 들어가기 — 크게 돌아 칸 입구와 일직선

**게임에서 일어나는 일**

- 앞으로 가며 핸들을 꺾는다
- 칸 아래 입구 쪽으로 돈다
- 속도에 비례해 방향이 바뀐다

플레이어의 판단: *"입구와 일직선을 만들자"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 방향 차 줄어듦 |
| 행동 | 가속 + · 조향 왼쪽 |
| 보상 | +진전 (작게) |

#### ③ 칸 안 정지 +1 — 위치 · 방향 · 정지를 모두 만족

**게임에서 일어나는 일**

- 칸 안으로 곧게 들어간다
- 방향 오차 < 15°, 속도 < 0.2
- +1 받고 판 끝

플레이어의 판단: *"똑바로 섰다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | 칸 위치 ≈ 0, 방향 차 ≈ 0 |
| 행동 | 브레이크 (가속 −) |
| 보상 | +1 — 판 끝 |

#### ④ 판 끝 — 실패 — 바닥 밖이거나 2000 스텝 초과

**게임에서 일어나는 일**

- 칸 근처에서 비뚤게 덜컹인다
- 2000 스텝이 지나면 끝
- 또는 바닥 밖으로 나감

플레이어의 판단: *"각도를 너무 늦게 맞췄다"*

| 강화학습으로 보면 |  |
|---|---|
| 관측 | — |
| 행동 | — |
| 보상 | 진전 보상만 — 판 끝 |

### 2-4. 점수와 승패

위치 · 방향 · 정지 세 가지를 모두 맞춰야 이긴다

**주차 성공**
- 칸 안 · 방향 15° 안 · 정지
- +1, 판 끝

**실패 · 판 끝**
- 2000 스텝 초과
- 바닥 밖으로 나감

| 조건 | 판정 방법 (코드에서) | 결과 |
|---|---|---|
| 주차 성공 | 거리 < 0.5 · 방향 오차 < 15° · 속력 < 0.2 | +1 · 판 끝 |
| 진전 | 칸까지 거리가 줄어든 만큼 | × 0.1, ±0.01 상한 |
| 실패 | 바닥 밖 · Max Step 2000 | 판 끝 |

### 2-5. 등장 요소

매 판 바뀌는 것이 있어야 에이전트가 자리를 외우지 않는다.

| # | 오브젝트 | 역할 | 컴포넌트 | 매 판 |
|---|---|---|---|---|
| 1 | Car | 차 = 에이전트 | Rigidbody (Y 회전만) · Agent | 무작위 자리 · 방향 |
| 2 | Spot | 주차 칸 (앞쪽 선) | 얇은 Cube — 콜라이더 제거 | 무작위 |
| 3 | Neighbors | 옆 차 (확장) | Cube | 선택 |
| 4 | Floor | 바닥 20 × 20 | Plane | 고정 |

### 2-6. 사람 조작 (Heuristic)

| 키 | 하는 일 |
|---|---|
| ↑ | 전진 |
| ← | 왼쪽 조향 |
| ↓ | 후진 |
| → | 오른쪽 조향 |

- **왜 먼저 사람이 하나** — 후진 주차까지 사람이 해 봐야 조향 배율이 적당한지 안다. 사람이 못 하면 학습도 안 된다

- **기록해 둘 것** — 키보드로 5판 주차해 걸린 스텝과 방향 오차를 적는다

## 3. 강화학습 설계

### 3-1. 게임 → 강화학습

결정할 때마다 관측을 보고 행동을 고르고, 그 결과로 보상을 받는다.

| 강화학습 |  | 이 게임에서 |
|---|---|---|
| Agent | 에이전트 | 자동차 |
| Environment | 환경 | 바닥 · 주차 칸 — ParkingArea |
| Observation | 관측 | 내 기준 칸 위치, 방향 차 sin · cos, 속도 |
| Action | 행동 | 가속 · 조향 (연속 2) |
| Reward | 보상 | 진전 (상한) + 주차 성공 +1 |
| Episode | 에피소드 | 성공 · 바닥 밖 · 2000 스텝 |

### 3-2. 관측 설계 (Observation) — 총 6칸

| 항목 | 칸 | 왜 필요한가 |
|---|---|---|
| 칸 위치, 차 기준 (x, z) | 2 | '내 앞 오른쪽 3m' — 운전은 내 기준으로 |
| 방향 차 sin, cos | 2 | 359° 와 1° 를 가깝게 — 각도가 이어진다 |
| 앞방향 속도 | 1 | 멈췄는가 |
| 회전 속도 | 1 | 얼마나 도는 중인가 |

칸 수를 Behavior Parameters 의 Space Size 와 맞춘다. 방향을 '각도 ÷ 180' 한 칸으로 준 모델과 비교해 sin · cos 의 효과를 본다

### 3-3. 행동 설계 (Action) — 연속 2

| 번호 | 값 | 하는 일 | 키보드 |
|---|---|---|---|
| 0 | −1 ~ +1 | 가속 (− 는 후진) | ↑ / ↓ |
| 1 | −1 ~ +1 | 조향 (속도에 비례해 회전) | ← / → |

멈춰 있을 때 돌 수 있으면 차가 아니다 — 회전량 = 조향 × 속도

### 3-4. 보상 설계 (Reward)

한 판의 시간 순서:

```
판 시작 ── 접근(+) ── 돌기(+) ── 정렬(+) ── 주차(+1)  → 시간
```

| 사건 | 보상 | 판은? |
|---|---|---|
| 칸에 가까워짐 | +진전 × 0.1 | 계속 (±0.01 상한) |
| 주차 성공 | +1 | 판 끝 |
| 바닥 밖 · 2000 스텝 | 0 | 판 끝 |

처음엔 방향 기준을 30° 로 느슨하게 → 성공이 오면 15° 로 조인다

### 3-5. 보상이 만드는 플레이

한 판의 누적 보상 — **예시 값, 실측 아님**:

| 스텝 | 돌아 들어가 주차 | 칸 근처 덜컹 | 바닥 밖 |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 400 | 0.1 | 0.1 | -0.05 |
| 800 | 0.2 | 0.2 | -0.05 |
| 1200 | 1.25 | 0.2 | -0.05 |
| 1600 | 1.25 | 0.21 | -0.05 |
| 2000 | 1.25 | 0.21 | -0.05 |

- **이 보상이 유도하는 행동** — 세 조건을 모두 맞춰야 +1 → 칸과 일직선을 먼저 만들고 들어가는 운전

- **넣지 않은 보상과 이유** — 위치만 맞으면 주는 보상 — 비뚤게 서도 성공이 되어 방향을 맞추는 법을 안 배운다

### 3-6. 에피소드 설계 (Episode)

| 단계 | 내용 |
|---|---|
| **시작할 때 (OnEpisodeBegin)** | 차: 무작위 자리 · 방향<br>칸: 무작위, 차와 4 이상<br>속도 0 |
| **진행 (결정마다)** | 관측 6칸 → 행동 2개<br>옆 미끄러짐 지우기<br>진전 보상 (상한) |
| **끝 (EndEpisode)** | 주차 성공 → +1<br>바닥 밖<br>Max Step 2000 |

> 옆 방향 속도를 매 스텝 지워야 차처럼 움직인다 (얼음 위 미끄러짐 방지)

## 4. 학습 계획

### 4-1. 학습 환경 구성

영역을 복제해 한 두뇌가 동시에 여러 판을 경험한다.

| 설정 | 예시 값 | 뜻 |
|---|---|---|
| Behavior Name | Parking | yaml behaviors 키와 같게 |
| Decision Period | 5 | 5 물리 스텝마다 결정 |
| Max Step | 2000 | 약 40초 |
| 영역 수 | 9 (3 × 3) | 한 두뇌로 묶인다 |
| max_steps (yaml) | 1,000,000 | 처음엔 칸을 넓게 |
| 예상 시간 | 40~90분 | 예상치 — 직접 잰다 |

### 4-2. 개발 단계

완료 기준을 넘어야 다음 단계로 간다.

| 단계 | 만들 것 | 완료 기준 |
|---|---|---|
| **1. 장면 · 조작** | 바닥 · 차 · 칸<br>차 움직임 3줄<br>화살표 키 조작 | 키보드로 주차 성공 5판 |
| **2. 에이전트 연결** | 관측 6칸 · 행동 2개<br>성공 판정 · 진전 보상<br>방향 기준 30° | 성공 · 실패로 판이 끝난다 |
| **3. 첫 학습** | 칸을 넓게 시작<br>영역 1개, 10만 스텝<br>방향 오차 확인 | 성공이 나오기 시작 |
| **4. 본 학습 · 완성** | 방향 기준 15° 로<br>영역 9개 · 100만 스텝<br>모델 연결 | 15/20 주차, 시연 영상 |

### 4-3. 예상 문제와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 얼음 위처럼 미끄러진다 | 옆 방향 속도를 안 지움 | 매 스텝 옆 속도 성분을 뺀다 |
| 제자리에서 빙글 돈다 | 회전이 속도와 무관 | 회전량 = 조향 × 앞방향 속도 |
| 위치는 맞고 방향이 틀림 | 방향 기준을 너무 일찍 조임 | 30° 에서 시작해 단계적으로 |

> 한 번에 하나만 바꾸고, 바꾼 이유와 결과를 숫자로 기록한다.
