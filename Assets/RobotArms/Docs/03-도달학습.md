# 3장 — 물체까지 도달 학습 (ML-Agents 도입)

> 1~2장에서 **사람이 키보드로** 팔을 움직여 물체까지 갔다.
> 이 장에서는 그 자리에 **AI를 꽂는다.** 아직 잡지는 않는다.

---

## 목표

팔 끝을 **랜덤한 위치의 물체까지** 가져가는 것을 학습한다.

```
2장:  Angle += 키보드입력 × maxSpeed × dt
3장:  Angle += AI의 액션  × maxSpeed × dt     ← 숫자의 출처만 바뀐다
```

관절을 돌리는 일은 2장의 `RobotArmController`가 이미 다 해두었다.
이 장에서 정할 것은 셋뿐이다.

| | |
|---|---|
| **무엇을 보는가** | 관측 12개 |
| **무엇을 하는가** | 연속 액션 3개 (관절 3개) |
| **언제 칭찬하는가** | 가까워진 만큼 + 도달하면 `+1` |

## RollerBall과 비교

| | RollerBall | RobotArms 3장 |
|---|---|---|
| 제어 대상 | 공 하나 | **연결된 관절 3개** |
| 액션의 의미 | 미는 힘 | **관절 회전 속도** |
| 관측 | 위치·속도 8개 (원시값) | 12개 (**전부 정규화**) |
| 보상 | 도달 `+1` / 낙하 `0` | **가까워진 만큼** + 도달 `+1` |
| `MaxStep` | 0 (무제한) | **1000 (필수)** |

함수 구성은 완전히 같다. `OnEpisodeBegin` / `CollectObservations` /
`OnActionReceived` / `Heuristic` 네 개다.

## 핵심 개념 ① — 관측은 정규화한다

```csharp
sensor.AddObservation(arm.NormalizedAngle(i));          // 각도 / 180
sensor.AddObservation(arm.ToNormalizedLocal(위치));      // 위치 / reach
```

각도는 `±180`, 위치는 `±2.7`이다. 그대로 섞어 넣으면
**숫자가 큰 값이 학습을 지배한다.** 전부 `-1 ~ 1` 근처로 맞춰서 넣는다.

위치는 **받침대 기준(로컬)** 으로 바꿔서 넣는다.
팔이 월드 어디에 놓여 있든 같은 숫자가 나와야, 나중에 학습 영역을
여러 개로 복제해도 그대로 쓸 수 있다.

> ### 관측 개수가 틀리면 Play하는 순간 에러가 난다
> `CollectObservations`에서 넣는 개수와 `BehaviorParameters`의
> `Vector Observation Size`가 **반드시 같아야 한다.**
> 그래서 코드 끝에 `// = 12` 주석을 꼭 남긴다.

## 핵심 개념 ② — "도달하면 +1"만으로는 학습되지 않는다

**이 장에서 가장 중요한 부분이다. 먼저 실패를 보고 나서 고친다.**

인스펙터에서 `Use Dense Reward`를 **끄고** 돌려보라.

```
보상이 -1 근처에서 꿈쩍도 하지 않는다.
```

이유는 간단하다. **팔이 우연히 물체에 닿을 확률이 거의 0이기 때문이다.**
공은 아무 방향으로 밀어도 굴러가다 목표에 닿을 수 있지만,
관절 3개가 동시에 맞아야 하는 팔은 무작위로 흔들어서는 평생 못 닿는다.

칭찬받은 적이 없으니 배울 것도 없다.

그래서 **가까워진 만큼** 칭찬한다.

```csharp
AddReward((_lastDistance - distance) / arm.reach);   // 가까워지면 +, 멀어지면 -
AddReward(-1f / MaxStep);                            // 시간 페널티
```

- 가까워지면 `+`, 멀어지면 저절로 `-` 가 된다. 한 줄로 양방향이 다 된다.
- `arm.reach`(2.7)로 나눠서 크기를 맞춘다. 한 판 총합이 대략 `1`을 넘지 않는다.
- 시간 페널티는 한 판 내내 더하면 약 `-1`. **빨리 가는 쪽이 이득**이 된다.

> 이것을 **보상 설계(Reward Shaping)** 라고 한다.
> "목표에 닿기까지의 길"을 잘게 쪼개서, 가는 동안에도 신호를 주는 것이다.

---

## 핵심 개념 ③ — `MaxStep`은 반드시 넣는다

RollerBall은 `0`(무제한)이어도 됐다. 공은 굴러떨어지면 에피소드가 끝났기 때문이다.

팔은 **떨어질 곳이 없다.** 실패한 판이 영원히 끝나지 않으면
학습 데이터가 한 판도 쌓이지 않는다.

```
Max Step = 1000     (물리 50Hz 기준 20초)
```

---

## 핵심 개념 ④ — 판단 주기

```
Decision Period = 5              물리 50Hz → AI는 10Hz로 판단한다
Take Actions Between Decisions   판단 사이에는 직전 액션을 계속 적용
```

매 물리 스텝마다 판단하면 계산이 5배 들지만 결과는 거의 같다.
사람도 초당 50번 손가락을 고쳐 잡지는 않는다.

## 학습 실행

```
run_env.bat
mlagents-learn Assets/RobotArms/robotarm_config.yaml --run-id=ch3_reach
  → "Start training by pressing Play" 가 뜨면 Unity에서 Play

tensorboard --logdir results
```

`robotarm_config.yaml`에서 RollerBall과 달라진 값들:

| 값 | RollerBall | 여기 | 왜 |
|---|---|---|---|
| `batch_size` | 10 | **1024** | 한 판마다 편차가 커서 많이 모아 평균을 낸다 |
| `hidden_units` | 128 | **256** | 관측·행동이 늘어났다 |
| `beta` | 5.0e-4 | **5.0e-3** | 초반에 더 많이 탐험시킨다 |
| `max_steps` | 5000 | **1000000** | 튜토리얼용 값이 아니다 |
| `normalize` | 꺼짐 | **켬** | 관측 범위가 제각각이다 |

## 확인 체크리스트

- [ ] `Behavior Type`을 `Heuristic Only`로 두고 Play → 키보드로 움직이고 에러가 없다
- [ ] 화면 왼쪽 위에 `에피소드 / 성공 / 보상`이 보인다
- [ ] Scene 뷰에 **흰 구**(도달 범위)와 **초록 부채꼴**(물체 구역)이 보인다
- [ ] `Use Dense Reward`를 **꺼서** 보상이 `-1`에서 안 움직이는 것을 확인했다
- [ ] 다시 **켜고** 돌리면 보상이 올라간다

## 자주 밟는 함정

| 증상 | 원인 |
|---|---|
| 실행 즉시 관측 관련 에러 | `Vector Observation Size`와 `AddObservation` 개수가 다르다 |
| 에피소드가 안 끝난다 | `MaxStep`이 `0`이다 |
| 보상이 `-1`에서 꿈쩍 안 한다 | 시간 페널티만 쌓였다 = 진전 보상 `0` = **팔이 목표로 못 간다** |
| 파이썬이 안 붙는다 | `Behavior Name`과 yaml의 `behaviors:` 키 이름이 다르다 |
| 물체를 집으러 가지 못한다 | 통과 방지의 `tipExemptDistance`가 성공 판정 거리보다 작다 |

> **학습이 안 될 때는 보상·하이퍼파라미터보다 환경을 먼저 의심한다.**
> 물체가 도달 범위 밖에 있으면 무슨 짓을 해도 학습되지 않는다.

---

## 이 장에서 배우는 것

1. **키보드 입력 자리에 액션을 꽂는다.** 팔 입장에서는 누가 시켰는지 구분하지 않는다.
2. **관측은 정규화한다.** 단위가 다른 값을 그대로 섞으면 큰 값이 학습을 지배한다.
3. **보상 설계(Reward Shaping).** "닿으면 +1"만으로는 팔이 학습되지 않는다.
4. **`MaxStep`은 필수다.** 끝나지 않는 판은 학습 데이터가 되지 않는다.
5. **먼저 실패를 본다.** 스위치를 꺼서 안 되는 것을 확인하고 나서 켠다.
