# 3장 — 물체까지 도달 학습 ★ 가장 중요

> **목표**: AI가 스스로 팔을 움직여 물체까지 팔 끝을 가져간다. (아직 잡지 않는다)
> **예상 시간**: 반나절
> **ML-Agents**: **여기서 처음 등장한다**

---

## 1. 하는 일은 하나다

**2장의 키보드 입력 자리에 AI를 꽂는 것.**

```
2장:  Angle += 키보드입력 × maxSpeed × dt
3장:  Angle += AI의액션   × maxSpeed × dt      ← 숫자의 출처만 바뀐다
```

관절을 돌리는 일은 2장의 `RobotArmController`가 이미 다 해두었다.
3장에서 정할 것은 셋뿐이다.

| 정할 것 | 무엇 |
|---|---|
| **무엇을 보는가** | Observation (관측) |
| **무엇을 하는가** | Action (행동) |
| **언제 칭찬하는가** | Reward (보상) |

---

## 2. 붙일 것

Unity 메뉴에서 **`RobotArms > 3. 에이전트 설정 (도달 학습)`** 을 누르면 끝난다.

| 컴포넌트 | 설정 |
|---|---|
| `RobotArmAgent` | Arm, Target Object, Hud 연결 / **Max Step `1000`** / Success Distance `0.25` |
| `BehaviorParameters` | Behavior Name `RobotArm` / **Space Size `12`** / Stacked `1` / **Continuous Actions `3`** |
| `DecisionRequester` | Decision Period `5`, Take Actions Between Decisions ✓ |

2장의 `ManualArmDriver`는 **끈다**(지우지는 않는다).
이제 Agent의 `Heuristic()`이 똑같은 일을 하기 때문이다.
2장과 비교해보고 싶을 때 다시 켜면 된다.

### Agent 스크립트 구조

RollerBall의 `RollerAgent.cs`와 함수 구성이 똑같다.

| 함수 | 하는 일 |
|---|---|
| `OnEpisodeBegin()` | 팔 자세를 되돌리고, 물체를 테이블 위 랜덤 위치에 놓는다 |
| `CollectObservations()` | 에이전트가 "보는" 값 12개를 넣는다 |
| `OnActionReceived()` | AI가 낸 숫자 3개로 관절을 돌리고, 보상을 준다 |
| `Heuristic()` | 2장의 키보드 조작을 그대로 쓴다 |

### 에피소드 흐름

```
OnEpisodeBegin()
   ↓
CollectObservations() → 신경망 → OnActionReceived()     ← 이 두 줄을 반복
   ↓
EndEpisode()  또는  MaxStep 도달
   ↓
OnEpisodeBegin()  (새 판)
```

## 3. Observation (관측) — 12개

| 관측 내용 | 개수 | 정규화 |
|---|---|---|
| 관절 3개의 각도 | 3 | `각도 / 180` |
| 관절 3개의 각속도 | 3 | `속도 / 최대속도` |
| Tip(팔 끝) 위치 | 3 | `/ 2.7` |
| Object(물체) 위치 | 3 | `/ 2.7` |

합계 **12** (RollerBall은 8이었다)

### RollerBall과 달라진 점 — 정규화

RollerBall은 위치를 그냥 넣었다. 값의 단위가 전부 "미터" 하나였기 때문이다.

로봇 팔은 다르다.

```
관절 각도    -180 ~ 180     ← 범위가 크다
위치          -2.7 ~ 2.7    ← 범위가 작다
```

이대로 넣으면 **크기가 큰 값이 학습을 지배해버린다.**
신경망 입장에서는 "각도가 10 변한 것"과 "위치가 10 변한 것"이 같은 크기로
보이는데, 실제로는 전혀 다른 의미이기 때문이다.

그래서 각자의 최대값으로 나눠 **전부 -1 ~ 1 근처로 맞춘다.**
정규화 함수는 2장에서 이미 만들어 두었다.

```csharp
arm.NormalizedAngle(i)       // 각도 / 180
arm.NormalizedVelocity(i)    // 각속도 / 최대속도
arm.ToNormalizedLocal(위치)   // 받침대 기준 로컬 좌표 / reach
```

학습 설정(`robotarm_config.yaml`)의 `normalize: true`도 같은 일을 한 번 더 해준다.

### 위치는 "받침대 기준"으로 넣는다

월드 좌표를 그대로 넣으면, 7장에서 학습 영역을 복제했을 때
영역마다 좌표가 달라져 학습이 깨진다.
RollerBall이 `localPosition`을 쓴 것과 같은 이유다.

### 각속도를 왜 넣는가

"지금 얼마나 빨리 움직이는 중인지"를 모르면 목표를 **지나쳐 버린다.**
RollerBall이 공의 속도를 관측에 넣은 것과 같은 이유다.

> ### Space Size가 틀리면 즉시 에러가 난다
> `BehaviorParameters`의 **Space Size**와 실제 `AddObservation` 개수가
> **1이라도 다르면** 실행하자마자 에러가 난다.
>
> RollerBall 코드처럼 `// = 12` 주석을 꼭 남겨둔다.
> 4장부터 관측이 계속 늘어나기 때문에, 이 주석이 없으면 반드시 헷갈린다.

## 4. Action (행동) — 연속 3개

`Continuous Actions = 3`. **관절 개수와 같다.**

```csharp
for (int i = 0; i < arm.JointCount; i++)
    arm.Drive(i, continuous[i], Time.fixedDeltaTime);
```

`arm.Drive()`는 2장에서 이미 만든 함수다. 안에서 하는 일도 똑같다.

```
관절 3개  =  3 DOF  =  연속 액션 3개
```

**이 1:1 대응이 로봇 팔 강화학습의 핵심이다.**

### 통과 방지는 학습 중에도 켜둔다

2장에서 만든 바닥·물체 통과 방지는 **학습할 때 더 중요하다.**

사람은 팔이 테이블을 뚫으면 "아, 잘못됐네" 하고 피한다.
**AI는 그렇지 않다.** 보상만 오르면 테이블을 뚫고 지나가는 지름길을
기꺼이 학습한다. 물리적으로 불가능한 동작을 배워버리는 것이다.

환경 단계에서 **애초에 불가능한 동작을 못 하게** 막아두면,
AI는 실제로 가능한 동작 안에서만 답을 찾는다.

> `Drive()`가 막으면 그 관절은 그 방향으로 더 못 간다.
> AI 입장에서는 "그 액션을 내도 각도가 안 변한다"로 보이고,
> 각도 관측이 그대로이니 자연스럽게 다른 방향을 시도하게 된다.

## 5. Reward (보상) — 이 장의 핵심

### 먼저 실패를 경험한다

`RobotArmAgent`의 인스펙터에 **`Use Dense Reward`** 체크박스가 있다.

**① 체크를 끄고** 학습을 돌린다. RollerBall과 똑같이 `도달하면 +1`만 주는 상태다.

```
mlagents-learn Assets/RobotArms/robotarm_config.yaml --run-id=ch3_sparse
```

10만 스텝쯤 돌려보면 **거의 학습되지 않는다.**

> **왜 RollerBall은 됐는데 팔은 안 되는가**
>
> 공은 바닥을 마구 굴러다니다 보면 **우연히** 목표에 닿는다.
> 한 번이라도 닿아서 `+1`을 받으면, 거기서부터 학습이 시작된다.
>
> 팔은 관절 **세 개**를 정확한 조합으로 맞춰야만 팔 끝이 물체에 닿는다.
> 마구 흔들어서는 **우연히 닿는 일이 거의 일어나지 않는다.**
> 보상을 한 번도 못 받으면 학습할 재료 자체가 없다.

### 그다음 조밀 보상을 켠다

**② 체크를 켜고** 다시 돌린다. 이번엔 수렴한다.

| 언제 | 값 | 목적 |
|---|---|---|
| 매 스텝 | `(이전거리 - 현재거리) / 2.7` | **가까워진 만큼 칭찬.** 멀어지면 자동으로 음수 |
| 매 스텝 | `-1 / MaxStep` (= -0.001) | 빨리 끝내도록 |
| 거리 < 0.25 | `+1.0` 후 `EndEpisode()` | 성공 |

**"가까워진 만큼"이 핵심이다.**
우연히 닿기를 기다릴 필요 없이, 조금이라도 가까워지면 바로 칭찬을 받는다.
그러면 AI는 **매 스텝 피드백**을 받으며 조금씩 올바른 방향을 찾아간다.

이것을 **Reward Shaping(보상 설계)** 이라고 한다.

### 보상 크기를 맞춘다

- 진전 보상은 전부 합치면 대략 `+1` (처음 거리만큼 가까워지므로)
- 시간 페널티는 전부 합치면 대략 `-1`
- 성공 보상 `+1`

에피소드 총합이 대략 `-1 ~ +2` 안에 들어온다.
**보상 숫자가 너무 크면 학습이 불안정해진다.**

## 6. `MaxStep = 1000` — RollerBall과 다른 점

RollerBall은 `MaxStep: 0`(무제한)이었다.
공은 바닥 아래로 떨어지면 에피소드가 끝났기 때문에 문제가 없었다.

**팔은 실패해도 아무 일이 없다.** 그냥 계속 허우적거린다.
`MaxStep`을 안 걸면 한 에피소드가 영원히 안 끝나고,
**학습 데이터가 전혀 쌓이지 않는다.**

```
MaxStep = 1000   (판단 10회/초 기준 약 100초 = 넉넉함)
```

### `Decision Period = 5`의 의미

물리는 초당 50번 계산되지만 AI는 **초당 10번만** 판단한다.
학습 스텝이 1/5로 줄어 훨씬 빠르다.

`Take Actions Between Decisions`를 켜두면 판단 사이에도 직전 액션을
계속 적용해서 팔이 끊기지 않고 움직인다.
(꺼보면 뚝뚝 끊기는 게 눈에 보인다 — 좋은 실험거리다)

## 7. 학습 설정 `robotarm_config.yaml`

RollerBall 설정과 비교하면서 **왜 달라졌는지** 이해하는 것이 중요하다.

| 항목 | RollerBall | RobotArm | 이유 |
|---|---|---|---|
| `batch_size` | 10 | 1024 | 관절 제어는 한 판마다 결과 편차가 커서, 많이 모아 평균내야 안정적 |
| `buffer_size` | 100 | 10240 | 보통 batch_size의 10배로 맞춘다 |
| `hidden_units` | 128 | 256 | 관측·행동이 늘어나서 |
| `normalize` | false | **true** | 관측 값의 범위가 제각각이므로 |
| `beta` | 5.0e-4 | 5.0e-3 | 초반에 더 많이 탐험하도록 |
| `time_horizon` | 64 | 128 | 도달까지 걸리는 스텝이 길어서 |
| `max_steps` | 5000 | 1000000 | 실제로 수렴하는 데 필요한 양 |

트레이너는 RollerBall과 같은 **PPO**를 그대로 쓴다.

## 8. 학습 실행

```
run_env.bat                    (가상환경 진입)
mlagents-learn Assets/RobotArms/robotarm_config.yaml --run-id=ch3_reach
  → "Start training by pressing Play" 가 뜨면 Unity에서 Play

tensorboard --logdir results   (다른 터미널에서 학습 곡선 보기)
```

- 이어서 학습: `--resume`
- 같은 이름으로 처음부터 다시: `--force`

학습이 끝나면 `results/ch3_reach/RobotArm.onnx` 가 생긴다.
`Assets/RobotArms/Models/`로 복사하고 `BehaviorParameters`의 `Model` 칸에 넣고
Behavior Type을 `Inference Only`로 바꾸면, **파이썬 없이 Play만으로** 팔이 움직인다.

> `Behavior Type`은 씬에 `Default`로 저장되어 있다.
> - `Default` : 파이썬이 붙어 있으면 학습, 없으면 Model로 추론
> - `Heuristic Only` : 항상 키보드 조작 (사람이 직접 확인할 때)
> - `Inference Only` : 항상 Model로 추론

## 9. TensorBoard 읽는 법

| 그래프 | 정상이면 | 의미 |
|---|---|---|
| `Environment/Cumulative Reward` | **올라간다** | 한 판에서 받는 총 보상 |
| `Environment/Episode Length` | **짧아진다** | 잘 배울수록 빨리 끝낸다 |
| `Policy/Entropy` | 높다가 **서서히 내려간다** | 탐험 → 활용으로 넘어가는 중 |
| `Losses/Value Loss` | 올랐다가 내려간다 | "이 상황이 얼마나 좋은지" 예측 정확도 |

**`Episode Length`가 안 줄어들면** 성공을 못 하고 있다는 뜻이다.
`Cumulative Reward`만 보지 말고 **반드시 같이 본다.**

화면 UI에도 `에피소드 / 성공 / 보상`이 실시간으로 표시된다.
TensorBoard를 켜기 전에 눈으로 먼저 확인할 수 있다.

## 10. 확인

- [ ] Behavior Type을 `Heuristic Only`로 두고 Play → **에러 없이** 에피소드가 반복된다
- [ ] 물체가 매 에피소드마다 테이블 위 다른 위치에 나타난다
- [ ] 화면 UI에 `에피소드 / 성공 / 보상` 이 표시되고 숫자가 바뀐다
- [ ] `Use Dense Reward` **끄고** 학습 → **잘 안 되는 것을 직접 봤다**
- [ ] `Use Dense Reward` **켜고** 학습 → `Cumulative Reward`가 올라간다
- [ ] `Episode Length`가 짧아진다
- [ ] 학습된 `.onnx`를 넣고 Play → 팔이 물체를 정확히 짚는다

## 11. 잘 안 될 때 확인 순서

| 증상 | 먼저 볼 것 |
|---|---|
| 실행하자마자 에러 | `Space Size`(12)와 `AddObservation` 개수가 같은가 |
| 보상이 아예 안 오른다 | `Use Dense Reward`가 켜져 있는가 |
| 보상은 오르는데 성공을 못 한다 | 물체가 도달 범위(Gizmo 초록 부채꼴) 안에 있는가 |
| 에피소드가 안 끝난다 | `MaxStep`이 0이 아닌가 |
| 팔이 덜덜 떤다 | `Decision Period`가 5인가, `Take Actions Between Decisions`가 켜져 있는가 |
| 파이썬이 안 붙는다 | `Behavior Name`(`RobotArm`)과 yaml의 `behaviors:` 이름이 같은가 |

> **순서가 중요하다.** 보상 설계나 하이퍼파라미터를 의심하기 전에
> **환경(도달 범위)과 설정(Space Size, MaxStep)을 먼저 본다.**
> 2장에서 키보드로 확인해두었다면 대부분 여기서 걸러진다.

## 12. 해볼 만한 실험

| 실험 | 무엇을 보게 되나 |
|---|---|
| 관측에 `물체 - 팔 끝` 벡터 3개를 추가 (12 → 15) | 계산 가능한 "중복" 정보인데도 학습이 빨라진다 |
| `Decision Period`를 1로 | 판단이 5배 늘어 느려지지만 동작은 정밀해진다 |
| `beta`를 10배로 | 초반에 더 많이 헤매고, 수렴이 늦어진다 |
| 관절 하나를 고정(2 DOF로) | DOF가 줄면 얼마나 빨리 배우는지 |

## 13. 이 장에서 배우는 것

| 개념 | 내용 |
|---|---|
| **에피소드 루프** | `OnEpisodeBegin` → (`CollectObservations` → `OnActionReceived`) → `EndEpisode` |
| **희소 vs 조밀 보상** | 왜 `+1`만으로는 안 되는가 (직접 실패해보기) |
| **Reward Shaping** | "가까워진 만큼" 보상이 학습을 가능하게 만든다 |
| **관측 정규화** | 단위가 다른 값을 섞을 때 반드시 필요 |
| **`MaxStep`** | 실패한 에피소드를 끊어줘야 학습 데이터가 쌓인다 |
| **환경 제약의 역할** | AI는 물리적으로 불가능한 지름길도 기꺼이 학습한다 |
| **TensorBoard** | 보상만 보지 말고 Episode Length를 같이 본다 |
