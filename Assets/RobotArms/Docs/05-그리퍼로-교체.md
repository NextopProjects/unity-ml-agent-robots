# 5장 — 집게로 교체 (마찰로 잡기)

> 4장에서 과제는 이미 완성됐다. **이 장에서 바뀌는 것은 집는 방식 하나뿐이다.**
>
> ```
> 4장  가까이서 버튼을 누르면 붙는다     SetParent — 프로그램이 붙여준다
> 5장  손가락이 눌러서 마찰로 버틴다     붙드는 코드가 아예 없다
> ```

---

## 목표

자석을 떼고 **진짜 집게**를 단다. 과제도, 보상 공식도, 팔도 그대로다.

| | 4장 | 5장 |
|---|---|---|
| 관측 | 16 | **19** (+ 쥔 정도 1, 좌우 접촉 2) |
| 액션 | 연속 3 + 이산 1 | **그대로** (뜻만 바뀐다) |
| 잡았다의 뜻 | 프로그램이 정한 상태값 | **양쪽 손가락이 닿아 있다** |
| 놓치는 일 | 없다 | **있다.** 세게 휘두르면 빠진다 |

> **한 번에 하나씩.** 팔도 과제도 그대로 두었기에,
> 4장과 5장의 학습 곡선을 나란히 놓고 비교할 수 있다.

## 왜 어려운가 — 두 세계를 섞는다

```

## 핵심 개념 ① — 집게를 팔의 자식으로 매달면 안 된다

**가장 먼저 밟는 함정이다.**

팔은 Transform을 직접 대입해서 움직인다. 그 밑에 Rigidbody를 매달면
손가락이 **물리 엔진 몰래 순간이동**한다. 순간이동하는 손가락은 물체를
"누르지" 못한다. 통과했다 나타났다 할 뿐이다.

마찰은 **맞닿은 채로 미는 힘**에서 나오므로, 그러면 영영 잡히지 않는다.

그래서 집게는 팔 **바깥**에 두고 매 물리 스텝마다 따라가게 한다.

```csharp
void FixedUpdate()
{
    _body.MovePosition(follow.position);
    _body.MoveRotation(AimRotation(follow.position, yawReference.position));
}
```

`MovePosition`은 순간이동이 아니라 **"이번 스텝 동안 여기까지 가라"** 는 주문이다.
물리 엔진이 속도를 계산해서 옮기므로, 물린 물체도 같은 속도로 딸려간다.

> `transform.position = ...` 로 바꾸면 물린 물체가 손에서 빠진다.

## 핵심 개념 ② — 손목이 없으면 옆에서 집을 수 없다

이 팔에는 어깨·팔꿈치·좌우 회전 셋뿐이다. **손목 관절이 없다.**
그래서 팔 끝의 기울기는 우리가 정하는 게 아니라 **끌려서 정해진다.**

계산해보면 이렇다.

```
테이블 위(높이 0.1)의 물체에 닿으려면
팔뚝은 약 62도 아래로 꽂히는 자세밖에 없다.
그 방향으로 손가락(길이 0.22)을 뻗으면 끝이 테이블 아래로 들어간다.
```

**보상으로는 못 고친다. 구조의 문제다.**

관절을 하나 더 다는 대신, 손목을 **항상 아래로 고정**해서
위에서 내려 집는 방식으로 바꾼다. 좌우 방향만 팔을 따라 돌린다.

```csharp
public static Quaternion AimRotation(Vector3 tip, Vector3 basePos)
{
    Vector3 flat = tip - basePos;
    flat.y = 0f;
    return Quaternion.LookRotation(Vector3.down, flat.normalized);
}
```

> 실제 로봇 팔이 손목 축을 두는 이유가 이것이다.

## 핵심 개념 ③ — 모양이 곧 성능이다

처음에는 판 두 개로 만들었다. 물체가 **수박씨처럼 튀어나갔다.**
회전하는 판은 물체와 비스듬히 만나서, 누르는 힘이 물체를 옆으로 밀어낸다.

그래서 **다 오므렸을 때 면이 물체와 나란해지도록 거꾸로 설계한다.**

```
    ● ●      경첩    ±0.17
   ╱   ╲     위마디
  ▌     ▐    팔꿈치  ±0.27   ← 가장 바깥
   ╲   ╱     아래마디
    ▓ ▓      패드    ±0.115  ← 여기로 문다 (물체 반폭 0.1)
```

① 먼저 "나란한 자세"에 패드를 놓고
② 경첩을 패드보다 바깥에 두고
③ 거기서 **바깥으로 50도 젖힌 것**을 쉬는 자세로 삼는다

벌리면 아래가 넓은 **깔때기**가 되어 물체가 알아서 가운데로 모이고,
오므리면 **평행한 두 면**이 물체를 납작하게 문다.

### 실측 — 벌렸을 때 치수

| | 값 |
|---|---|
| 입구 | `0.714` |
| **가장 좁은 목** | **`0.556`** |
| 패드 사이 | `0.622` |
| 물체 한 변 | `0.2` |

> 집게발 모양에는 **팔꿈치와 패드 사이에 "목"** 이 생긴다.
> 물체는 이 목을 지나야 들어온다. 벌림을 38도로 뒀을 때 목이 `0.487`이라
> **허용 오차가 반 토막 났다.** → 50도로 넓혔다.
>
> **모양을 바꾸면 허용 오차를 반드시 다시 재야 한다.**
> 보기 좋아진 대신 조용히 성능이 깎일 수 있다.

허용 오차는 좌우·앞뒤 **`±0.12`** (한 방향만 어긋나면 `±0.18`).

## 핵심 개념 ④ — 마찰이 아니라 **무게**가 문제였다

물었는데 들어 올리면 미끄러졌다. 마찰 계수를 올려도, 쥐는 힘을 올려도
고쳐지지 않았다. 원인은 전혀 다른 곳에 있었다.

> **물리 엔진은 무게 차이가 큰 두 물체를 관절로 잇는 것에 약하다.**
> 가벼운 쪽이 무거운 쪽에 밀려나면서 계산이 흐트러진다.

실측:

| 손가락 무게 | 버티는 물체 무게 |
|---|---|
| `0.05 kg` | `0.2 kg` — 흔들면 빠진다 |
| **`0.6 kg`** | **`2.0 kg` — 흔들어도 버틴다** ← 이 값을 쓴다 |
| `2.0 kg` | 자기 관성 때문에 다시 빠진다 |

**계수부터 올리지 않는다.** 구조를 먼저 본다.

---

## 핵심 개념 ⑤ — 마찰 재질은 손가락에만 붙인다

```csharp
m.staticFriction = 2.0f;      // 미끄러지기 시작하는 문턱
m.dynamicFriction = 1.6f;     // 미끄러지는 중에 버티는 힘
m.frictionCombine = PhysicsMaterialCombine.Maximum;
```

`Maximum`이면 두 재질이 만날 때 **큰 쪽**이 쓰인다. 손가락에만 붙이면 충분하다.

오히려 물체에까지 붙이면 손해다. 물체가 **테이블에도** 2.0으로 들러붙어서,
깔때기가 물체를 가운데로 밀어 넣지 못한다. (실측: 밀어준 거리가 `0.008`에 그쳤다)

## 핵심 개념 ⑥ — 잠든 Rigidbody는 충돌 이벤트를 보내지 않는다

처음에는 `OnTriggerEnter`로 접촉을 잡으려 했다. **전혀 감지되지 않았다.**

물체가 테이블 위에서 멈춰 있으면 물리 엔진이 sleep 상태로 재운다.
잠든 물체에 콜라이더를 밀어 넣어도 이벤트가 오지 않는다.
학습 중에는 물체가 거의 항상 잠들어 있으니 영영 잡을 수 없다.

그래서 콜백을 기다리지 않고 **매 스텝 직접 겹침을 검사**한다.

```csharp
Physics.OverlapBoxNonAlloc(center, half, _hits, rotation, ~0, QueryTriggerInteraction.Collide);
```

물체 쪽에는 `sleepThreshold = 0`도 함께 걸어 둔다.

## 핵심 개념 ⑦ — 단계가 넷으로 늘어난다

자석은 **아무 방향에서나** 닿기만 하면 됐다.
집게는 옆에서 돌진하면 **물체를 밀어내 버린다.**
밀린 물체를 또 쫓아가니 거리가 영영 줄지 않는다.

> 이것 때문에 800만 스텝을 돌려도 보상이 `-1`에서 꿈쩍하지 않았다.

그래서 **"위로 먼저"** 가 들어간다.

```
① 잡으러 간다 — 물체 위로. 정렬되면 목표가 내려온다
② 들어올린다  — 옆으로 끌지 말고 먼저 똑바로 (0.40까지)
③ 옮긴다      — 놓을 자리 위로. 정렬되면 내려온다
④ 놓는다      — 손을 펴면 끝
```

```csharp
Vector3 Above(Vector3 spot)
    => spot + Vector3.up * (Mathf.Clamp01(Flat(Mover, spot) / AlignRadius) * HoverHeight);
```

멀면 높이 뜬 점, 가까우면 낮은 점을 목표로 준다.
**"위로 돌아 내려오는" 경로가 저절로 만들어진다.**

| 값 | |
|---|---|
| `HoverHeight` | `0.35` |
| `AlignRadius` | `0.30` |
| `LiftHeight` | `0.40` |

단계 보너스: 정렬 `+0.3` · 물기 `+0.5` · 들기 `+0.5` · 놓기 `+1.0`

## 핵심 개념 ⑧ — 거리 기준점이 팔 끝이 아니다

집게는 팔 끝보다 **`0.22` 아래**에 물린다. 팔 끝을 물체에 맞추면
손가락은 물체보다 아래, 테이블 속에 있게 된다.

```csharp
public Vector3 GripCenter => transform.position + transform.forward * gripDepth;
```

관측도 보상도 전부 이 **손가락 사이 한가운데**로 잰다.

## 핵심 개념 ⑨ — 작업 범위가 4장보다 좁아진다

집게는 **위에서 내려와야** 하므로, 실제로 작업할 수 있는 구역이 자석보다 좁다.
정기구학으로 전수 스캔해서 쟀다.

```
손가락 사이를 물체 중심(높이 0.1)에 0.10 안으로 보낼 수 있는가
(blockPenetration ON, clearance 0.14, gripDepth 0.22)

거리    0도   30도   60도   90도   110도
 1.05    X     X     X     X     X
 1.10    O     O     O     O     O     ← 여기부터
 2.75    O     O     O     O     O     ← 여기까지
 2.80    X     X     X     X     X
```

| | 4장 (자석) | 5장 (집게) |
|---|---|---|
| 실측 가능 범위 | `0.95 ~ 2.90` | **`1.10 ~ 2.75`** |
| 코드에 넣은 값 | `1.00 ~ 2.80` | **`1.15 ~ 2.70`**, 좌우 `±110도` |

> **집는 방식을 바꾸면 작업 범위도 다시 재야 한다.**
> 4장 값을 그대로 쓰면 집을 수 없는 자리를 향해 끝까지 헛돈다.

## 핵심 개념 ⑩ — 바닥 한계선을 잘못 잡으면 학습이 통째로 실패한다

**이 장에서 가장 비싼 교훈이다. 800만 스텝을 날렸다.**

손가락이 테이블을 파고들지 않게 `clearance`를 `0.29`로 올렸다. 그런데
**어깨(J0·J1)가 높이 `0.30`에 있다.** 한계선을 거기 붙이면 팔 전체가
`0.29~0.30` 사이의 **아주 얇은 층**만 지나다닐 수 있고,
통과 방지는 관절을 **하나씩** 되돌리므로 그 좁은 통로를 못 빠져나간다.

```
실측 — 통과 방지 ON일 때 스폰 25곳 중 도달 가능한 곳
  clearance 0.29  →  10곳
  clearance 0.22 이하 → 25곳
```

즉 **60%의 물체에는 접근 자체가 불가능**했다.

```
clearance = 0.14      ← 이 값을 쓴다
```

손가락이 테이블에 닿는 것은 물리가 알아서 처리한다(경첩이 꺾인다).
애초에 에이전트가 거기까지 내려갈 이유도 없다. 목표는 물체 **위**다.

> ### 검증 조건이 실제 조건과 같아야 한다
> 이 문제를 못 찾은 진짜 이유는 따로 있다.
> **잡기 검증을 `blockPenetration`을 끄고 했다.** 전부 통과했다.
> 학습은 켠 채로 돌아갔다. **편의를 위해 끈 스위치가 곧 원인이었다.**

## 핵심 개념 ⑪ — 관절을 모터처럼 느리게

2장 값(어깨 120 · 팔꿈치 180 · 좌우 120 도/초)은 손으로 조작할 때는
시원했지만, 물리 집게를 단 뒤로는 너무 빠르다.

- 빠르게 다가가면 집게가 물체를 **쳐서 날려버린다**
- 급정거할 때 물고 있던 물체가 관성으로 빠진다

```
60 / 90 / 60 도/초      (2장의 절반)
```

한 판이 3000스텝(60초)이라 시간은 넉넉하다.

## 핵심 개념 ⑫ — 병렬 학습

```
메뉴 > RobotArms > 학습 영역 복제 (병렬 학습)    → 25개 (5x5)
메뉴 > RobotArms > 학습 영역 되돌리기 (1개로)
```

강화학습이 느린 이유는 계산이 무거워서가 아니라 **경험을 모으는 속도**다.
같은 환경을 25개 돌리면 경험이 25배로 쌓인다.

**학습 코드는 한 줄도 바꾸지 않는다.**
ML-Agents는 `Behavior Name`이 같은 에이전트를 모두 **한 두뇌**로 묶기 때문이다.

> 복제는 **1~5장 구성을 모두 마친 뒤** 마지막에 한다.
> 장별 메뉴는 이름으로 부품을 찾으므로, 복제본이 있으면 첫 영역만 고친다.
>
> 저장소에는 **1개 상태로** 커밋한다. 복제본이 씬 파일에 들어가면
> diff가 25배로 불어나 `git log`가 교재로서 읽기 어려워진다.

거리 1.2 :  들었음  들었음  들었음  들었음  들었음
거리 1.5 :  들었음  들었음  들었음  들었음  들었음
거리 1.8 :  들었음  들었음  들었음  들었음  들었음
거리 2.1 :  들었음  들었음  들었음  들었음  들었음
거리 2.4 :  들었음  들었음  들었음  들었음  들었음

물기 25/25   들어올리기 25/25   가장 낮았던 물체 높이 0.408
```

> 검증 코드는 끝에서 **반드시 5장 메뉴를 다시 실행하고 저장한다.**
> 물리를 돌려본 자세가 그대로 씬에 저장되면, 다음에 열었을 때
> 손가락이 반쯤 오므려진 채로 시작한다.
> `Physics.simulationMode`처럼 전역 설정을 만지는 부분은 `try / finally`로 감싼다.
> 되돌리기 전에 예외가 나면 **프로젝트 설정에 그대로 저장된다.**

---

## 확인 체크리스트

- [ ] `Hand`에 붙은 스크립트가 **1개**(`Gripper`)다
- [ ] 손가락이 **활짝 벌어져** 있다 (패드 사이 `0.622`)
- [ ] `Heuristic Only`로 Play → `Space`로 집어 들 수 있다
- [ ] 세게 휘두르면 **빠진다** (붙드는 코드가 없다는 증거다)
- [ ] `Vector Observation Size` = **19**
- [ ] 물체가 테이블에 들러붙어 있지 않다 (마찰 재질이 물체에 붙었는지 확인)

---

## 자주 밟는 함정

| 증상 | 원인 |
|---|---|
| 손가락이 물체를 통과한다 | **Transform으로 움직이는 것 아래에 Rigidbody를 매달았다** |
| 물린 물체가 손에서 빠진다 | `transform.position = …` 으로 옮겼다. `MovePosition`을 쓴다 |
| 옆에서 집으려니 손가락이 바닥을 판다 | **손목 관절이 없어서 생기는 구조적 한계다.** 손목을 아래로 고정한다 |
| 집으려 하면 물체가 밀려 달아난다 | 손가락 면이 물체와 비스듬하다. 오므린 자세부터 거꾸로 설계한다 |
| **물었는데 들면 미끄러진다** | **마찰·힘이 아니라 무게 문제다.** 손가락 `0.05kg` → `0.6kg` |
| 물체가 테이블에 들러붙어 있다 | 마찰 재질을 물체에도 붙였다. `Maximum`이면 손가락에만 붙이면 된다 |
| 조금만 어긋나도 못 집는다 | 벌렸을 때 **가장 좁은 목**이 물체보다 넉넉한가 |
| 모양만 바꿨는데 성능이 떨어졌다 | **모양을 바꾸면 허용 오차를 다시 재야 한다** |
| 손가락이 아예 안 오므라든다 | 벌린 손끝이 테이블에 걸렸다. `GripDepth`를 키운다 |
| 트리거가 아예 안 온다 | **잠든 Rigidbody는 이벤트를 발생시키지 않는다.** 겹침 검사로 직접 본다 |
| 물리 질의 결과가 한 박자 늦다 | Transform을 옮긴 뒤 `Physics.SyncTransforms()`를 부른다 |
| `HingeJoint.angle`이 `NaN`이다 | 두 손가락의 회전축을 반대로 달았다. **축은 같게, 부호로 구분** |
| `HingeJoint.anchor`가 엉뚱하다 | anchor는 **로컬 좌표**라 스케일이 곱해진다 |
| 바닥 한계선을 올렸더니 학습이 죽었다 | `clearance`가 어깨 높이(`0.30`)에 가까우면 팔이 얇은 층에 갇힌다 |
| 집게로 다가가면 물체가 도망간다 | 옆에서 직진하면 밀어낸다. **물체 위로 먼저** 간다 |
| 에피소드마다 이상한 자세로 시작한다 | 쉬는 자세를 "현재 상태"로 기억했다. **자리를 숫자로 적는다** |
| 씬을 열면 그리퍼가 반쯤 오므려져 있다 | **물리를 돌려본 뒤 그대로 저장했다.** 메뉴를 다시 실행하고 저장한다 |
| 팔은 움직이는데 그리퍼가 안 따라온다 | `Physics.simulationMode`가 `Script`로 남았다 |

---

## 이 장에서 배우는 것

1. **운동학과 물리를 섞는 법.** Transform으로 움직이는 것 아래에 Rigidbody를 매달지 않는다.
2. **`MovePosition`.** 순간이동과 "이번 스텝에 여기까지"는 물리적으로 완전히 다르다.
3. **구조가 과제를 결정한다.** 손목이 없으면 옆에서 집을 수 없다. 보상으로는 못 고친다.
4. **계수부터 올리지 않는다.** 마찰·힘으로 안 되던 것이 무게 하나로 풀렸다.
5. **물리 이벤트를 믿지 않는다.** 잠든 Rigidbody는 트리거를 보내지 않는다.
6. **모양이 곧 성능이다.** 모양을 바꾸면 허용 오차를 다시 잰다.
7. **검증 조건 = 실제 조건.** 편의를 위해 끈 스위치가 곧 원인이 된다.
8. **병렬 학습.** 코드를 고치지 않고 경험을 25배로. `Behavior Name`이 같으면 한 두뇌다.
9. **한 번에 하나씩.** 팔과 과제를 그대로 두었기에 4장과 곡선을 비교할 수 있다.
