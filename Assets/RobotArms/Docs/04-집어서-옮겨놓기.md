# 4장 — 집어서 옮겨 놓기 (자석 방식) ★

> **목표**: 물체를 집어서 놓을 자리로 옮겨 내려놓는다.
> **예상 시간**: 반나절
> **이 장에서 프로젝트의 최종 과제 형태가 완성된다.**

---

## 1. 이 장이 왜 4장인가

**"집어서 옮겨 놓기"는 이 프로젝트의 목표 그 자체다.**

이걸 마지막 장까지 미루면, 앞 장들이 무엇을 향해 가는지 모른 채
부품만 만드는 셈이 된다.

그래서 4장에서 **가장 단순한 방법(자석)으로 끝까지 한 번 완성**한다.

| | 만드는 것 | 바꾸는 것 |
|---|---|---|
| **4장** | **과제를 완성한다** (자석) | — |
| 5장 | — | 집는 **방식** (자석 → 그리퍼) |
| 6장 | — | **난이도** (목표 고정 → 랜덤 → 커리큘럼) |

5장부터는 완성된 과제를 그대로 두고
**"무엇을 바꾸면 학습이 어떻게 달라지는가"** 만 실험한다.

---

## 2. 3장에서 바뀌는 것

```
관측 +4 : 지금 잡고 있는가 1 + 놓을 자리 위치 3   (12 → 16)
액션 +1 : 이산 액션 "잡기 / 놓기"                 (연속 3 → 연속 3 + 이산 1)
보상 +3 : 집기 +0.5, 놓기 성공 +1.0, 잘못 놓기 -0.3
```

`RobotArmAgent.cs`(3장)와 `RobotArmPickPlaceAgent.cs`(4장)를
나란히 열어놓고 비교하면 무엇이 늘었는지 그대로 보인다.

> ### 관측이 한 번에 4개 늘어도 되는가
> 이 프로젝트의 원칙은 "한 번에 하나씩"이다. 어긋나 보이지만,
> **추가되는 개념은 "집어서 옮긴다" 하나**다.
>
> 그 하나를 표현하는 데 "지금 들고 있는가"와 "어디에 놓아야 하는가"가
> **함께** 필요할 뿐이다. 둘 중 하나만 넣으면 과제 자체가 성립하지 않는다.

## 3. 붙일 것

Unity 메뉴에서 **`RobotArms > 4. 집어서 옮겨 놓기 (자석)`** 을 누르면 끝난다.

| 컴포넌트 | 설정 |
|---|---|
| `RobotArmPickPlaceAgent` | Grab Distance `0.25` / Place Radius `0.25` / **Max Step `2500`** |
| `BehaviorParameters` | Behavior Name `RobotArmPickPlace` / **Space Size `16`** / 연속 `3` + 이산 `[2]` |

3장의 `RobotArmAgent`는 **제거된다.** 한 오브젝트에 Agent는 하나만 있어야 한다.

> ### 순서가 중요하다
> 3장 에이전트를 **먼저 지우면** `DecisionRequester`가
> "Agent가 필요하다"며 삭제를 거부한다.
>
> **새 에이전트를 먼저 붙여** 조건을 만족시킨 뒤에 옛 것을 지워야 한다.
> (`RequireComponent`가 걸린 컴포넌트를 교체할 때 흔히 겪는 일이다)

## 4. 핵심 아이디어 — "현재 목표"가 상태에 따라 바뀐다

```
잡기 전  →  현재 목표 = 물체
잡은 후  →  현재 목표 = 놓을 자리
```

```csharp
float DistanceToGoal()
{
    if (isHolding) return 거리(물체, 놓을자리);
    else           return 거리(팔끝, 물체);
}
```

이렇게 하면 AI는 **"현재 목표를 향해 간다"** 는
**하나의 단순한 규칙**만 배우면 된다. 보상 공식도 하나로 끝난다.

> ### 다단계 과제를 다루는 일반적인 방법
> 단계마다 보상 공식을 따로 만들면 금방 복잡해지고 서로 충돌한다.
>
> **"지금 몇 단계인지"를 관측에 넣고, "현재 목표"만 바꾼다.**
> 공식은 하나로 유지한다. 단계가 10개가 되어도 같은 방법이 통한다.

---

## 5. Observation — 12개 → **16개**

| 관측 내용 | 개수 |
|---|---|
| (3장과 동일한 12개) | 12 |
| **지금 물체를 잡고 있는가** (`0` 또는 `1`) | **1** |
| **놓을 자리 위치** | **3** |

합계 **16**. Space Size를 `16`으로 바꾼다.

### "지금 잡고 있는가"가 없으면 학습이 불가능하다

```
팔 자세가 똑같은데
  잡기 전 → 물체 쪽으로 내려가야 한다
  잡은 후 → 놓을 자리 쪽으로 가야 한다
```

**해야 할 행동이 정반대인데 보이는 것이 같으면, 학습은 불가능하다.**

→ **여러 단계로 이루어진 과제에서는
"지금 몇 단계인지"를 반드시 관측에 넣는다.**

"놓을 자리가 어디인가"는 그 짝이다.
잡고 있으면 이쪽으로, 아니면 물체 쪽으로 가면 된다.

## 6. Action — 연속 3개 + **이산 1개**

`Discrete Branches = 1`, `Branch 0 Size = 2`

```
0 = 놓기
1 = 잡기
```

### 왜 이건 이산(Discrete)인가

| | 관절 각도 | 잡기 |
|---|---|---|
| 중간값의 의미 | "조금 더 / 조금 덜" — 의미 있음 | 없음 |
| 적절한 타입 | **연속** | **이산** |

**액션의 성질에 맞는 타입을 고르는 것이 설계의 일부다.**

ML-Agents는 연속과 이산을 **동시에** 쓸 수 있다. RollerBall에는 없던 개념이다.

```csharp
var continuous = actions.ContinuousActions;   // 관절 회전
bool wantGrip = actions.DiscreteActions[0] == 1;
```

> `Heuristic()`에서 이산 액션을 쓸 때 주의할 점이 있다.
> `DiscreteActions`는 프로퍼티라서 `actionsOut.DiscreteActions[0] = ...` 로
> 바로 대입하면 컴파일 에러가 난다. 지역 변수로 한 번 받아서 써야 한다.
> ```csharp
> var discrete = actionsOut.DiscreteActions;
> discrete[0] = RobotArmInput.Grip ? 1 : 0;
> ```

## 7. 자석(Attach) 방식

손가락으로 진짜 집는 그리퍼는 **5장**에서 한다.
4장에서는 **과제의 뼈대를 완성하는 데만** 집중한다.

```
잡기:  (Tip과 Object의 거리 < 0.25) AND (잡기 액션 == 1) AND (아직 안 잡음)
         → Object를 Tip의 자식으로 붙인다        transform.SetParent(arm.tip)
         → Object의 Rigidbody를 isKinematic = true
         → isHolding = true

놓기:  (잡은 상태) AND (잡기 액션 == 0)
         → Object를 원래 부모로 되돌린다
         → Rigidbody를 isKinematic = false       (중력에 따라 떨어진다)
         → isHolding = false
```

### 왜 잡는 동안 물리를 끄는가

물체를 팔 끝에 붙여놓아도 물리 엔진은 계속 중력을 적용한다.
그러면 **중력이 끌어내리고 팔이 붙잡으면서 서로 싸운다.**
잡고 있는 동안만 `isKinematic = true`로 두는 것이 가장 단순하고 안정적이다.

### `Tip`이 스케일 1이어야 하는 이유

물체를 `Tip`의 자식으로 붙이는데, `Tip`에 스케일이 있으면
**물체가 그 비율만큼 쪼그라든다.**

1장에서 `Tip`을 빈 오브젝트로 두고 보이는 구는 `TipMesh`로 분리해둔 것이
여기서 값을 한다. (검증: 잡은 뒤에도 물체 크기 `(0.2, 0.2, 0.2)` 유지)

### 통과 방지와의 관계

2장의 통과 방지에는 `tipExemptDistance`(0.28)가 있다.
팔 끝에서 이 거리 안쪽은 물체 검사에서 제외한다.

```
grabDistance 0.25  <  tipExemptDistance 0.28
```

**이 부등식이 깨지면 물체에 다가가는 것 자체가 막혀 영영 잡을 수 없다.**
둘 중 하나를 바꾸면 반드시 같이 확인한다.

## 8. Reward

| 언제 | 값 | 목적 |
|---|---|---|
| 매 스텝 | `(이전거리 - 현재거리) / 2.7` | **현재 목표**에 가까워진 만큼 |
| 매 스텝 | `-1 / MaxStep` | 빨리 끝내도록 |
| 집는 데 성공 (한 번만) | `+0.5` | 잡기를 시도할 이유를 만들어준다 |
| 놓을 자리에 내려놓기 성공 | `+1.0` 후 `EndEpisode()` | 최종 목표 |
| 엉뚱한 곳에 놓음 | `-0.3` (에피소드는 계속) | 아무 데나 놓지 않도록 |

### 집기 보상 `+0.5` — 새 행동으로 건너가는 다리

잡아봤자 보상이 없으면 AI는 "잡기"를 시도할 이유가 없다.
영원히 물체 근처만 맴돌다 끝난다.

### 한 에피소드에 한 번만 준다

이 조건이 없으면 AI는 **잡았다 놨다를 반복해서 보상만 긁어모으는 것**을 배운다.
과제는 하나도 안 풀고 점수만 올리는 것이다.

> 강화학습에서 흔히 말하는 **보상 해킹(reward hacking)** 의 가장 단순한 예다.
> **"이 보상을 악용하는 가장 게으른 방법은 무엇인가"** 를 항상 먼저 생각해본다.

### 잘못 놓았을 때 에피소드를 끝내지 않는 이유

끝내버리면 AI는 **"놓으면 큰일 난다"** 만 배우고,
**"잘못 놓았으면 다시 주우면 된다"** 는 배우지 못한다.

실수에서 회복하는 것도 과제의 일부다.

### 잡는 순간 거리 기준을 새로 잡는다

목표가 "물체"에서 "놓을 자리"로 바뀌는 순간, 기준을 새로 잡지 않으면
**그 한 스텝에 보상이 크게 튄다.**

```csharp
void Grab() {
    ...
    _previousDistance = DistanceToGoal();   // ← 새 목표 기준으로 다시 잡는다
}
```

## 9. 성공 조건 네 가지

```
1. 한 번이라도 물체를 들었다      ← 가만히 있다가 성공하는 것을 막는다
2. 지금은 손을 뗀 상태다
3. 물체가 놓을 자리 위에 있다      (수평 거리 < 0.25)
4. 물체가 멈춰 있다                (속도 < 0.2)
```

**1번과 4번이 없으면 안 된다.**

| 빠지면 | 무슨 일이 생기나 |
|---|---|
| 1번 (들어본 적 있음) | 물체가 놓을 자리 근처에 스폰되면 **아무것도 안 하고 성공** |
| 4번 (멈춰 있음) | **떨어지는 도중에** 성공 처리된다 |

그래서 스폰할 때도 **물체를 놓을 자리에서 `minSeparation`(0.6) 이상
떨어뜨리는 검사**를 함께 넣었다.

## 11. 확인

- [ ] 키보드로 물체를 집어 초록 원판 위로 옮기고 `Space`를 떼면 성공한다
- [ ] 화면 UI에 `목표=물체` / `목표=놓을자리` 가 상태에 따라 바뀐다
- [ ] 잡은 물체의 **크기가 변하지 않는다**
- [ ] 엉뚱한 곳에서 놓으면 벌점이 들어오고 **에피소드는 계속된다**
- [ ] 잡았다 놨다를 반복해도 `+0.5`가 **한 번만** 들어온다
- [ ] `BehaviorParameters`의 Space Size가 `16`, 이산 묶음 크기가 `2`다
- [ ] 학습 후, 팔이 물체를 집어 놓을 자리로 옮긴다
- [ ] **학습 곡선을 저장해둔다** (5장에서 그리퍼와 비교할 것이다)

### 검증해둔 것

| 항목 | 결과 |
|---|---|
| 스폰 300회 | 물체↔놓을자리 최소 `0.60` ≥ `0.6`, **즉시 성공 0회**, 범위 밖·테이블 밖 0회 |

| 목표 전환 | `목표=물체` → `목표=놓을자리` |

## 12. 잘 안 될 때

| 증상 | 먼저 볼 것 |
|---|---|
| 물체 근처에만 가고 잡지 않는다 | `grabReward`가 0이 아닌가 |
| 잡았다 놨다만 반복한다 | 집기 보상이 한 번만 들어오는가 |
| 잡기 직전에 멈춘다 | `grabDistance < tipExemptDistance` 인가 |
| 잡으면 물체가 작아진다 | `Tip`의 Scale이 (1,1,1)인가 |
| 아무것도 안 했는데 성공한다 | 물체와 놓을 자리가 겹쳐 스폰되지 않는가 |
| 떨어지는 중에 성공한다 | `IsObjectAtRest()` 조건이 들어 있는가 |
| 집기만 하고 옮기지 않는다 | 잡은 후 `DistanceToGoal`이 놓을 자리 기준으로 바뀌는가 |
| 잡자마자 보상이 크게 튄다 | `Grab()`에서 `_previousDistance`를 다시 잡는가 |
| 에이전트가 두 번 동작한다 | `Base`에 Agent가 두 개 붙어 있지 않은가 |
