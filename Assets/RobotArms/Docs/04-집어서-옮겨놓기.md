# 4장 — 집어서 옮겨 놓기 (자석 방식)

> **이 프로젝트의 최종 과제가 여기서 완성된다.**
> 5장부터는 이 과제를 그대로 두고 **집는 방식과 난이도만** 바꿔가며 실험한다.

---

## 목표

랜덤한 자리의 물체를 **집어서**, 랜덤한 **놓을 자리**로 옮겨 놓는다.
놓고 나면 놓을 자리가 새 자리로 바뀌고, 판이 끝날 때까지 계속한다.

```
3장    가서 닿는다                        관측 12 / 연속 3
4장    가서 집고 → 옮기고 → 놓는다        관측 16 / 연속 3 + 이산 1
```

**집는 방법은 가장 단순한 자석으로 한다.** 가까이서 버튼을 누르면 붙는다.
물리로 제대로 집는 것은 5장에서 한다.

> 왜 자석부터인가: 집는 방식과 과제 구조를 **한 번에** 바꾸면,
> 학습이 안 될 때 어느 쪽이 원인인지 알 수 없다.
> 4장에서 과제를 완성해두면, 5장에서 바뀌는 것은 집는 방식 하나뿐이다.

---

## 3장에서 바뀌는 것

| | 3장 | 4장 |
|---|---|---|
| 관측 | 12 | **16** (+ 잡고있는가 1, 지금 가야 할 점 3) |
| 액션 | 연속 3 | **연속 3 + 이산 1** |
| 목표 | 물체 하나 | **상태에 따라 바뀐다** |
| 성공하면 | 판이 끝난다 | **놓을 자리만 바뀌고 계속한다** |
| 성적표 | 에피소드 길이 | **`Task/Cycles`** (한 판에 몇 번 옮겼나) |
| `MaxStep` | 1000 | **3000** |

---

## 붙일 것

```
메뉴 > RobotArms > 4. 집어서 옮겨 놓기 (자석)
```

| 컴포넌트 | 설정 |
|---|---|
| `RobotArmPickPlaceAgent` | arm, targetObject, placeTarget, hud 연결 / Max Step **3000** |
| `BehaviorParameters` | Behavior Name `RobotArmPickPlace` / 관측 **16** / 연속 **3** + 이산 **1(값 2개)** |
| `RobotArmAgent` | **지운다** (새 Agent를 먼저 붙이고 나서) |

> `DecisionRequester`가 Agent를 요구하기 때문에, 옛 Agent를 먼저 지우면
> Unity가 삭제를 거부한다. **새 것을 먼저 붙인다.**

## 핵심 개념 ① — 연속 액션과 이산 액션을 함께 쓴다

```csharp
bp.BrainParameters.ActionSpec = new ActionSpec(3, new[] { 2 });
//                                            ↑연속 3   ↑이산 1개, 값 2가지
```

- **관절 각도**는 "조금 더 / 조금 덜"이 의미 있는 **연속량**이다.
- **잡기**는 잡거나 안 잡거나 둘 중 하나다. 중간값이 의미가 없는 **이산량**이다.

액션의 성질에 맞는 타입을 고르는 것도 설계의 일부다.

---

## 핵심 개념 ② — 목표가 상태에 따라 바뀐다

이 장에서 가장 중요한 아이디어다.

```csharp
Vector3 CurrentGoal()
{
    if (!_holding) return targetObject.position;        // ① 가지러 간다

    Vector3 local = arm.ToLocal(placeTarget.position);  // ② 놓을 자리로 옮긴다
    local.y = arm.spawnHeight;
    return arm.transform.TransformPoint(local);
}
```

목표가 둘이지만 **보상 공식은 3장과 똑같이 하나다.**

```csharp
AddReward(Mathf.Clamp((_lastDistance - distance) / arm.reach, -0.05f, 0.05f));
```

AI는 "지금 가야 할 점으로 간다"는 규칙 하나만 배우면 된다.

### 그래서 관측에 "지금 가야 할 점"을 넣는다

```csharp
sensor.AddObservation(_holding ? 1f : 0f);                    // 1
sensor.AddObservation(arm.ToNormalizedLocal(CurrentGoal()));  // 3
```

`_holding`이 없으면 **학습이 불가능하다.** 팔 자세가 똑같아도
"가지러 가는 중"과 "들고 가는 중"은 해야 할 행동이 정반대인데,
그 둘을 구분할 단서가 없기 때문이다.

> "놓을 자리"를 그대로 넣지 않고 **"지금 가야 할 점"**을 넣는 이유:
> 잡기 전에 놓을 자리는 쓸모없는 정보다. 개수는 똑같이 3개지만,
> **단계가 바뀌면 뜻이 바뀌는 값**을 넣는 편이 배우기 쉽다.

---

## 핵심 개념 ③ — 진전 보상에는 상한을 건다

**이걸 빼먹으면 학습이 통째로 망가진다.** 실제로 그랬다.

```
step      보상      에피소드 길이   Value Loss
 20,000   -1.58        499            -
120,000  -23.33        499          195.58     ← 발산
```

원인은 이렇다. 물체를 놓치거나 테이블 밖으로 떨어뜨리면
**목표까지의 거리가 한 스텝에 몇 미터씩 벌어진다.**
진전 보상을 그대로 주면 그 한 스텝이 판 전체의 보상을 덮어쓴다.

```csharp
// 상한 없이
AddReward((_lastDistance - distance) / arm.reach);            // -3.0 같은 값이 나온다

// 상한을 걸고
AddReward(Mathf.Clamp((...) / arm.reach, -0.05f, 0.05f));     // 최대 ±0.05
```

> `Value Loss`가 100을 넘으면 **보상 크기가 들쭉날쭉하다**는 뜻이다.
> 하이퍼파라미터가 아니라 보상 공식을 본다.

---

## 핵심 개념 ④ — 끝낼 수 없는 상황은 끝내 준다

물체가 팔이 갈 수 없는 곳으로 가면, AI는 **갈 수 없는 곳을 향해
3000스텝을 헛돈다.** 그 판은 학습에 아무 도움이 되지 않는다.

```csharp
bool ObjectLost()
{
    if (_holding) return false;             // 들고 있는 동안은 팔 안에 있다

    Vector3 p = arm.ToLocal(targetObject.position);
    if (p.y < -0.3f) return true;           // 테이블 아래로 떨어졌다

    float d = new Vector2(p.x, p.z).magnitude;
    if (d < 1.00f || d > 2.80f) return true;
    return Mathf.Abs(Mathf.Atan2(p.x, p.z) * Mathf.Rad2Deg) > 115f;
}
```

벗어났으면 `-0.5`를 주고 **판을 새로 연다.**

### 이 숫자는 실측값이다

정기구학으로 전수 스캔했다. **팔 끝을 물체에 `0.25` 안으로 가져갈 수 있는 범위**다.

```
거리    0도   30도   60도   90도   120도
 0.90    X     X     X     X     X
 0.95    O     O     O     O     O     ← 여기부터 가능
 2.90    O     O     O     O     O     ← 여기까지 가능
 3.00    X     X     X     X     X
```

그 안쪽으로 여유를 둬서 `1.00 ~ 2.80`, 좌우 `±115도`로 잡았다.
스폰 범위(`1.2~2.4`, `±60도`)보다 넉넉하므로 살짝 밀린 정도로는 판이 깨지지 않는다.

> **"팔 길이 안"과 "실제로 작업할 수 있는 곳"은 다르다.**
> 추측하지 말고 재야 한다. 좁게 잡으면 멀쩡한 판이 자꾸 끊기고,
> 넓게 잡으면 갈 수 없는 곳을 향해 끝까지 헛돈다.

---

## 핵심 개념 ⑤ — 성공해도 판을 끝내지 않는다

```csharp
AddReward(placeReward);
_cycles++;
MovePlaceTarget(arm.ToLocal(targetObject.position));   // 목표만 새 자리로
ResetCycle();
```

성공할 때마다 판을 끝내면 **한 판에서 배우는 것이 한 번**뿐이다.
계속 이어가면

- 한 판에서 여러 번 배운다 (경험이 촘촘해진다)
- 물체가 **어디에 놓여 있든** 집어야 한다. 직전에 자기가 놓은 자리다
- "옮기고 나면 또 옮긴다"는 실제 작업에 가까워진다

### 그래서 성적표가 바뀐다

에피소드 길이는 늘 최대값(3000)이 된다. 잘하는지 알 수 없다.

```csharp
Academy.Instance.StatsRecorder.Add("Task/Cycles", _cycles);
```

TensorBoard에 **`Task/Cycles`** 로 나타난다. 한 판에 몇 번 옮겼는가가 실력이다.
**내가 만든 지표를 TensorBoard에 올리는 법**이기도 하다.

---

## 핵심 개념 ⑥ — 물체도 놓을 자리도 매번 랜덤이다

놓을 자리를 고정하면 AI가 **그 자리를 통째로 외워버린다.**
관측을 보지 않고도 성공하니, 겉보기 성적은 좋은데 아무것도 배우지 못한다.

둘 다 흔들되 **최소 `0.6`은 떨어뜨린다.** 겹치면 아무것도 안 하고 성공해버린다.

---

## 보상 한눈에

| 언제 | 값 | 왜 |
|---|---|---|
| 가까워진 만큼 | `±0.05` 이내 | 길을 알려준다. 상한이 없으면 발산한다 |
| 매 스텝 | `-1/MaxStep` | 빨리 하는 쪽이 이득이 되게 |
| 처음 집었을 때 | `+0.5` | 새 행동으로 건너가는 **다리**. 한 사이클에 한 번만 |
| 놓을 자리에 놓기 | `+1.0` | 진짜 목표 |
| 엉뚱한 곳에서 놓기 | `-0.3` | 판은 계속한다. 실수에서 회복하는 것도 과제다 |
| 작업 범위 밖으로 | `-0.5` + **판 종료** | 끝낼 수 없는 상황을 끝낸다 |

- [ ] 물체를 테이블 밖으로 밀면 판이 새로 시작된다
- [ ] TensorBoard에 `Task/Cycles` 가 보인다

## 자주 밟는 함정

| 증상 | 원인 |
|---|---|
| **보상이 -100 아래로 폭주한다** | **끝나지 않는 실패 상황이 있다.** 진전 보상 상한 + 실패 종료를 넣는다 |
| `Value Loss`가 100을 넘는다 | 보상 크기가 들쭉날쭉하다. 한 스텝 진전 보상에 상한을 건다 |
| 자꾸 timeout으로 끝난다 | 물체가 **집을 수 없는 자리**로 갔다. 작업 범위를 따로 둔다 |
| 성공하는데 에피소드 길이가 안 줄어든다 | 반복 과제라면 정상이다. `Task/Cycles`로 본다 |
| 잡았다 놨다만 반복한다 | 집기 보상이 매번 지급된다. 한 사이클에 한 번만 주도록 막는다 |
| 아무것도 안 했는데 성공한다 | 물체와 놓을 자리가 겹쳤다. `minSeparation`을 둔다 |
| 떨어지는 중에 성공한다 | 성공 판정에 "물체가 멈춰 있는가"가 빠졌다 |
| 잡은 물체가 쪼그라든다 | `Tip`에 스케일이 있다. `Base`와 `Tip`은 scale 1을 유지한다 |
| Agent 교체 시 삭제가 거부된다 | `DecisionRequester`가 Agent를 요구한다. **새 Agent를 먼저 붙인다** |
| 성적이 좋은데 실제로는 못한다 | 놓을 자리가 고정이다. 자리를 외운 것이다 |

---

## 이 장에서 배우는 것

1. **연속 + 이산 하이브리드 액션.** 액션의 성질에 맞는 타입을 고른다.
2. **상태에 따라 목표가 바뀌는 다단계 과제.** 보상 공식은 하나로 유지한다.
3. **중간 보상은 다리다.** 집기 보상이 없으면 집기를 시도할 이유가 없다.
4. **진전 보상에는 상한을 건다.** 없으면 한 스텝이 판 전체를 덮는다.
5. **끝낼 수 없는 상황은 끝내 준다.** 실패 종료 조건도 설계의 일부다.
6. **내가 만든 지표를 TensorBoard에 올린다.** (`StatsRecorder`)
7. **외울 수 있게 두지 않는다.** 물체도 목표도 매번 흔든다.
