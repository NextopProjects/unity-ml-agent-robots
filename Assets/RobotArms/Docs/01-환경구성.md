# 1장 — 환경 구성

> **목표**: 3관절 로봇 팔과 물체가 놓인 씬을 만든다. 아직 코드는 없다.
> **예상 시간**: 1시간
> **ML-Agents**: 아직 나오지 않는다

---

## 1. 씬 만들기

1. `Assets/RobotArms/Scenes/` 폴더에 새 씬 `RobotArms.unity` 를 만든다
2. `File > Build Profiles`(또는 Build Settings)에서 이 씬을 목록에 추가한다
3. 씬을 연다

---

## 2. 오브젝트 배치

### 빠른 방법

Unity 상단 메뉴에서 **`RobotArms > 1. 환경 만들기 (씬 구성)`** 을 누른다.
아래 구조가 한 번에 만들어진다.

### 구조

```
TrainingArea                  빈 오브젝트. 기준점이자, 나중에 통째로 복제할 단위
├── Table                     납작한 큐브. 물체가 놓이는 바닥
├── RobotArm                  빈 오브젝트 (묶음용)
│   └── Base                  빈 오브젝트 ← 2장부터 스크립트가 여기 붙는다
│       ├── BaseMesh          원기둥. 바닥에 고정된 받침대 몸통 (보이기만 한다)
│       └── J0                빈 오브젝트 = 관절0 (좌우 회전, Y축)
│           ├── J0Mesh        납작한 원기둥. 돌아가는 턴테이블 (보이기만 한다)
│           └── J1            빈 오브젝트 = 관절1 (어깨, X축)
│               ├── Link1     원기둥. 팔 윗부분
│               └── J2        빈 오브젝트 = 관절2 (팔꿈치, X축)
│                   ├── Link2 원기둥. 팔 아랫부분
│                   └── Tip   빈 오브젝트. 팔 끝 = 물체를 집는 지점
│                       └── TipMesh   작은 구 (보이기만 한다)
├── Object                    작은 큐브 + Rigidbody. 옮길 물체
└── PlaceTarget               납작한 원판. 놓을 자리 (6장에서 사용)
```

### 치수

Position / Scale 은 전부 **로컬** 값이다.

| 오브젝트 | Position | Rotation | Scale |
|---|---|---|---|
| `Table` | (0, -0.05, 1.2) | - | (5.0, 0.1, 4.0) |
| `Base` | (0, 0, 0) | - | (1, 1, 1) |
| `BaseMesh` | (0, 0.15, 0) | - | (0.45, 0.15, 0.45) |
| `J0` | (0, 0.30, 0) | - | (1, 1, 1) |
| `J0Mesh` | (0, 0.02, 0) | - | (0.40, 0.02, 0.40) |
| `J1` | (0, 0, 0) | - | (1, 1, 1) |
| `Link1` | (0, 0, 0.75) | (90, 0, 0) | (0.13, 0.75, 0.13) |
| `J2` | (0, 0, 1.50) | - | (1, 1, 1) |
| `Link2` | (0, 0, 0.60) | (90, 0, 0) | (0.11, 0.60, 0.11) |
| `Tip` | (0, 0, 1.20) | - | (1, 1, 1) |
| `TipMesh` | (0, 0, 0) | - | (0.14, 0.14, 0.14) |
| `Object` | (0, 0.1, 1.8) | - | (0.2, 0.2, 0.2) |
| `PlaceTarget` | (-1.2, 0.01, 1.2) | - | (0.35, 0.01, 0.35) |

### 머티리얼

`Assets/RobotArms/Materials/` 에 용도 이름으로 만든다.
**색상 코드로 이름을 지으면 나중에 색을 바꿀 때 이름이 거짓말이 된다.**

| 머티리얼 | 쓰는 곳 | 색 |
|---|---|---|
| `M_Table` | Table | 밝은 회색 |
| `M_ArmBase` | BaseMesh | 진한 회색 |
| `M_Turntable` | J0Mesh | 황토색 |
| `M_UpperArm` | Link1 | 진한 파랑 |
| `M_ForeArm` | Link2 | 밝은 파랑 |
| `M_Tip` | TipMesh | 노랑 |
| `M_TargetObject` | Object | 주황 |
| `M_PlaceTarget` | PlaceTarget | 초록 |

### 콜라이더 정리

| 오브젝트 | Collider | 이유 |
|---|---|---|
| `Table`, `Object` | **남긴다** | 물체가 떨어져 테이블 위에 멈춰야 한다 |
| 팔의 모든 메시, `PlaceTarget` | **지운다** | 팔은 물리 없이 Transform으로만 돌릴 것이라, 콜라이더가 있으면 물체를 엉뚱하게 밀어낸다 |

`Object`에는 **Rigidbody**를 붙인다 (Mass `0.2`).

## 3. 관절 3개 = 3 DOF

이 팔은 관절이 3개다. 실제 산업용 로봇 팔의 가장 기본적인 구성이다.

| 관절 | 이름 | 회전축 | 하는 일 |
|---|---|---|---|
| 0 | `J0` | **Y축** | **좌우로 돈다** (몸통 회전) |
| 1 | `J1` | X축 | 어깨 — 위아래 |
| 2 | `J2` | X축 | 팔꿈치 — 위아래 |

**J0이 없으면** 팔은 앞뒤·위아래로만 움직이는 평면 로봇이 된다.
J0이 있어야 **3차원 공간 어디든** 팔 끝을 가져갈 수 있다.

```
             J0 (좌우)
               ↓
    ┌──────────────────────┐
    │   J1(어깨) → J2(팔꿈치) → Tip
    └──────────────────────┘
      이 평면 전체가 J0을 따라 좌우로 돈다
```

---

## 4. 지켜야 할 4가지

### ① 관절과 링크를 반드시 나눈다

`J1`은 **회전만** 담당하는 빈 오브젝트, `Link1`은 그 자식인 실제 막대다.

이렇게 해야
- "회전축 = 관절", "길이 = 링크"가 눈에 보이고
- 5장에서 그리퍼를, 7장에서 물리 관절을 **구조를 바꾸지 않고** 붙일 수 있다

### ② 스케일이 있는 오브젝트에는 자식을 붙이지 않는다

`Base`와 `Tip`은 **스케일 1인 빈 오브젝트**다.
보이는 몸통은 `BaseMesh`, `TipMesh`로 따로 뺐다.

| 만약 | 어떻게 되나 |
|---|---|
| `Base`에 직접 원기둥을 붙이고 스케일을 주면 | 그 아래 관절·링크가 **전부 같은 비율로 찌그러진다** |
| `Tip`에 스케일이 있으면 | 4장에서 물체를 Tip에 붙일 때 **물체가 쪼그라든다** |

> 팔이 이상하게 납작해지거나 물체가 갑자기 작아지면 이걸 의심한다.

### ③ 좌표는 전부 로컬 좌표를 쓴다

RollerBall이 `localPosition`을 쓴 것과 같은 이유다.
나중에 `TrainingArea`를 통째로 복제해서 여러 개를 동시에 학습시켜도
(7장) 좌표가 꼬이지 않는다.

### ④ 닿는 범위를 계산해두고, 그 안에만 물체를 놓는다

```
팔이 닿는 최대 거리   = Link1(1.5) + Link2(1.2) = 2.7
물체가 나타나는 구역  = 테이블 위 부채꼴
                        거리   1.2 ~ 2.4
                        좌우각 -60° ~ +60°
```

**왜 `1.2` 부터인가**

팔에는 최대 거리뿐 아니라 **최소 거리**도 있다.
팔꿈치를 최대한 접어도 팔 끝은 어깨에서 약 `1.17` 이상 떨어져 있다.
**너무 가까운 곳은 오히려 못 닿는다.**

**왜 공중이 아니라 테이블 위인가**

`Object`에는 `Rigidbody`가 있다. **공중에 놓으면 곧바로 떨어진다.**
테이블 위에 놓으면 가만히 있어주고, 4장에서 집어 올릴 때도 그대로 쓸 수 있다.

**검증 결과** (정기구학 전수 스캔)

| 항목 | 결과 |
|---|---|
| 거리 1.2 ~ 2.4 전 구간 | 도달 가능, 최대 오차 `0.015` |
| 좌우 각도 ±60° | 관절 범위 ±120° 안에 들어옴 |
| 물체 스폰 위치 | `\|x\|` 최대 2.08 < 테이블 반폭 2.5 → 전부 테이블 안 |

> ### 초보자가 가장 많이 하는 실수
> 닿을 수 없는 위치에 물체를 놓으면 학습은 **절대** 성공하지 않는다.
> 학습이 안 될 때 보상이나 코드부터 의심하게 되는데, 원인은 보통 여기다.
>
> 2장에서 `RobotArmController`를 붙이면 Scene 뷰에 Gizmo가 그려진다.
> **흰 구 = 최대 도달 범위, 초록 부채꼴 = 물체가 나타나는 구역.**
> 초록 부채꼴이 흰 구 안쪽에 있는지 눈으로 확인한다.

## 5. 확인

- [ ] 씬이 열리고 팔, 테이블, 물체가 보인다
- [ ] Hierarchy 구조가 위 표와 같다
- [ ] `Base`와 `Tip`의 Scale이 (1, 1, 1) 이다
- [ ] `J0`의 **Rotation Y**를 손으로 돌리면 팔 전체가 좌우로 돈다
- [ ] `J1`의 **Rotation X**를 돌리면 팔 전체가 위아래로 접힌다
- [ ] `J2`의 Rotation X를 돌리면 팔꿈치 아래만 접힌다
- [ ] 팔에는 Collider가 없고, `Table`과 `Object`에는 있다

## 6. 이 장에서 배우는 것

### 부모-자식 구조가 곧 팔의 구조다

`J0`을 돌리면 그 아래 전부가 함께 돈다. `J1`을 돌리면 그 아래만 돈다.
관절 각도 3개만 정해지면 팔 끝 위치가 **자동으로** 정해진다.

이것을 **정기구학(Forward Kinematics)** 이라고 부른다.
Unity의 Transform 계층 구조가 이미 정기구학 계산기라서,
우리가 따로 계산할 필요가 없다.

### 관절 개수 = DOF(자유도)

관절이 3개이므로 **3 DOF**다.
3장에서 이 숫자가 그대로 **액션 개수**가 된다.

```
관절 3개  =  3 DOF  =  연속 액션 3개
```

**이 대응 관계가 로봇 팔 강화학습의 출발점이다.**
