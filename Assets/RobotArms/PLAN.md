# RobotArms 개발 계획 — 목차

Unity ML-Agents 실습 프로젝트. `RollerBall` 다음 단계로 진행한다.

**최종 목표**
3관절 로봇 팔이 **랜덤한 위치의 물체를 집어서, 다른 위치로 옮겨 놓는 것**을 학습한다.

> **이 프로젝트의 원칙**
> 1. 각 장은 **RollerBall 하나 정도의 분량**이다. 한 번에 다 만들지 않는다.
> 2. 각 장은 그 자체로 **끝까지 동작하는 완성품**이다. 확인하고 다음으로 간다.
> 3. 장마다 **커밋을 나눈다.** `git log`가 곧 실습 진행 순서다.
> 4. 어려운 것은 과감히 뺀다. 목적은 산업용 로봇이 아니라 **ML-Agents 이해**다.

### 1~2장 — 학습 환경 구성

**1~2장은 ML-Agents가 전혀 나오지 않는다.**
이 단계의 목적은 하나다.

> **AI를 붙이기 전에, 사람이 손으로 풀 수 있는 환경을 만들어 두는 것.**

로봇 팔은 관절 길이와 가동 범위를 조금만 잘못 잡아도
**물체에 영원히 닿을 수 없는 환경**이 된다.
그 상태에서 학습을 돌리면, 원인은 환경인데 보상 설계나
하이퍼파라미터를 끝없이 의심하게 된다.

그래서 **키보드로 직접 물체까지 팔을 가져갈 수 있는지 확인**하는 것을
독립된 단계로 두었다. 이것이 1~2장이다.

### 3장 — ML-Agents 도입

2장에서 키보드 입력을 넣던 자리에 AI의 액션을 꽂는다.

```
2장:  Angle += 키보드입력 × maxSpeed × dt
3장:  Angle += AI의액션   × maxSpeed × dt      ← 숫자의 출처만 바뀐다
```

관측 12개 / 연속 액션 3개. 핵심은 **보상 설계(Reward Shaping)** 다.
RollerBall처럼 "도달하면 +1"만 줘서는 팔이 거의 학습되지 않는다는 것을
직접 실패해보고 나서, "가까워진 만큼" 보상을 추가한다.

### 메뉴 도구

Unity 상단 메뉴에 `RobotArms` 가 생긴다. 장 순서대로 누르면 된다.

| 메뉴 | 하는 일 | 장 |
|---|---|---|
| `1. 환경 만들기 (씬 구성)` | 팔·테이블·물체를 배치한다 | 1장 |
| `2. 관절 제어 붙이기` | 관절 설정 + 키보드 조작 + 화면 UI | 2장 |

> 메뉴는 "정답 씬"을 빠르게 만들어 비교해보기 위한 것이다.

## 로봇 팔 구조 — 3 DOF

| 관절 | 이름 | 회전축 | 하는 일 | 가동 범위 | 키 |
|---|---|---|---|---|---|
| 0 | `J0` | **Y축** | 좌우 회전 (몸통) | -120° ~ 120° | `E` / `D` |
| 1 | `J1` | X축 | 어깨 (위아래) | -10° ~ 100° | `Q` / `A` |
| 2 | `J2` | X축 | 팔꿈치 (위아래) | -130° ~ 130° | `W` / `S` |

```
관절 3개  =  3 DOF  =  (3장에서) 연속 액션 3개
```

**이 대응 관계가 로봇 팔 강화학습의 출발점이다.**

## 도달 범위 — 가장 중요한 전제

```
팔이 닿는 최대 거리   = Link1(1.5) + Link2(1.2) = 2.7
팔이 닿는 최소 거리   ≈ 1.17            (팔꿈치를 최대한 접어도 이만큼은 떨어진다)

물체가 나타나는 구역  = 테이블 위 부채꼴
                        거리   1.2 ~ 2.4
                        좌우각 -60° ~ +60°
```

**검증 결과** (정기구학 전수 스캔)

| 항목 | 결과 |
|---|---|
| 거리 1.2 ~ 2.4 전 구간 | 도달 가능, 최대 오차 `0.015` |
| 좌우 각도 ±60° | 관절 범위 ±120° 안에 들어옴 |
| 물체 스폰 위치 | `\|x\|` 최대 2.08 < 테이블 반폭 2.5 → 전부 테이블 안 |

> ### 초보자가 가장 많이 하는 실수
> 닿을 수 없는 위치에 물체를 놓으면 학습은 **절대** 성공하지 않는다.
> 학습이 안 될 때 코드부터 의심하게 되는데, 원인은 보통 여기다.
>
> Scene 뷰에 Gizmo가 그려진다 — **흰 구 = 최대 도달 범위,
> 초록 부채꼴 = 물체가 나타나는 구역.** 눈으로 확인할 것.

## RollerBall과 비교해서 새로 배우는 것

| 주제 | RollerBall | RobotArms | 어느 장에서 |
|---|---|---|---|
| 제어 대상 | 공 하나 | **연결된 관절 3개** | 1~2장 |
| 액션의 의미 | 미는 힘 | **관절 회전 속도** | 2~3장 |
| 환경 검증 | 필요 없었음 | **사람이 먼저 풀어봐야 한다** | 2장 |
| 관측 | 원시값 그대로 | **정규화가 필요** | 3장 |
| 보상 | `+1` 하나 | **진전 보상 (Reward Shaping)** | 3장 |
| 종료 조건 | 도달 / 낙하 | **`MaxStep` 필수** | 3장 |
| 액션 타입 | 연속만 | **연속 + 이산 함께** | 4장 |
| 과제 구조 | 한 단계 | **여러 단계 (가서-집고-옮기고-놓기)** | 6장 |
