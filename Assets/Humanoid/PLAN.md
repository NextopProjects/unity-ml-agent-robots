# Humanoid 개발 계획 — 목차

Unity ML-Agents 실습 프로젝트. `RobotArms` 다음 트랙이다.

> **상태: 검수 전 초안.** 구성 · 문구 · 튜토리얼 단계는 아직 검수 중이며 바뀔 수 있다.
> 코드 동작(테스트 · 조건 검증 · 물리 실측 · 서기/걷기 학습)은 확인했지만, 수업에 쓰기 전 사람이 처음부터 끝까지 따라가 보는 검수가 남아 있다.

**최종 목표**
두 다리 휴머노이드가 **넘어지지 않고 목표를 향해 스스로 걷는 정책**을 학습한다.

> **이 트랙의 원칙** (RobotArms와 같다)
> 1. 각 장은 그 자체로 **끝까지 동작하는 완성품**이다.
> 2. 관측·행동·보상은 장마다 **조금씩만** 바꾼다. 두 가지를 한꺼번에 넣지 않는다.
> 3. 숫자는 추측하지 않는다. 문서의 수치는 전부 **실측값**이다.
> 4. 걷는 데 꼭 필요하지 않은 것은 뺀다. (팔 관절, 머리 관절, 관절 힘 조절)
> 5. **코드는 짧게.** 여러 곳에서 쓰는 것만 함수·변수·상수로 만든다. 한 번 쓰는 값은 그 자리에 적는다.

## 1~2장 — 강화학습 전 환경 구성: 무대와 몸을 직접 만들고 검증한다

학습자는 빈 실습 씬(`Assets/Humanoid/Scenes/Humanoid.unity`)에서 Hierarchy · Inspector 를 직접 만지며
학습 영역 → 바닥 → 카메라 → Humanoid 계층(골반 · 몸통 · 허벅지 + 관절) → 몸 스크립트 → 모터 → 키보드 조작 순서로 쌓는다.
같은 방법의 반복(정강이 · 발 · 오른다리 · 머리)은 버튼으로 처리한다.

키보드로 걸을 수는 없다(관절 12축). 대신 이것을 사람이 먼저 확인한다.

| 확인할 것 | 어떻게 | 실측 |
|---|---|---|
| 관절이 원하는 각도까지 가는가 | `H`로 매달고 12축을 하나씩 | 목표를 따라간다 |
| 가만히 서 있을 수 있는가 | 차렷으로 둔다 | 6초 이상 버팀 |
| 자세를 바꿔도 버티는가 | `2` 무릎 굽히기 (2초에 걸쳐) | 버팀, 각도 오차 2.5° |
| **살짝 밀면 버티는가** | `P` 몸통 20 N·s | **넘어짐 → 3장에서 AI가 배울 것** |

### 유니티 패키지로 내보내기

`Assets/Humanoid` 에서 **정해 둔 것만** `.unitypackage` 하나로 내보낸다 (폴더를 통째로 담지 않는다).

| 담는 것 | 빼는 것 |
|---|---|
| `Docs` · `Editor` · `Materials` · `Scenes`(빈 실습 씬 + 정답 씬) · `Scripts` 폴더, `humanoid_config.yaml` · `PLAN.md` | 그 밖의 모든 것 (`results/` 학습 결과 등) · 담는 폴더 안의 학습 결과 파일 `.onnx` · `.pt` · `.nn` · `.json` |

미리 학습해 둔 모델은 `Assets/Humanoid/results/HumanoidStand.onnx`(서기, 400만 스텝) · `HumanoidWalk.onnx`(걷기, 1000만 스텝)에 있다. 패키지에는 담지 않는다.

뺀 것은 내보낼 때 콘솔에 개수와 폴더 이름으로 나온다 (실측: 35개 담음, `results` 28개 뺌).
새 폴더를 패키지에 넣으려면 `HumanoidPackageExporter.Folders` 에 이름을 더한다.
`IncludeDependencies` 는 쓰지 않는다 — 켜면 URP 설정 같은 프로젝트 에셋까지 딸려 들어간다.

| 가져갈 프로젝트에 필요한 것 | |
|---|---|
| Unity 6000.3 이상 | |
| `com.unity.ml-agents` 4.x | 에이전트 · Behavior Parameters |
| `com.unity.inputsystem` | 키보드 조작 (`Keyboard.current`) |
| URP (선택) | 없으면 머티리얼이 Standard 셰이더로 만들어진다 |
| Python ml-agents | 학습(`mlagents-learn`)할 때만 |

자동화에서는 `HumanoidEditor.HumanoidPackageExporter.Export(경로)` (대화상자 없음)를 부른다.
| `Humanoid > 개발자 > 튜토리얼 점검 · 튜토리얼 화면 시험 · 대신 해주기로 끝까지 (조건 검증) · 전체 채점 · 모든 실습 시작 코드로 · 모든 정답 되돌리기` | - |

### 직접 구현 실습 — 강화학습 환경 코드

실습 대상은 **수학 계산이 아니라 Unity 로 학습 환경을 만드는 코드**다 — 몸(`BodyPart` · `HumanoidBody`)과 에이전트(`StandAgent` · `WalkAgent`)의 메서드.
회전 · 보상 공식 같은 수학은 `HumanoidMath.cs` 에 완성본으로 주고 불러 쓰기만 한다. 빈칸 코드는 힌트 4단계에서만 나오는 보조 수단이다.

| 장 | 실습 | 대상 | 형태 | 핵심 개념 | 요구사항 · 케이스 |
|---|---|---|---|---|---|
| 1 | 1-1 | `BodyPart.ResetPose` | 처음부터 | 처음 상태로 되돌리기 (위치 · 회전 · 속도) | 4 · 4 |
| 1 | 1-2 | `HumanoidBody.HasFallen` | 처음부터 | 판 끝 조건 (발 아닌 부품이 바닥에) | 3 · 5 |
| 2 | 2-1 | `BodyPart.SetTarget` | 처음부터 | 관절 모터 targetRotation | 3 · 4 |
| 2 | 2-2 | `HumanoidBody.SetActions` | 일부 코드 제공 | 행동 18개 → 관절 (X · Z 함께) | 4 · 5 |
| 3 | 3-1 | `StandAgent.OnEpisodeBegin` | 처음부터 | 판 시작 초기화 | 4 · 4 |
| 3 | 3-2 | `StandAgent.CollectObservations` | 처음부터 | 관측 48개 | 5 · 5 |
| 3 | 3-3 | `StandAgent.OnActionReceived` | 일부 코드 제공 | 행동 · 보상 · EndEpisode | 4 · 4 |
| 4 | 4-1 | `WalkAgent.CollectObservations` | 기능 추가 | 상속 + 관측 +3 | 4 · 5 |
| 4 | 4-2 | `WalkAgent.StepReward` | 일부 코드 제공 | 목표 도달 보상 · 새 목표 | 4 · 6 |
| 4 | 4-3 | `WalkAgent.OnActionReceived` | 기능 추가 | 제한시간 판 끝 | 3 · 3 |
| 5 | 5-1 | `WalkAgent.RecordStats` | 처음부터 | StatsRecorder 지표 | 2 · 5 |
| 5 | 5-2 | `WalkAgent.ReadCurriculum` | 처음부터 | 커리큘럼 파라미터 | 2 · 3 |

학습 흐름 (튜토리얼 창의 코드 단계):

```
[구현 시작] → 직접 작성 → [▶ 테스트 실행] → 요구사항별 ✔/✘ · 실패한 상황 · 원인 · 수정 방향
                         ↘ 막히면 💡 힌트 1 방향 → 2 구조·순서 → 3 핵심 로직 → 4 빈칸 코드 → 5 완성 코드·해설
```

- 시작 코드 · 힌트 · 해설 · **정답**은 `TutorialChapters.cs` 의 실습 단계에 데이터로 있다 (`start` · `mode` · `hints` · `skeleton` · `explain` · `answer`).
  정답을 데이터에 두는 이유: 파일 · `Library/` 상태와 상관없이 힌트 5단계가 항상 보이게. (`튜토리얼 점검`이 데이터의 정답과 스크립트가 같은지 확인한다)
- 실습 자리는 표시 주석 없이 이름으로 찾는다 (`BlankTool.Member`: id → 파일 · 메서드).
- 테스트(`BlankCheck.cs`)는 임시 씬에 몸(과 에이전트)을 만들어 메서드를 실제로 부르고, 끝나면 지운다 — 학습자 씬은 건드리지 않는다.
  에이전트 실습은 ML-Agents 를 초기화하고(`LazyInitialize`) 끝나면 `Academy.Dispose`. 물리는 돌리지 않고 속도 · 접촉은 값을 넣어 만든다.
- **저장소에는 정답이 든 채로 둔다.** 1장 첫 단계 [실습 씬 열기]가 아직 시작 안 한 실습을 전부 시작 코드로 바꾼다 (앞 실습의 답이 미리 보이지 않게).
- 진행 상태(EditorPrefs)는 프로젝트마다 따로 저장한다 (`Humanoid.Tutorial.<프로젝트 id>.…`).

검증(개발자): `개발자 > 모든 실습 시작 코드로` → `전체 채점`이면 **모든 실습이 하나 이상 실패**하고 (실측 41 / 53 실패),
`모든 정답 되돌리기` → `전체 채점`이면 **전부 통과**하고 스크립트가 원래와 같아진다 (53 / 53). 실습을 추가 · 수정하면 둘 다 다시 확인한다.
