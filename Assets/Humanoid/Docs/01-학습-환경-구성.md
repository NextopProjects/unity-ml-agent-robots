# 1장 — 학습 환경 구성

> 강화학습을 시작하기 전에 **AI가 배울 무대와 몸**을 직접 만든다.
> 빈 씬에서 학습 영역 → 바닥 → 카메라 → 휴머노이드의 부품과 관절을 하나씩 쌓는다.
> 아직 근육(모터)은 없다. 마지막에 Play하면 실 끊긴 인형처럼 무너진다. **이 장에서는 그게 정상이다.**
>
> 실습은 **튜토리얼 창**(`Humanoid > 튜토리얼 열기`, Ctrl+Shift+H)을 따라 한다. 이 문서는 그 설명을 자세히 푼 참고서다.

---

## 학습 목표

- 학습 영역(HumanoidArea)과 바닥을 만들고, 왜 그렇게 두는지 설명할 수 있다
- 부품마다 Rigidbody + Collider를 주고 **관절(Configurable Joint)로 잇는** 계층을 직접 쌓을 수 있다
- 관절의 Anchor · Motion · Limit 가 각각 무엇을 정하는지 말할 수 있다
- 무게중심을 계산할 수 있다 → **빈칸 1-1**

## 튜토리얼 창 읽는 법

```
┌ 1.학습 환경 │ 2.기초 움직임 │ 3.서기 │ 4.걷기 │ 5.학습 ─────── 📖 문서 ┐  ← 장 고르기 (끝낸 장은 ✔)
│ ✔ 시작하기          │ 단계 6 / 13 · 골반 — 첫 번째 부품                 │
│ ✔ 학습 영역 만들기   │ 🎯 물리로 움직이는 부품 하나를 만든다              │  ← 목표 (언제나 보인다)
│ ✔ 바닥 만들기        │ (설명)                                         │
│ ▶ 골반              │ ✔ Humanoid 아래에 빈 오브젝트 Pelvis              │  ← 끝낸 일은 저절로 ✔
│ ○ 몸통              │ ▶ Position (0, 0.96, 0)                         │  ← 지금 할 일 (파란 칸)
│                     │   📍 Inspector ▸ Pelvis ▸ Transform ▸ Position  │  ← 어디서 하는지 + [📍 여기 보기]
│ …                   │   Add Component > Box Collider …                │
│ 이 장의 목표         │ 💡 힌트 · 막혔을 때 [대신 해주기]                  │
│ • …                 │ [◀ 이전 단계]          [다음 단계 ▶]              │  ← 할 일을 다 하면 켜진다
└─────────────────────┴─────────────────────────────────────────────────┘
```

- 할 일은 **위에서부터 하나씩** 확인한다. Hierarchy · Inspector 에서 값을 바꾸면 창이 알아서 ✔ 를 붙인다.
- **어디를 고쳐야 하는지 화면에 표시된다.**
  - 지금 할 일 아래 **📍 위치** (예: `Inspector ▸ Pelvis ▸ Box Collider ▸ Size`)
  - 대상 오브젝트가 **Hierarchy 에서 노란 줄 + "◀ 여기"**, **Scene 뷰에서 노란 상자**로 보인다
  - 코드 단계에서는 Project 창의 `HumanoidMath.cs` 가 노랗게 표시된다
  - **[📍 여기 보기]** 를 누르면 그 오브젝트를 선택하고 창을 앞으로 가져오며, Inspector 에서는 고칠 컴포넌트만 펼쳐 준다
- 확인할 수 없는 일(눈으로 보기, 문서 읽기)은 **[했어요]** 로 넘긴다.
- 막히면 **💡 힌트** → 그래도 안 되면 **막혔을 때 > [대신 해주기]** (Ctrl+Z 로 되돌릴 수 있다).
- 진행은 자동 저장된다. 처음부터: `Humanoid > 튜토리얼 진행 초기화`.
- 실습 씬은 `Assets/Humanoid/Practice/Practice.unity` 에 만들어진다 (버전 관리 밖). 완성된 정답 씬은 `Scenes/Humanoid.unity`.

## 핵심 개념 ① — 학습 영역 하나에 전부 담는다

바닥 · 몸 · 목표(4장)를 전부 `HumanoidArea` 아래에 둔다.
5장에서 이것 하나를 복제하면 학습 환경이 통째로 9개가 된다(병렬 학습). 코드와 메뉴가 이 이름으로 찾으므로 철자를 정확히 쓴다.

바닥은 Cube 를 y = -0.5 에 두어 **윗면이 y = 0** 이 되게 한다. 바닥에는 Rigidbody 를 붙이지 않는다.
몸의 부품(`BodyPart`)은 **"Rigidbody 가 없는 것에 닿았다 = 바닥에 닿았다"** 로 판단한다. 태그를 따로 쓰지 않는다.

## 핵심 개념 ② — 부품 = 스케일 1인 본체 + 보이는 모양

```
Pelvis (스케일 1)  ← Rigidbody(무게·중력), Box Collider(Size로 크기), Body Part
└── PelvisMesh     ← 보이는 상자 (콜라이더 크기에 맞춰 버튼이 붙인다)
```

본체에 스케일을 주면 자식으로 달린 다음 부품까지 찌그러진다. 크기는 **Box Collider 의 Size** 로 정한다.
자식의 Position 은 **부모 기준(로컬)** 이다. 몸통 가운데는 세상에서 y = 1.25, 골반이 0.96 이라 로컬 0.29.

위가 무겁다(몸통 14kg). 사람도 그렇다. 그래서 서 있는 것 자체가 "거꾸로 세운 막대"를 버티는 일이다.

## 핵심 개념 ③ — 관절은 "어디서, 어느 방향으로, 얼마나"

| 설정 | 뜻 |
|---|---|
| Connected Body | 누구와 잇나 (부모 부품) |
| Anchor | 관절 점. **자기 기준 로컬 좌표** (몸통이면 아래 끝 (0,-0.21,0)) |
| X / Y / Z Motion | 이동. 전부 Locked — 빠지지 않고 돌기만 |
| Angular X / Y / Z | X = 앞뒤 굽히기, Y = 비틀기(Locked), Z = 좌우 |
| Low · High Angular X, Angular Z Limit | 범위 (도) |

**관절 공간의 부호** — 다리에서 X+ 는 "다리를 앞으로", 몸통에서는 "뒤로", 발목에서는 "발끝을 위로"다.
그래서 허리 Low -40(앞) · High 20(뒤), 엉덩이 Low -30(뒤) · High 90(앞).

모든 부품이 회전 없이(정면 +Z) 서 있게 만들었다. 그래서 **관절 각도 0 = 차렷 자세**. 2장에서 그대로 쓴다.

## 핵심 개념 ④ — 무게중심

몸 전체를 점 하나로 봤을 때의 위치. 무거운 부품일수록 그쪽으로 끌려간다.

```
COM = (m1·p1 + m2·p2 + ...) / (m1 + m2 + ...)
```

서 있을 수 있느냐는 결국 무게중심이 발 위에 있느냐로 갈린다.
빈칸 1-1 을 통과한 뒤 Play 하면 Scene 뷰에 노란 점(무게중심)과 바닥으로 내린 선이 그려진다.
4장에서는 같은 식을 **속도**에 써서 "몸 전체가 얼마나 빨리 가나"를 잰다.

## 빈칸 1-1 — 무게중심 `CenterOfMass`

**하는 일** — 부품 위치 배열과 질량 배열을 받아 무게중심을 돌려준다. 질량 합이 0이면 `(0,0,0)`.

```csharp
Vector3 sum = Vector3.zero;
float totalMass = 0f;
for (int i = 0; i < positions.Length; i++)
{
    sum += ___;
    totalMass += ___;
}
return ___;     // 질량 합이 0이면 0으로 나누지 않도록
```

| 케이스 | 기대값 | 걸러내는 오답 |
|---|---|---|
| 같은 무게 둘 (0,0,0)·(2,0,0) | (1,0,0) | |
| 3kg 위 (0,2,0) · 1kg 아래 (0,0,0) | (0,1.5,0) | 질량을 무시한 평균 → (0,1,0) |
| 부품 하나 **(경계)** | 그 자리 | |
| 부품 없음 **(경계)** | (0,0,0) | 0으로 나눠 NaN |

## 자주 밟는 함정

| 증상 | 원인 |
|---|---|
| 몸이 찌그러져 보인다 | 본체(`Humanoid` 나 부품)에 스케일을 줬다. 크기는 `Box Collider.size` 로 |
| 부품이 Play 하자마자 튀어 날아간다 | Anchor 가 엉뚱하다. Anchor 는 **자기 기준** 좌표다 (몸통 (0,-0.21,0)) |
| 다리가 빠져 따로 떨어진다 | X · Y · Z Motion 을 Locked 로 하지 않았다 |
| 무릎이 앞으로 꺾인다 | 무릎 범위가 -120 ~ 0 이 아니다 |
| 조건이 ✔ 가 안 된다 | 이름 철자(대소문자)와 부모가 맞는지, 값이 정확한지 본다 (소수점 둘째 자리까지) |
| 서 있게 해도(2장) 2초 만에 넘어진다 | **`Rigidbody.solverIterations`는 씬에 저장되지 않는다.** 에디터에서 넣어도 기본값 6으로 돌아간다. 그래서 `BodyPart`가 실행할 때 30을 넣는다 (실측: 6이면 2초에 넘어지고 30이면 버틴다) |
| 무릎만 굽혀도 발목이 꺾여 넘어진다 | **발이 너무 가볍다.** 1kg 발이 44kg 몸을 떠받치면 물리 엔진이 관절을 다 못 푼다. 3kg으로 올리자 발목 오차 29° → 2° |
| 무릎 각도가 162° 같은 엉뚱한 값 | 오일러각(`eulerAngles`)으로 읽었다. 90° 근처에서 뒤집힌다. `BodyPart.Angles`처럼 방향 벡터로 계산한다 |

> 발 질량 이야기는 RobotArms 5장의 "손가락 0.05kg → 0.6kg"과 같은 종류다.
> **마찰이나 힘을 의심하기 전에 무게(질량 비율)를 의심한다.**

## 이 장에서 배우는 것

1. **학습 영역 하나에 전부 담는다.** 나중에 통째로 복제할 수 있다.
2. **부품마다 Rigidbody, 관절로 잇는다.** 위치는 우리가 아니라 물리가 정한다.
3. **관절의 Anchor · Motion · Limit** 가 몸을 사람답게 만든다. 관절 각도 0 = 차렷 자세.
4. **무게중심 = 질량 가중 평균.** 서 있을 수 있느냐는 이 점의 위치로 갈린다.
5. **저장되지 않는 설정, 질량 비율** — 물리는 숫자 몇 개로 갑자기 무너진다.
