# 6장 — 집어서 옮기기

> 5장까지 휴머노이드는 걷기만 했다. 이 장은 **걸어가서 작업대 위 상자를 양팔로 집어 들고, 무작위로 고른 다른 작업대에 내려놓는다.**
> RobotArms 4~5장(집어서 옮겨 놓기 · 집게)의 구조를 휴머노이드에 옮긴다: 단계마다 "지금 가야 할 점"이 바뀌고, 성공은 "정말 놓였는가"로 판정한다.
> 몸은 그대로다 (행동 18). 관측은 상자 · 놓을 자리 17개가 늘어 65.

>
> 실습은 **튜토리얼 창**(`Humanoid > 튜토리얼 열기`)을 따라 한다. 이 문서는 그 설명을 자세히 푼 참고서다.

---

## 학습 목표

- 몸으로 할 수 있는 일인지 **학습 전에 실측**한다 (팔이 닿는 높이 · 마찰로 들 수 있는 무게)
- 물리로 잡는다: 상자를 붙이거나 옮기는 코드 없이, 양팔이 조여 생긴 마찰로만 든다 → **실습 6-1**
- "목표에 닿음"이 아니라 **"정말 놓였는가"**로 성공을 판정한다 → **실습 6-2**
- 보상 크기가 아니라 **성공률로 난이도를 올린다** → **실습 6-3**
- 학습이 엉뚱한 쪽으로 갈 때 지표로 원인을 찾아 보상을 고친다 (이 장을 만들며 네 번 고쳤다)

---

## 단계별로 하는 일

| 단계 | 하는 일 |
|---|---|
| 1 작업대 두 개 | PickTable(직접) · PlaceTable + PlaceMarker(버튼). **Kinematic Rigidbody** |
| 2 상자 | Box 0.30 × 0.20 × 0.20 · 1kg · Rigidbody · Carry Box |
| 3 실습 6-1 | 어느 팔이 닿았나 (`CarryBox.Touch`) · 처음부터 |
| 4 에이전트 바꾸기 | Gait Agent → **Carry Agent** · 연결 · Max Step 3000 · HumanoidCarry · 관측 65 · Target 지우기 |
| 5 실습 6-2 | 정말 놓였나 (`CarryAgent.Placed`) · 처음부터 |
| 6 실습 6-3 | 성공률로 난이도 올리기 (`CarryAgent.LevelUp`) · 처음부터 |
| 7 병렬 학습 | 영역 9개로 복제 (작업대 · 상자도 같이) |
| 8 학습하기 | `humanoid_carry_config.yaml` → 빌드 → 학습 → TensorBoard `Carry/…` |
| 9 평가 | 영역 1개로 → `Humanoid > 집어서 옮기기 평가` (20판) |

메뉴 `Humanoid > 6. 집어서 옮기기 환경 만들기` 가 1~4단계를 한 번에 만든다 (정답 씬 확인용).

## 핵심 개념 ① — 학습 전에 몸으로 되는지 잰다

**사람이 키보드로 못 하면 AI 도 못 한다** (작업 원칙 3). 팔에 손이 없는 몸으로 무엇을 집을 수 있는지 먼저 쟀다.

| 시험 (받침대 위 상자, 몸 정면 0.38m) | 결과 |
|---|---|
| 서서 팔 끝이 내려가는 높이 | 약 0.9m — **바닥의 물체는 쪼그려 앉아야 닿는다** → 물체 · 놓을 자리를 높이 1.06 작업대 위에 |
| 팔을 앞으로(어깨 30° · 팔꿈치 60°) 뻗은 높이 | 아래팔이 약 1.16m 에서 수평 → 작업대 윗면 1.06 + 상자 절반 0.10 |
| 양팔을 안쪽으로 15~25° 조이고 받침대를 치움 | 너비 0.26~0.34 · 1~2kg 버팀 (처짐 0~3cm) |
| 조이지 않고 받침대를 치움 (대조) | **떨어진다** — 붙잡는 힘은 마찰뿐이다 |
| 조인 채 어깨를 60° 로 | 상자가 13cm 올라간다 · 넘어지지 않는다 |

그래서 상자는 0.30 × 0.20 × 0.20 · 1kg, 잡기 = **두 아래팔이 모두 상자에 닿음**.

## 핵심 개념 ② — 물리로 잡는다

상자를 손에 붙이는 코드(FixedJoint · 위치 옮기기)는 없다. 4장 RobotArms 의 자석과 다르다.

```
CarryBox.Touch(이름, 닿음)   OnCollisionStay / Exit 가 부른다 — 왼 · 오른 아래팔만 센다 (실습 6-1)
Grasped = touchL && touchR   잡았다 = 양쪽에서 조이고 있다
```

위팔 · 몸통으로 끼운 것까지 세면, 상자를 가슴에 대고 밀기만 해도 "잡음"이 된다.

> **작업대에 Kinematic Rigidbody 를 단다.** BodyPart 는 Rigidbody 가 없는 것을 바닥으로 본다(1장).
> 그대로 두면 팔이 작업대에 스치기만 해도 "넘어짐"으로 판이 끝난다.

## 핵심 개념 ③ — 단계와 보상

RobotArms 5장처럼 단계마다 가야 할 점이 바뀐다.

| 단계 | 가야 할 점 (거리) | 보상 |
|---|---|---|
| ① 접근 | 왼 · 오른 아래팔 → 상자 왼 · 오른 옆면 자리 (가운데에서 0.19, 가까운 짝) | 최고 기록 갱신만큼 |
| ② 잡기 · 들기 | 상자 → 작업대보다 8cm 위 | 갱신만큼 × 5 · 잡기 0.3초 **+1** · 들기 0.5초 **+1** (판에 한 번) |
| ③ 옮기기 | 상자 → 놓을 자리 위 (가까울수록 낮게) | 갱신만큼 × 3 · 놓을 자리 작업대 위에 멈춰 놓으면 **+1** (쥐고 있어도, 판에 한 번) |
| ④ 놓기 | 정말 놓였나 (실습 6-2) | **+3**, 판 끝 |
| 실패 | 상자가 바닥에 (높이 < 0.5) · 넘어짐 | **−1**, 판 끝 |
| 서 있기 | 매 스텝 0.0003 × 서 있는 정도 | 판 전체 0.9 이하 |

다가간 보상은 한 스텝 0.05 상한, 몸통 자세 · 행동 떨림만큼 깎는다 (5장과 같은 생각).

## 핵심 개념 ④ — 정말 놓였는가

```
자리 안     수평 거리 < 0.15
작업대 위   높이 차 < 0.03          ← 없으면: 들고 자리 위에 서 있기만 해도 성공
멈춤       속도 < 0.1              ← 없으면: 던져서 굴러가며 지나가도 성공
팔 뗌      양팔 다 안 닿음           ← 없으면: 꼭 쥔 채 작업대에 대기만 해도 성공
→ 네 가지가 25스텝(0.5초) 이어져야 성공 (실습 6-2)
```

## 핵심 개념 ⑤ — 성공률로 난이도를 올린다

| 난이도 | 상자까지 | 방향 | 놓을 작업대까지 |
|---|---|---|---|
| 0 | 0.45m (걷지 않고 닿는다) | 정면 | 0.4m (바로 옆 ±90° 만) |
| 1 | 0.45m | 정면 | 0.8m (바로 옆 ±90° 만) |
| 2 | 0.8m | ±15° | 0.8m |
| 3 | 1.2m | ±30° | 1.2m |
| 4 | 2.0m | ±90° | 2.0m |
| 5 | 3.5m | 사방 | 3.0m |

놓을 작업대는 상자 작업대 둘레 후보 6곳(몸 쪽에서 본 ±60° · ±90° · ±120°) 중 하나다.
에이전트마다 **최근 20판 중 14판 이상 성공**하면 한 단계 올린다 (실습 6-3). TensorBoard `Carry/Level` 이 평균 난이도.

## 학습이 엉뚱한 쪽으로 간 기록 — 지표로 원인을 찾는다

이 장의 보상은 처음부터 이렇지 않았다. 학습 → 지표 → 원인 → 수정을 네 번 했다 (모두 500만 스텝 안에서 판단).

| 학습 | 지표 | 원인 | 고친 것 |
|---|---|---|---|
| 1 | 넘어짐 100% · 판 1초 · 잡기 47% · 들기 33% | 넘어져도 벌점 없음 · 서 있어도 보상 없음 → **1초 만에 몸을 던져 잡고 들기(+2) 후 넘어짐** | 넘어짐 −1 · 서기 보상 · 들기는 0.5초 유지해야 |
| 2 | 잡기 99% · 떨어뜨림 96% · 들기 0% · **성공 0 인데 난이도 2** | ① yaml 커리큘럼이 보상 기준이라 성공 없이 단계가 오름 ② 단계가 바뀔 때마다 거리 기준을 새로 잡아 잡았다 놓기로 보상이 쌓임 ③ 들기 거리 8cm → 보상 0.1 | 성공률 난이도(6-3) · 최고 기록 갱신 보상 · 들기 ×5 · 떨어뜨림 −2 |
| 3 | 넘어짐 5% · 판 길이 상한 근처 · **잡기 0~2%** | 서기 보상(판당 1.5)만 챙기고 상자는 피함(떨어뜨림 −2 가 무서움) · 접근 거리가 "손 가운데 → 상자 가운데"라 옆을 감쌀 이유가 없음 | 접근 = 아래팔 → 상자 옆면 · 떨어뜨림 −1 · 잡기 0.3초 유지 · 서기 0.0003 |
| 4 | 잡기 100% · 들기 99% · 떨어뜨림 95% → 33% · 넘어짐 0 (1000만) · **성공은 거의 0** — 들고 서 있다 시간 초과 | 옮기기 0.8m 를 옆걸음으로 가야 하는데 보상은 0.8 뿐(떨어뜨림 −1 보다 작다) · 내려놓고 팔 떼기에 차이가 없다 | 난이도 0 의 놓을 자리 0.8 → 0.5m · 옮기기 ×3 · 내려놓기 +1 · **4번 학습 신경망에서 이어서**(--initialize-from) |
| 5 | 300만 스텝(4번에서 이어서): 잡기 99% · 들기 97% · 내려놓기 0% · 성공 0 — 직접 돌려 보니 상자를 든 채 작업대 위에 서 있기만 함 | **놓을 자리가 골반 바로 옆 0.43m** — 후보 ±60° 가 거리가 짧아지자 몸 옆이 됐다. 비틀기 축 없는 몸은 들고 돌아서야만 놓을 수 있다 | 난이도 0 은 상자 작업대 바로 옆(±90°) 0.4m 만 · 5번에서 이어서 |
| 6 | **처음으로 성공** — 난이도 0 에서 성공 5% → 33% · 내려놓기 39% · 배치 오차 6~7cm (185만). 그런데 난이도가 1(상자 1.0m · 놓을 자리 1.2m)로 오르자 성공 9% · 잡기 30% · 넘어짐 17% 로 무너짐 | 난이도 0 → 1 의 폭이 너무 크다: 상자까지 걸어가기와 멀리 옮기기가 한꺼번에 늘었다 (한 번에 하나씩 원칙) | 난이도를 6 단계로 잘게 · 6번에서 이어서 |

> **보상은 "하면 좋은 것"이 아니라 "하게 될 것"을 정한다.** 매번 AI 는 우리가 준 점수에서 가장 쉬운 길을 찾았다.
> 성공률 · 잡기 · 떨어뜨림 · 넘어짐을 따로 남겼기 때문에(5장의 교훈) 무엇이 문제인지 바로 보였다.

## 실습 6-1 — 어느 팔이 닿았나 `CarryBox.Touch(part, down)`

**형태** — 처음부터

| 요구사항 | 테스트 상황 → 기대 |
|---|---|
| 왼 아래팔이 닿으면 touchL | ForearmL 닿음 → touchL 예 |
| 오른 아래팔이 닿으면 touchR | ForearmR 닿음 → touchR 예 · 양쪽 다 → Grasped 예 |
| 떨어지면 지운다 | 닿았다 떨어짐 → 아니오 |
| 아래팔이 아니면 세지 않는다 | UpperArmL · Torso **(경계)** → 잡음 아니오 |

## 실습 6-2 — 정말 놓였나 `CarryAgent.Placed()`

**형태** — 처음부터

| 요구사항 | 테스트 상황 → 기대 |
|---|---|
| 놓을 자리 위에 0.5초 멈춰 있으면 성공 | 25스텝 → 성공 · 24스텝 **(경계)** → 아직 |
| 놓을 자리 15cm 안 | 0.2m 옆 → 실패 |
| 작업대 위 | 공중 0.1m → 실패 |
| 멈춰 있어야 | 0.5 m/s 로 미끄러짐 → 실패 |
| 팔을 떼야 | 팔이 닿아 있음 → 실패 |

## 실습 6-3 — 성공률로 난이도 올리기 `CarryAgent.LevelUp(success)`

**형태** — 처음부터

| 요구사항 | 테스트 상황 → 기대 |
|---|---|
| 최근 20판 중 14판 성공이면 올린다 | 14 · 6 → 1 · 13 · 7 **(경계)** → 0 |
| 20판이 쌓이기 전에는 올리지 않는다 | 15판 모두 성공 → 0 |
| 올린 뒤에는 기록을 비운다 | 올린 뒤 19판 더 성공 → 1 그대로 |
| 끄거나 마지막 단계면 그대로 | autoLevel 끔 → 0 · 난이도 5 **(경계)** → 5 |

> 막히면 튜토리얼 창의 **💡 힌트**를 한 단계씩 연다.

## 실행 및 검증

```
mlagents-learn Assets/Humanoid/humanoid_carry_config.yaml --run-id=carry --env=<빌드>.exe --no-graphics --num-envs=3
```

**실측** — 학습 진행 중. 결과(난이도별 성공률 · 잡기 · 배치 오차 · 떨어뜨림 · 넘어짐)가 나오면 채운다.

**확인 체크리스트**

- [ ] 실습 6-1 ~ 6-3 테스트 통과
- [ ] Play 해서 상자 색(주황 → 노랑 → 초록)과 놓을 자리 색(지난 판 결과)이 바뀌는 것을 본다
- [ ] TensorBoard 에서 Carry/Grasped → Lifted → Success 가 차례로 오르고 Carry/Level 이 오른다
- [ ] 평가 메뉴로 난이도별 성공률을 적었다
- [ ] 저장소의 씬은 영역 1개 상태로 되돌렸다

## 자주 밟는 함정

| 증상 | 원인 |
|---|---|
| 팔이 작업대에 스치기만 해도 판이 끝난다 | 작업대에 Rigidbody 가 없다 → BodyPart 가 바닥으로 본다. Kinematic Rigidbody 를 단다 |
| 1초 만에 몸을 던져 잡고 넘어진다 | 넘어짐 벌점 · 서기 보상이 없다. 들기 보상을 유지 시간 조건 없이 준다 |
| 성공은 0 인데 난이도가 오른다 | 보상 기준 커리큘럼. 성공률로 올린다 |
| 잡았다 놓기만 반복한다 | 단계마다 거리 기준을 새로 잡는 진전 보상. 최고 기록 갱신 때만 준다 |
| 상자를 아예 안 건드린다 | 서기 보상이 너무 크거나 떨어뜨림 벌점이 너무 크다. 접근 거리가 옆을 감싸는 방향을 알려 주는가 |
| 잡기는 되는데 들기 0% | 들기 단계 거리가 짧아 보상이 거의 없다 (LiftWeight) |
| 상자를 들고 자리 위에 서 있는데 성공이 아니다 | 정상. 내려놓고 팔을 떼야 성공이다 |
| 모델을 넣었더니 Unity 가 꺼진다 | 관측 65 · 행동 18 이 아닌 모델 (5장 모델은 51) |

## 이 장에서 배우는 것

1. **몸으로 되는지 먼저 잰다.** 닿는 높이 · 마찰로 드는 무게를 실측하고 환경을 맞춘다.
2. **물리로 잡는다.** 접촉을 읽기만 하고, 잡을지는 AI 의 팔이 정한다.
3. **성공은 "정말 그렇게 됐는가"로.** 자리 · 높이 · 멈춤 · 손 뗌을 모두 본다.
4. **난이도는 진짜 목표(성공률)로 올린다.**
5. **보상은 가장 쉬운 길을 만든다.** 지표를 따로 남기고, 이상하면 원인을 찾아 고친다.
