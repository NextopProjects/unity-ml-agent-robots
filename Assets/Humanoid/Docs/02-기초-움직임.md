# 2장 — 기초 움직임

> 1장의 몸에 **근육**을 단다. 그리고 AI를 붙이기 전에 **사람이 먼저** 몸을 움직여 본다.
> 키보드로 걸을 수는 없다(관절 축이 18개다). 대신 **이 몸으로 걷는 것이 가능한지**를 확인한다.
> 1장과 이 장까지가 **강화학습 전의 환경 구성**이다.
>
> 실습은 **튜토리얼 창**(`Humanoid > 튜토리얼 열기`)을 따라 한다. 이 문서는 그 설명을 자세히 푼 참고서다.

---

## 학습 목표

- 관절 모터(스프링·댐퍼)가 "목표 각도로 당기는 힘"이라는 것을 설명할 수 있다
- 목표 각도를 관절 모터에 넣고, 행동 18개를 관절마다 보내는 코드를 쓸 수 있다 → **실습 2-1, 2-2**
- "관절을 단단하게 하는 것 ≠ 균형을 잡는 것"을 실험으로 보여줄 수 있다

---

## 단계별로 하는 일

| 단계 | 하는 일 | 값 |
|---|---|---|
| 1 모터 켜기 | `Humanoid` 의 Humanoid Body | Spring **4000** · Damper **400** (1장에서는 0) |
| 2 실습 2-1 | 관절 모터에 목표 넣기 (`BodyPart.SetTarget`) | 처음부터 구현 |
| 3 실습 2-2 | 행동 18개를 관절로 (`HumanoidBody.SetActions`) | 일부 코드 제공 |
| 4 키보드 조작 | `Humanoid` 에 Add Component > Keyboard Control | 키보드 → 행동 18개 → 몸 · 화면에 각도 표시 |
| 5 손으로 돌려 보기 | Play → `H` 매달기 → `←→↑↓` → `H` 내리고 `2` | 저절로 확인 |
| 6 밀어서 넘어뜨리기 | `1` 차렷 → `P` 밀기 → `R` 다시 세우기 | |

실습 2-1 · 2-2 를 키보드보다 먼저 구현한다. 키보드가 만든 숫자를 관절로 보내는 것이 바로 `SetActions` 라서,
아직 비어 있으면 어떤 키를 눌러도 관절이 움직이지 않는다.

| 키 | 동작 |
|---|---|
| `←` `→` | 관절 축 고르기 (18개) |
| `↑` `↓` | 고른 축의 목표 각도 바꾸기 |
| `1` | 차렷 (2초에 걸쳐) |
| `2` | 무릎 굽히기 (2초에 걸쳐) |
| `H` | 공중에 매달기 / 내리기 — 넘어지지 않게 하고 관절만 본다 |
| `P` | 몸통을 앞으로 밀기 (20 N·s) |
| `R` | 처음 자세로 |

## 핵심 개념 ① — 관절 모터 = 목표 각도로 당기는 스프링

```
힘 = spring × (목표 각도 − 지금 각도) − damper × (지금 회전 속도)
```

- **spring** — 클수록 목표로 세게 당긴다. 너무 약하면 목표까지 못 간다.
- **damper** — 흔들림을 잡는다. 없으면 목표를 지나쳤다 돌아왔다 출렁인다. 보통 spring의 1/10.

이것을 **PD 제어**라고 한다(P = 비례, D = 미분). 로봇 관절 모터가 대부분 이렇게 동작한다.
**AI가 정하는 것은 힘이 아니라 목표 각도뿐이다.** 힘은 이 스프링이 알아서 낸다.

> ★ Unity의 함정 — `targetRotation`에 +30을 넣으면 실제 관절은 **-30**만큼 돈다. (실측)
> 다행히 가동 범위(limit)도 같은 공간이라, 범위 안의 값을 그대로 넣으면 맞게 돈다.
> 각도를 **읽을 때**만 부호를 뒤집어 같은 공간으로 맞춘다 (`BodyPart.Angles`).

## 핵심 개념 ② — 행동 0 = 차렷 자세

행동(-1~1)을 각도로 바꾸는 가장 흔한 방법은 범위의 가운데를 0으로 두는 것이다.
그러면 무릎(-120~0)의 행동 0은 -60도, 즉 **반쯤 주저앉은 자세**가 된다.
학습 초반의 AI는 0 근처 숫자를 내므로, 늘 주저앉은 자세에서 시작하게 된다.

여기서는 **0 = 0도(차렷)** 로 두고 양쪽을 따로 늘린다(`HumanoidMath.ActionToAngle` — 주어진 함수).
그러면 학습이 **서 있는 자세**에서 시작해 서기(3장)를 배우기가 훨씬 쉽다.

## 핵심 개념 ③ — 행동 18개의 순서

```
 0 허리 앞뒤        1 허리 좌우
 2 왼 어깨 앞뒤      3 왼 어깨 좌우      4 왼 팔꿈치
 5 오른 어깨 앞뒤    6 오른 어깨 좌우    7 오른 팔꿈치
 8 왼 엉덩이 앞뒤    9 왼 엉덩이 좌우   10 왼 무릎   11 왼 발목 앞뒤   12 왼 발목 좌우
13 오른 엉덩이 앞뒤 14 오른 엉덩이 좌우 15 오른 무릎 16 오른 발목 앞뒤 17 오른 발목 좌우
```

**Hierarchy 위에서 아래 순서 = 키보드 순서 = 행동 순서 = 관측 순서.** 3장에서 AI는 이 순서 그대로 숫자 18개를 낸다.
팔이 다리보다 앞에 오는 것은 `Torso` 가 `Pelvis` 의 첫 번째 자식이라서다 (`GetComponentsInChildren` 은 위에서부터 차례로 찾는다).

## 핵심 개념 ④ — 단단한 것과 균형 잡는 것은 다르다

**이 장에서 가장 중요한 실험이다.** 모터를 켜고 차렷 자세로 두면 몸은 서 있다.
그러면 균형을 잡는 걸까? `P`로 밀어 보자.

| 몸통을 미는 세기 | 앞으로 | 뒤로 | 옆으로 |
|---|---|---|---|
| 10 N·s | 버팀 | **넘어짐** | 버팀 |
| 20 N·s | **넘어짐** | **넘어짐** | **넘어짐** |

(실측. 뒤로 약한 이유: 뒤꿈치가 0.08m로 발끝 0.16m보다 짧다)

모터는 "관절 각도"를 지킬 뿐, **"몸 전체가 쓰러지는지"는 모른다.**
몸 전체가 막대처럼 단단히 굳은 채로 넘어진다.
넘어지지 않으려면 밀린 쪽으로 발을 내딛거나 발목·엉덩이를 순간적으로 틀어야 한다.
**그 판단을 3장에서 AI가 배운다.**

## 핵심 개념 ⑤ — 자세는 천천히 바꾼다

`2`(무릎 굽히기)를 누르면 목표가 2초에 걸쳐 바뀐다. 한 번에 바꾸면 그 움직임에 몸이 밀려 넘어진다.
같은 자세라도 **어떻게 가느냐**에 따라 넘어지기도 하고 버티기도 한다. 걷기가 어려운 이유다.

## 구현 과제

1. Humanoid Body 의 Spring · Damper 를 넣는다. 실습 2-1 · 2-2 를 구현한다. Keyboard Control 을 붙인다.
2. Play → `H`로 매달고, `←→↑↓`로 18축을 **하나씩 끝까지** 돌려 본다. 화면의 "목표"와 "실제"가 같이 움직이는지 본다.
3. `H`로 내리고 `2` → 무릎을 굽힌 채 버티는지 본다. `1`로 다시 선다.
4. `P`로 민다 → 넘어진다. `R`로 다시 선다.
5. Inspector에서 `HumanoidBody`의 Spring을 300으로 바꾸고 Play → `2` → 무릎을 굽히다 넘어진다.

## 실습 2-1 — 관절 모터에 목표 넣기 `BodyPart.SetTarget(x, z)`

**형태** — 처음부터 (한 줄)

**하는 일** — 관절이 x(앞뒤) · z(좌우) 도로 가도록 Configurable Joint 모터의 `targetRotation` 을 정한다. Y(비틀기)는 잠갔으니 0.
AI가 정하는 것은 이 **목표**뿐이고, 힘은 모터(spring · damper)가 낸다.

| 요구사항 | 테스트 상황 → 기대 |
|---|---|
| 앞뒤(X) 각도 | `SetTarget(30, 0)` → 앞뒤 30° |
| 좌우(Z) 각도 | `SetTarget(0, 15)` · `SetTarget(30, 15)` |
| 부호를 바꾸지 않는다 | `SetTarget(-40, -10)` **(경계)** → 그대로 (가동 범위도 같은 관절 공간이다) |

## 실습 2-2 — 행동 18개를 관절로 `HumanoidBody.SetActions(actions)`

**형태** — 일부 코드 제공 (반복과 "관절이 바뀌는 곳" 판정이 주어진다)

**하는 일** — 키보드든 AI든 몸을 움직이는 유일한 입구. 행동 i번(-1~1)을 i번 축의 목표 각도로 바꿔 관절마다 `SetTarget` 한다.
한 관절에 축이 둘(X · Z)이면 두 값을 모았다가 **한 번에** 넣어야 한쪽이 지워지지 않는다.

**쓸 수 있는 것** — `_dofPart[i]`(축이 속한 부품) · `_dofIsZ[i]` · `Range(i)` · `HumanoidMath.ActionToAngle`(주어진 함수: -1 → low, 0 → 0도, +1 → high) · 실습 2-1

| 요구사항 | 테스트 상황 → 기대 |
|---|---|
| 행동 0 = 차렷 | 행동 전부 0 → 모든 관절 목표 0도 |
| 행동 → 각도 (가동 범위 안에서) | 왼 엉덩이 앞뒤 +1 → 90도 · 왼 무릎 -1 → -120도 |
| 한 관절의 X · Z 를 함께 | 엉덩이 앞뒤 0.5 · 좌우 -1 → (45, -25) |
| 다음 관절에 값이 남지 않는다 | 엉덩이 좌우 +1 만 → 무릎은 0도 **(경계)** |

> 막히면 튜토리얼 창의 **💡 힌트**를 한 단계씩 연다 — ① 방향·핵심 개념 → ② 구조와 처리 순서 → ③ 핵심 로직 → ④ 기본 코드 + 빈칸 → ⑤ 완성 코드 + 해설.
> 빈칸 코드(④)와 정답(⑤)은 창에서만 보여 주고, [파일에 넣기]로 바로 넣을 수도 있다.

```
튜토리얼 창 2장 · 실습 2-1 (요구사항 3/3) · 2-2 (4/4)
```

> 구현을 시작한 직후(임시값) Play하면 어떤 키를 눌러도 관절이 0도에 머문다(임시값 `return 0f`).
> 채우고 나서 다시 해보면 차이를 바로 볼 수 있다.

**실측 (spring 4000 · damper 400)**

| 시험 | 결과 |
|---|---|
| 차렷으로 6초 | 버팀 (골반 높이 0.96 유지) |
| 무릎 굽히기(엉덩이 20 · 무릎 -40 · 발목 20)를 2초에 걸쳐 | 버팀. 자리 잡은 뒤 최대 각도 오차 **2.5°** |
| 같은 무릎 굽히기 · spring 300 | 2.3초에 넘어짐 |
| 같은 무릎 굽히기 · spring 1000 | 3.9초에 넘어짐 |
| 몸통 밀기 20 N·s | 넘어짐 (앞·뒤·옆 모두) |
| 매달고 팔 축을 끝까지 | 어깨 -60 / 120 · 팔꿈치 0 / 130 까지 간다. 어깨를 안쪽으로 모으면 아래팔이 몸통에 막혀 5~9° 에서 멈춘다 |
| 선 채로 양팔을 앞뒤로 흔들기 (어깨 ±50%, 6초) | 버팀 |

**확인 체크리스트**

- [ ] 매단 상태에서 18축이 모두 목표를 따라 움직인다 (어깨 안쪽은 몸통에 막히는 것이 정상)
- [ ] 무릎이 앞으로 꺾이지 않는다 (가동 범위 0이 막는다)
- [ ] 무릎 굽히기 자세에서 넘어지지 않는다
- [ ] `P`로 밀면 넘어진다 — **3장에서 AI가 고칠 문제**
- [ ] 실습 2-1 · 2-2 테스트 통과 (요구사항 전부 ✔)

## 자주 밟는 함정

| 증상 | 원인 |
|---|---|
| 키를 눌러도 관절이 안 움직인다 | Spring이 0이다(1장 상태). 메뉴 2를 실행했는지 본다. 또는 실습 2-1 · 2-2 를 아직 구현하지 않았다 |
| 관절이 출렁이며 멈추지 않는다 | Damper가 너무 작다. Spring의 1/10에서 시작 |
| 목표의 반대쪽으로 돈다 | `targetRotation` 부호. 가동 범위와 같은 공간인지 확인 |
| 자세를 바꾸자마자 넘어진다 | 한 번에 바꿨다. 천천히 바꾼다 |
| `R`로 되돌렸는데 곧바로 또 넘어진다 | 몸만 되돌리고 목표 각도는 이전 자세로 남겨 두면 다시 그 자세로 당겨진다. 초기화할 때 목표 각도도 차렷(0)으로 되돌린다 (`ResetActions`) |

## 이 장에서 배우는 것

1. **관절 모터 = 목표 각도로 당기는 스프링(PD 제어).** AI는 목표만 정한다.
2. **행동 0 = 차렷 자세.** 학습이 서 있는 자세에서 출발하게 한다.
3. **관측은 -1~1로 맞춘다.** 범위가 다른 각도를 그대로 섞지 않는다.
4. **단단함 ≠ 균형.** 모터만으로는 살짝 밀어도 넘어진다. 그래서 학습이 필요하다.
5. **사람이 먼저 확인한다.** 관절이 다 돌고, 서 있을 수 있는 몸인지를 AI 전에 본다.
