# 4장 — 걷기 보상 (최종 과제)

> 3장에서 AI는 **넘어지지 않는 법**을 배웠다. 이제 **"앞으로 가라"** 를 보상으로 말한다.
> 이 장에서 이 트랙의 목표 — **스스로 걷는 정책** — 이 완성된다.

>
> 실습은 **튜토리얼 창**(`Humanoid > 튜토리얼 열기`)을 따라 한다. 이 문서는 그 설명을 자세히 푼 참고서다.

---

## 학습 목표

- 상속한 에이전트에 관측을 더할 수 있다 → **실습 4-1**
- 목표 도달 보상과 "제한시간 안에 못 닿으면 판 끝"을 쓸 수 있다 → **실습 4-2, 4-3**
- 두 보상을 **곱하는 이유**를 설명할 수 있다
- 3장 에이전트를 **상속해** 바뀐 것만 고치는 방법을 안다

---

## 단계별로 하는 일

| 단계 | 하는 일 |
|---|---|
| 1 목표 상자 | `HumanoidArea` 아래 Cube `Target` · Position (0,0.25,6) · Scale 0.5 · Box Collider 지우기 |
| 2 에이전트 바꾸기 | Walk Agent 붙이기 → Stand Agent 지우기 → Target 연결 · Target Speed 1 · Push Interval 0 · Max Step 5000 |
| 3 두뇌 설정 | Behavior Name `HumanoidWalk` · Space Size 51 |
| 4 실습 4-1 | 목표 관측 +3 (`CollectObservations`) · 기능 추가 |
| 5 실습 4-2 | 목표 도달 보상 (`StepReward`) · 일부 코드 제공 |
| 6 실습 4-3 | 제한시간 판 끝 (`OnActionReceived`) · 기능 추가 |
| 7 서 있으면 0점 | Heuristic Only 로 확인 |
| 8 학습 | `mlagents-learn` |

| 컴포넌트 | 설정 |
|---|---|
| `WalkAgent` | `StandAgent`를 대신한다. Target 연결 · Target Speed **1** · Push Interval **0** · Max Step **5000** (안전 상한) |
| `BehaviorParameters` | Behavior Name `HumanoidWalk` · 관측 **51** (행동은 그대로 18) |
| `Target` | 빨간 상자. 몸 주변 4~8m에 무작위로 놓인다 |

`WalkAgent`는 `StandAgent`를 **상속**한다. 관측 48개, 행동 18개, 넘어지면 끝내기는 그대로 물려받고
**관측 3개 추가 · 보상 교체 · 목표 제한시간**만 새로 쓴다.

> 밀기(Push Interval)는 끈다. 걷기를 배우는 동안 밀기까지 하면 무엇 때문에 실패하는지 알 수 없다.

## 핵심 개념 ① — 관측 +3 (총 51)

| 개수 | 관측 | |
|---|---|---|
| 48 | 3장 그대로 | 자세 · 기울기 · 속도 · 발 |
| 2 | 목표 방향 (내가 보는 방향 기준 x, z) | [실습 4-1] |
| 1 | 목표 속도 | 5장에서 바뀐다. AI가 알아야 맞출 수 있다 |

**"내가 보는 방향 기준"** — 목표가 내 오른쪽에 있으면 언제나 x가 양수다.
세상 기준으로 주면 같은 "오른쪽"이라도 내가 어느 쪽을 보고 있느냐에 따라 숫자가 달라진다.

그런데 몸은 걸으며 앞뒤로 기운다. 기운 몸의 정면을 그대로 쓰면 "땅을 보는 방향"이 된다.
그래서 **좌우 회전만** 남긴다 (`forward.y = 0`). 주어진 함수 `HumanoidMath.HeadingRotation` 이 이것을 한다.

## 핵심 개념 ② — 보상 = 속도 × 방향

```
속도 보상 = (1 − (d / 목표속도)²)²     d = |몸 속도 − 목표방향 × 목표속도|      SpeedReward — 주어진 함수
방향 보상 = (몸통 정면 · 목표 방향 + 1) / 2                                   FacingReward — 주어진 함수
매 스텝 보상 = 속도 보상 × 방향 보상   (+ 목표에 닿으면 1)
```

| 상황 | 속도 | 방향 | 곱 | 더하기였다면 |
|---|---|---|---|---|
| 목표를 보며 1 m/s로 간다 | 1 | 1 | **1** | 2 |
| 목표를 보고 서 있다 | 0 | 1 | **0** | 1 ← 서 있기만 해도 절반 |
| 뒷걸음으로 목표 쪽으로 간다 | 1 | 0 | **0** | 1 ← 뒤로 걸어도 절반 |
| 엉뚱한 쪽으로 달린다 | 0 | 0.5 | **0** | 0.5 |

**곱하면 둘 다 만족해야 점수가 난다.** 더하면 하나만 잘해도 절반은 받으니,
AI는 쉬운 쪽(서 있기)만 하고 멈춘다.

> 3장의 서기 보상은 이제 없다. 그런데도 넘어지지 않으려 한다.
> **넘어지면 판이 끝나 앞으로 받을 속도 보상이 사라지기 때문이다.**

## 핵심 개념 ③ — 목표를 맞힐수록 오래 산다 (판이 끝나는 때)

RollerBall 은 공이 바닥에서 떨어지면 판이 끝났다. 걷기도 같은 생각을 쓴다 — **실패하면 끝, 잘하면 계속.**

| 끝나는 때 | 왜 |
|---|---|
| 넘어짐 | 3장 그대로 |
| **목표마다 주는 제한시간** 안에 못 닿음 | 서성이거나 엉뚱한 데로 가면 끝 |
| Max Step 5000 (100초) | 잘 걸을 때의 안전 상한. 판이 영원히 이어지면 출발 상황을 다시 배우지 못한다 |

```
제한시간 = 목표까지 거리 ÷ 목표 속도 × 2 + 5초        (예: 6m · 1.0 m/s → 17초,  8m · 0.5 m/s → 37초)
목표에 닿으면  +1 · 목표를 새 자리로 · 제한시간도 새로
```

거리와 목표 속도로 정하기 때문에 먼 목표나 느린 목표(5장 커리큘럼의 0.5 m/s)도 공평하다.
제한시간에 걸려도 **벌점은 없다.** 넘어짐과 같이, 앞으로 받을 보상이 사라지는 것이 벌이다.

그래서 **에피소드 길이 = 생존 시간 = 성적**이 된다. 목표를 잘 맞히는 정책일수록 판이 길어진다
(TensorBoard `Environment/Episode Length`). 시간이 다 돼서 끊기는 것이 아니라 실력만큼 산다.

> AI는 남은 시간을 관측하지 않는다(관측을 늘리지 않는다). 대신 제한시간을 넉넉하게(2배 + 5초) 두어,
> 제대로 걸어가는 동안에는 걸리지 않게 했다. 화면 왼쪽 위에 남은 시간이 보인다.

## 핵심 개념 ④ — 몸 전체의 속도

골반 속도만 보면 골반만 앞으로 내밀어도 점수가 난다.
**부품 12개의 속도를 질량으로 가중 평균**한다. 1장의 무게중심 식(`CenterOfMass`)에 위치 대신 속도를 넣으면 된다.
`HumanoidBody.CenterOfMassVelocity`가 그것이다. 같은 실습 함수를 두 번 쓴다.

---

## 구현 과제

1. 튜토리얼 창 4장의 단계를 차례로 한다 (위 표). 4장 전체를 한 번에: `Humanoid > 4. 걷기 에이전트로 바꾸기`.
2. `Heuristic Only`로 Play → 키보드로 아무리 움직여도 보상이 거의 0이다. **사람이 손으로 걷게 만들 수는 없다.** 그래서 학습한다.
3. 실습 4-1 ~ 4-3을 구현한다.
4. 학습한다. 결과를 3장과 비교한다.

## 실습 4-1 — 목표 관측 +3 `WalkAgent.CollectObservations(sensor)`

**형태** — 기능 추가 (`base.CollectObservations(sensor)` 가 주어진다)

**하는 일** — 서기 관측 48개 뒤에 목표 방향(내가 보는 방향 기준 x · z)과 목표 속도를 더한다.
`HumanoidMath.HeadingRotation`(주어진 함수)의 역회전으로 세상 방향을 내 방향으로 바꾼다.

| 요구사항 | 테스트 상황 → 기대 |
|---|---|
| 관측 51개 | 넣은 개수 51 |
| 서기 관측이 먼저 | 첫 값 0.96 |
| 목표 방향을 내가 보는 방향 기준으로 | 목표가 오른쪽 → (1, 0) · 몸을 오른쪽으로 돌림 **(경계)** → 앞 (0, 1) |
| 목표 속도 | targetSpeed 1.3 → 마지막 값 1.3 |

## 실습 4-2 — 걷기 보상 `WalkAgent.StepReward()`

**형태** — 일부 코드 제공 (방향 · 속도 계산과 성적표 기록 줄이 주어진다)

**하는 일** — 목표에 닿으면(수평 0.6m 안) +1 · 닿은 수 +1 · `MoveTarget()`. 그리고 속도 점수 × 방향 점수(주어진 함수 `SpeedReward` · `FacingReward`)를 더한다.
닿아도 판은 끝내지 않는다 — 목표만 옮겨 계속 걷게 한다.

| 요구사항 | 테스트 상황 → 기대 |
|---|---|
| 목표에 닿으면 +1 | 목표가 0.3m 앞 → 보상 1 이상 |
| 닿으면 목표를 새 자리로 | 닿은 뒤 목표까지 4m 이상 · 닿은 수 1 |
| 걷기 점수 = 속도 × 방향 | 목표 쪽을 보며 1 m/s → 1 · 서 있기만 함 **(경계)** → 0 |
| 더하지 않고 곱한다 | 목표를 등지고 목표 쪽으로 이동 **(경계)** → 0 |

## 실습 4-3 — 제한시간 `WalkAgent.OnActionReceived(actions)`

**형태** — 기능 추가 (`base.OnActionReceived(actions)` 가 주어진다)

**하는 일** — 서기의 행동 · 보상 · 넘어지면 끝내기는 base 로 그대로 하고, `StepCount > _deadline` 이면 `EndEpisode()` (위 개념 ③).

| 요구사항 | 테스트 상황 → 기대 |
|---|---|
| 제한시간이 지나면 판 끝 | 마감 지남 → 끝난 판 수 +1 |
| 제한시간 안에는 계속 | 마감 전 **(경계)** → 판 계속 |
| 서기 동작도 그대로 | 왼 무릎 행동 -1 → 무릎 목표 -120도 (base 를 지우지 않았나) |

> 막히면 튜토리얼 창의 **💡 힌트**를 한 단계씩 연다 — ① 방향·핵심 개념 → ② 구조와 처리 순서 → ③ 핵심 로직 → ④ 기본 코드 + 빈칸 → ⑤ 완성 코드 + 해설.
> 빈칸 코드(④)와 정답(⑤)은 창에서만 보여 주고, [파일에 넣기]로 바로 넣을 수도 있다.

## 실행 및 검증

```
mlagents-learn Assets/Humanoid/humanoid_config.yaml --run-id=walk
```

> 걷기는 서기보다 훨씬 오래 걸린다. 5장의 병렬 학습(영역 9개)을 먼저 해두면 그만큼 빨라진다.
> 5장 커리큘럼 없이 1.0 m/s 고정으로 돌리려면 yaml 맨 아래 `environment_parameters:` 부분을 지운다.

`HumanoidWalk`에서 3장과 달라진 값:

| 값 | 서기 | 걷기 | 왜 |
|---|---|---|---|
| `hidden_units` × `num_layers` | 256 × 2 | **512 × 3** | 할 일이 많다 |
| `gamma` | 0.99 | **0.995** | 한 걸음의 결과가 늦게 나타난다 (약 4초 앞까지) |
| `max_steps` | 4백만 | **1천만** | |

**실측 학습 결과** (빌드 4개 × 영역 9개 = 에이전트 36개, 목표 속도 1.0 고정)

| 스텝 | 학습 중 평균 보상 |
|---|---|
| 100만 | 33 (처음엔 몸을 던지고 넘어진다) |
| 200만 | 75 |
| 300만 | 381 ← 여기서 급격히 오른다 (넘어지지 않고 몇 걸음 가기 시작) |
| 400만 | 1033 |
| 500만 | 1660 |
| 700만 | 2513 |
| 1000만 | 약 3050 (마지막 50만 스텝 평균) |

1000만 스텝 = 약 52분. 서기(3장)보다 2.5배 많은 경험이 필요했다.
보상이 계속 오르는 것은 **목표를 맞힐수록 판이 길어지기** 때문이다 — 보상 곡선과 `Episode Length` 곡선이 같이 오른다.

**학습된 모델 평가** (Inference Only · 목표 속도 1.0 · 10판)

| 평균 생존 (중앙값) | 판당 도달한 목표 | 끝난 이유: 넘어짐 · 제한시간 · 상한 100초 | 평균 속도 |
|---|---|---|---|
| **84초 (100초)** | **11.7개** | 3 · 0 · **7** | 0.75 m/s |

10판 중 7판은 넘어지지 않고 상한(100초)까지 목표를 계속 맞혔다. 제한시간에 걸린 판은 없다.
넘어진 3판도 넘어지기 전까지는 목표를 맞히고 있었다 (그래서 평균 84초).
목표 속도(1.0)보다 조금 느리다. 속도 보상은 곡선이라 0.75여도 0.8점 가까이 받기 때문에
"넘어질 위험을 줄이고 조금 느리게"가 이득이었던 것으로 보인다.

> 판 끝을 "40초 고정"으로 두었을 때(같은 몸 · 같은 1000만 스텝)는 40초에 4.8개, 10판 중 3판 넘어짐이었다.
> 시간당 도달은 비슷하지만(분당 약 7~8개), 이제는 **잘하는 만큼 판이 길어져** 성적이 에피소드 길이로 바로 보인다.

**확인 체크리스트**

- [ ] 실습 4-1 ~ 4-3 테스트 통과 (요구사항 전부 ✔)
- [ ] Heuristic Only로 Play — 에러 없음, 서 있기만 하면 보상 0
- [ ] TensorBoard `Environment/Cumulative Reward`가 오른다
- [ ] `Environment/Episode Length`가 길어진다 = 넘어지지 않고 제한시간 안에 목표를 계속 맞힌다 (최대 5000)
- [ ] 학습된 모델로 Play → 빨간 상자를 향해 걸어가고, 닿으면 다음 상자로 방향을 튼다 (실측: 10판 중 7판이 100초 상한까지 버팀, 판당 11.7개)

## 자주 밟는 함정

| 증상 | 원인 |
|---|---|
| 앞으로 몸을 던지고 끝난다 | 넘어지기 직전의 속도로 점수를 얻는다. 학습 초반에는 흔하다. 계속 넘어지면 판이 짧아져 총점이 낮다는 것을 곧 배운다 |
| 제자리에서 버티기만 한다 | 보상을 더하기로 만들었다. 곱한다 |
| 목표를 등지고 뒷걸음질 | 방향 보상이 빠졌다 |
| 목표 방향 관측이 몸을 돌릴 때마다 튄다 | 4-1에서 y를 버리지 않았다 |
| 보상이 처음부터 끝까지 0 | 실습 4-2 를 아직 구현하지 않았다 (StepReward 가 0) |

---

## 이 장에서 배우는 것

1. **상속으로 한 가지만 바꾼다.** 서기 에이전트 + 관측 3 + 보상 교체 = 걷기 에이전트.
2. **관측은 "내가 보는 방향" 기준.** 그때 기울기는 버리고 좌우 회전만 남긴다.
3. **곱하는 보상.** 둘 다 만족해야 점수 — 쉬운 쪽만 하는 꼼수를 막는다.
4. **판 종료가 균형을 지킨다.** 서기 보상이 없어도 넘어지지 않으려 한다.
5. **같은 식을 다른 곳에 쓴다.** 무게중심 식 = 몸 전체 속도 식.
