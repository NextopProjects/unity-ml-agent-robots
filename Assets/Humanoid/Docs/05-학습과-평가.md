# 5장 — 학습과 평가

> 4장에서 걷는 정책이 나왔다. 이 장은 같은 과제를 **더 빨리(병렬) · 더 넓게(커리큘럼)** 학습시키고,
> **"잘 걷는다"를 숫자로 재는 법(평가 지표)** 을 다룬다. 관측·행동·보상은 바꾸지 않는다.

>
> 실습은 **튜토리얼 창**(`Humanoid > 튜토리얼 열기`)을 따라 한다. 이 문서는 그 설명을 자세히 푼 참고서다.

---

## 학습 목표

- 학습 영역을 복제해 경험을 여러 배로 모을 수 있다 (코드 수정 없이)
- 커리큘럼으로 목표 속도를 단계적으로 올릴 수 있다
- 평균 속도 · 속도 오차 · 넘어짐 · 도달 수를 TensorBoard 에 남기고, 커리큘럼 값을 읽는 코드를 쓸 수 있다 → **실습 5-1, 5-2**
- 학습된 모델을 붙여 **추론(Inference)** 으로 평가할 수 있다

---

## 단계별로 하는 일

| 단계 | 하는 일 |
|---|---|
| 1 실습 5-1 | 성적 기록 (`RecordStats` — StatsRecorder) · 처음부터 |
| 2 실습 5-2 | 커리큘럼 값 읽기 (`ReadCurriculum` — GetWithDefault) · 처음부터 |
| 3 병렬 학습 | 학습 영역 9개로 복제 (버튼 · 메뉴 `Humanoid > 5. 학습 영역 9개로 복제`) |
| 4 커리큘럼 | yaml 확인 → 빌드 → 학습 → TensorBoard |
| 5 평가·정리 | 목표 속도별 평가표 → 영역 1개로 되돌리기 |

- `WalkAgent` 의 판마다 성적 기록(실습 5-1)과 목표 속도 읽기(실습 5-2)를 직접 쓴다.
- `humanoid_config.yaml` 맨 아래 `environment_parameters:` 가 커리큘럼이다.

> 복제는 **1~4장을 다 끝낸 뒤 마지막에** 한다. 장별 메뉴와 튜토리얼 조건은 이름으로 첫 번째 영역만 찾는다.
> 저장소에는 1개 상태로 둔다(씬 파일이 9배로 커진다).

---

## 핵심 개념 ① — 병렬 학습: 코드는 그대로, 경험은 9배

강화학습이 느린 이유는 계산이 아니라 **경험을 모으는 속도**다.
`Behavior Name`이 같은 에이전트는 ML-Agents가 **한 두뇌**로 묶는다. 영역을 9개 두면 경험이 9배로 쌓인다.

```
mlagents-learn ... --num-envs=4     ← 실행 파일(빌드)을 4개 띄운다. 9영역 × 4 = 에이전트 36
```

`--num-envs`는 빌드한 실행 파일로 학습할 때 쓴다(`--env=빌드경로.exe --no-graphics`).
에디터 Play로는 1개만 돈다. 이 트랙의 학습 결과는 전부 빌드 4개로 측정했다.

## 핵심 개념 ② — 커리큘럼: 쉬운 것부터

처음부터 1.5 m/s를 요구하면 넘어지기만 한다. 느린 걸음에서 시작해 잘하면 올린다.

```yaml
environment_parameters:
  target_speed:
    curriculum:
      - name: Slow    value: 0.5    → 보상이 기준을 넘으면 다음으로
      - name: Normal  value: 1.0    → 보상이 기준을 넘으면 다음으로
      - name: Fast    value: 1.5
```

`WalkAgent`는 판마다 `Academy.Instance.EnvironmentParameters.GetWithDefault("target_speed", …)`로 읽는다.
목표 속도는 관측에도 들어 있어서(4장) AI는 "지금 얼마나 빨리 가야 하는지" 안다.

> 다음 단계로 넘어가는 기준(`threshold`)은 **보상 크기에 맞춰야 한다.** 보상 식을 바꾸면 다시 정한다.
> 기준이 너무 높으면 영원히 첫 단계에 머물고, 너무 낮으면 못 걷는데 넘어간다.

## 핵심 개념 ③ — 보상만 보면 안 된다

보상이 오르는데 실제로는 이상하게 걷는 경우가 많다(몸을 던지기, 종종걸음, 한 발 뛰기 …).
보상은 **우리가 정한 식의 점수**일 뿐이다. 진짜 하고 싶은 것을 직접 잰다.

| 지표 (TensorBoard) | 뜻 | 좋은 값 |
|---|---|---|
| `Walk/Speed` | 목표 쪽으로 실제로 간 평균 속도 [실습 5-1] | 목표 속도에 가깝게 |
| `Walk/SpeedError` | \|평균 속도 − 목표\| / 목표 [실습 5-1] | 0에 가깝게 |
| `Walk/FallRate` | 넘어져서 끝난 판의 비율 | 0에 가깝게 |
| `Walk/Targets` | 한 판에 닿은 목표 수 = 얼마나 오래 살았나 (닿을 때마다 제한시간을 새로 받는다) | 많을수록 |

`StatsRecorder.Add`로 남긴 값은 `summary_freq`마다 평균을 내서 그려진다.
판마다 넘어졌으면 1, 아니면 0을 넣으면 **그 평균이 곧 넘어짐 비율**이다.

## 핵심 개념 ④ — 평가는 학습과 따로

학습 중의 AI는 일부러 **무작위로 흔들며**(탐험) 행동한다. 학습 중 점수는 실력보다 낮게 나온다.
실력은 학습을 멈추고 재야 한다.

```
results/<run-id>/HumanoidWalk.onnx  →  Behavior Parameters의 Model 칸
(미리 학습해 둔 모델: Assets/Humanoid/results/HumanoidWalk.onnx · HumanoidStand.onnx)
Behavior Type = Inference Only  →  Play
화면 왼쪽 위: 평균 속도 / 목표 · 도달 수
```

## 구현 과제

1. 1~4장을 끝낸 뒤 학습 영역을 9개로 복제한다.
2. 빌드한다 (`File > Build Profiles`, 씬은 `Humanoid.unity` 하나).
3. 커리큘럼 기준값을 확인하고(아래 실측 참고) 학습한다.
   ```
   mlagents-learn Assets/Humanoid/humanoid_config.yaml --run-id=walk_curriculum --env=<빌드>.exe --no-graphics --num-envs=4
   ```
4. TensorBoard에서 `Environment/Lesson Number`(커리큘럼 단계)와 `Walk/…` 지표를 본다.
5. 학습된 모델로 평가한다. 표를 채운다.

| 목표 속도 | 평균 속도 | 속도 오차 | 넘어짐 비율 | 판당 도달 |
|---|---|---|---|---|
| 0.5 | | | | |
| 1.0 | | | | |
| 1.5 | | | | |

(Inspector에서 `WalkAgent`의 Target Speed를 바꿔 가며 잰다. 학습기 없이 Play하면 커리큘럼은 적용되지 않는다)

6. 실습 5-1 · 5-2 를 구현한다 (학습 전에 — 지표와 커리큘럼이 이 코드로 동작한다).

## 실습 5-1 — 성적 기록 `WalkAgent.RecordStats()`

**형태** — 처음부터

**하는 일** — 판이 시작될 때 지난 판의 성적 네 가지를 `Academy.Instance.StatsRecorder.Add("Walk/…", 값)` 로 남긴다. 기록이 없으면(첫 판) 남기지 않는다.

**쓸 수 있는 것** — `_speed`(SpeedStats: `Count` · `Average` · `Error(targetSpeed)`) · `_fell` · `_reached`

| 요구사항 | 테스트 상황 → 기대 |
|---|---|
| 성적 네 가지를 남긴다 | Walk/Speed 0.8 · Walk/SpeedError 0.2 · Walk/FallRate 1 · Walk/Targets 3 |
| 기록이 없으면 남기지 않는다 | 첫 판 **(경계)** → 아무것도 안 남김 |

## 실습 5-2 — 커리큘럼 값 읽기 `WalkAgent.ReadCurriculum()`

**형태** — 처음부터 (한 줄)

**하는 일** — `Academy.Instance.EnvironmentParameters.GetWithDefault("target_speed", targetSpeed)` 로 커리큘럼이 정한 목표 속도를 판마다 읽는다.
이름이 yaml 과 다르면 에러 없이 늘 기본값만 나온다 — 커리큘럼이 "안 먹는" 흔한 원인.

| 요구사항 | 테스트 상황 → 기대 |
|---|---|
| 커리큘럼 값을 읽는다 | target_speed 1.5 → 1.5 · 단계가 0.5 → 1.0 으로 오름 → 다음 판 1.0 |
| 없으면 지금 값 그대로 | 커리큘럼 없음 **(경계)** → Inspector 값(1.2) 그대로 |

> 막히면 튜토리얼 창의 **💡 힌트**를 한 단계씩 연다 — ① 방향·핵심 개념 → ② 구조와 처리 순서 → ③ 핵심 로직 → ④ 기본 코드 + 빈칸 → ⑤ 완성 코드 + 해설.
> 빈칸 코드(④)와 정답(⑤)은 창에서만 보여 주고, [파일에 넣기]로 바로 넣을 수도 있다.

## 실행 및 검증

**실측** (빌드 4개 × 영역 9개)

**① 1.0 m/s로만 학습한 모델(4장)을 다른 속도로 평가** (Inference Only · 각 10판)

| 목표 속도 | 평균 생존 (중앙값) | 판당 도달 | 넘어진 판 | 평균 속도 |
|---|---|---|---|---|
| 0.5 | 38초 (37초) | 3.7 | **9 / 10** | 0.53 |
| **1.0 (학습한 속도)** | **84초 (100초)** | **11.7** | **3 / 10** | 0.75 |
| 1.5 | 56초 (63초) | 8.4 | **8 / 10** | 0.77 |

배운 속도에서 가장 오래 살고, **배우지 않은 속도에서는 대부분 넘어진다.**
1.5를 시켜도 0.77로 간다 — 빠르게 걷는 법은 배우지 않았다. 0.5에서는 속도는 맞추지만 느린 걸음이 불안정해 넘어진다. 여러 속도를 쓰려면 여러 속도로 학습해야 한다 → 커리큘럼.

**② 커리큘럼 기준값**

`threshold: 2100` 은 위 1.0 고정 학습이 최종 약 3050에 도달한 것을 보고 그 70% 정도로 잡은 값이다.
(판이 실력만큼 길어지므로 보상 크기도 판 길이를 따라간다. 판 끝 규칙을 바꾸면 이 값도 다시 잡는다.)
**커리큘럼 학습 자체는 아직 실측하지 않았다.** 돌려 보고 `Environment/Lesson Number`가 오르지 않으면 낮추고,
너무 빨리 넘어가 넘어짐 비율이 치솟으면 높인다.

**확인 체크리스트**

- [ ] 실습 5-1 · 5-2 테스트 통과 (요구사항 전부 ✔)
- [ ] 영역 9개로 복제해도 코드 수정 없이 학습이 돈다
- [ ] TensorBoard에 `Walk/Speed` · `Walk/SpeedError` · `Walk/FallRate` · `Walk/Targets` 가 보인다
- [ ] `Environment/Lesson Number` 가 0 → 1 → 2로 오른다
- [ ] 학습된 모델로 목표 속도별 평가표를 채웠다
- [ ] 저장소의 씬은 영역 1개 상태로 되돌렸다

## 자주 밟는 함정

| 증상 | 원인 |
|---|---|
| 복제했더니 메뉴가 엉뚱한 영역을 고친다 | 복제를 먼저 했다. 1개로 되돌리고 메뉴를 실행한 뒤 다시 복제 |
| `Lesson Number`가 0에서 안 오른다 | `threshold`가 보상 크기보다 높다 |
| `--num-envs`가 "worker in use" 오류 | 다른 학습이 같은 포트를 쓴다. `--base-port=5020` 처럼 바꾼다 |
| 학습 중 점수와 평가 점수가 다르다 | 정상. 학습 중에는 일부러 흔들며 행동한다 |
| `Walk/…` 그래프가 없다 | 판이 한 번도 끝나지 않았다 (지표는 다음 판 시작 때 기록한다) |

---

## 이 장에서 배우는 것

1. **병렬 학습은 코드를 바꾸지 않는다.** 같은 Behavior Name = 한 두뇌.
2. **커리큘럼 = 쉬운 것부터.** 기준값은 보상 크기에 맞춘다.
3. **보상 ≠ 목표.** 진짜 하고 싶은 것(속도 · 넘어짐 · 도달)을 따로 잰다.
4. **평가는 학습과 따로.** 탐험을 끄고(Inference) 잰다.
