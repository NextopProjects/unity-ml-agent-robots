# 3장 — 서기 학습 (ML-Agents 도입)

> 2장에서 확인했다. 모터만으로는 **살짝 밀어도 넘어진다.**
> 이 장에서 AI를 붙여 **밀려도 버티는 법**을 배우게 한다. 아직 걷지 않는다.

>
> 실습은 **튜토리얼 창**(`Humanoid > 튜토리얼 열기`)을 따라 한다. 이 문서는 그 설명을 자세히 푼 참고서다.

---

## 학습 목표

- 에이전트의 네 함수(OnEpisodeBegin · CollectObservations · OnActionReceived · Heuristic)를 휴머노이드에 맞게 채울 수 있다
- 판 시작 · 관측 · 행동과 보상 · 판 끝 — 에이전트의 함수를 직접 쓸 수 있다 → **실습 3-1 ~ 3-3**
- 넘어지면 판을 끝내는 것만으로 벌이 된다는 것을 학습 곡선으로 확인한다

---

## 단계별로 하는 일

| 단계 | 하는 일 |
|---|---|
| 1 에이전트 붙이기 | `Humanoid` 에 Add Component > Stand Agent (Behavior Parameters 가 같이 붙는다) · Max Step 1000 |
| 2 두뇌 설정 | Behavior Parameters: Behavior Name · Space Size · Continuous Actions |
| 3 판단 주기 | Add Component > Decision Requester · Period 5 · Take Actions Between Decisions |
| 4 키보드는 행동만 | Keyboard Control 의 Drive Body 끄기 |
| 5 실습 3-1 | 판 시작 (`OnEpisodeBegin`) · 처음부터 |
| 6 실습 3-2 | 관측 48개 (`CollectObservations`) · 처음부터 |
| 7 실습 3-3 | 행동 · 보상 · 넘어지면 판 끝 (`OnActionReceived`) · 일부 코드 제공 |
| 8 Heuristic 확인 | Heuristic Only → Play → 밀려 넘어지면 판이 다시 시작 → Default 로 되돌리기 |

| 10 평가 | 학습된 모델 → Inference Only |

| 컴포넌트 | 설정 |
|---|---|
| `StandAgent` | Max Step **1000** · Push Interval **150** · Max Push **20** |

## 핵심 개념 ① — 무엇을 보는가 (관측 48)

| 개수 | 관측 | 왜 |
|---|---|---|
| 1 | 골반 높이 | 주저앉는 중인가 |
| 3 | **몸이 느끼는 아래쪽** (`HumanoidMath.DownInBody` — 주어진 함수) | 어느 쪽으로 얼마나 기울었나 |
| 3 | 골반 속도 (몸 기준) | 어느 쪽으로 밀리는 중인가 |
| 3 | 골반 회전 속도 | 얼마나 빨리 쓰러지는 중인가 |
| 18 | 관절 각도 -1~1 (`body.NormalizedAngle`) | 지금 자세 (팔 6 포함) |
| 18 | 관절 속도 | 관절이 어느 쪽으로 움직이는 중인가 |
| 2 | 양발이 땅에 닿았나 | 어느 발로 버티고 있나 |

**"몸 기준"으로 본다.** 몸이 어느 쪽을 보고 서 있든 같은 상황이면 같은 숫자가 나와야
한 번 배운 것을 어느 방향에서나 쓸 수 있다.

> 관측 개수와 `BehaviorParameters`의 Space Size가 다르면 Play하는 순간 에러가 난다.
> 코드 끝의 `// = 48` 주석을 꼭 맞춘다.

## 핵심 개념 ② — 언제 칭찬하는가 (보상)

```
매 스텝 보상 = 똑바른 정도 × 높이 비율          (0 ~ 1)   StepReward() — 주어진 함수
넘어지면      판을 끝낸다 (벌점 없음)
```

- **곱한다.** 더하면 "쪼그려 앉아 똑바로" 또는 "기운 채로 높이"도 절반 점수를 받는다.
- **넘어지면 끝낸다.** 서 있으면 매 스텝 최대 1점, 1000스텝이면 최대 1000점.
  넘어지는 순간 남은 스텝의 점수가 사라진다.

> **할인율 γ(감마)** — 에이전트가 최대화하는 것은 지금 받는 보상이 아니라 앞으로 받을 보상의 합이다.
> 먼 미래일수록 γ를 한 번씩 더 곱해 깎는다:  `G = r0 + γ·r1 + γ²·r2 + …`
> 매 스텝 1점을 계속 받으면 G = 1/(1−γ). yaml의 `gamma: 0.99` 이면 **100점**이다.
> 넘어지면 이 100점이 한꺼번에 사라진다. 그래서 벌점을 따로 주지 않아도 넘어지기를 싫어하게 된다.

## 핵심 개념 ③ — 일부러 민다

150스텝(3초)마다 몸통을 무작위 방향으로 0~20 N·s 민다.
안 밀면 AI는 "가만히 있기(행동 0)"만 배운다. 2장에서 봤듯 그것만으로도 서 있기 때문이다.
**밀어야 "밀렸을 때 어떻게 버티는가"를 배운다.** 4장에서는 걷기에 집중하도록 끈다.

## 핵심 개념 ④ — 판단 주기

```
물리 50Hz,  Decision Period 5  →  AI는 1초에 10번 판단한다
판단 사이에는 직전 목표 각도를 유지한다 (모터가 알아서 버틴다)
```

모터가 짧은 시간의 균형을 맡고, AI는 "다음 목표 자세"만 정한다.
사람도 근육 하나하나를 의식하지 않는다.

## 구현 과제

튜토리얼 창 3장의 단계를 차례로 한다 (위 표). 컴포넌트는 메뉴 없이 직접 붙이고 값을 넣는다.
막히면 단계마다 [대신 해주기] 가 있다. 3장 전체를 한 번에 만들려면 `Humanoid > 3. 서기 에이전트 붙이기`.

## 실습 3-1 — 판 시작 `StandAgent.OnEpisodeBegin()`

**형태** — 처음부터

**하는 일** — 새 판이 시작될 때 몸 · 관절 목표 · (있으면) 키보드 행동을 처음 상태로. RollerBall 의 OnEpisodeBegin 이 공을 되돌린 것과 같다.

| 요구사항 | 테스트 상황 → 기대 |
|---|---|
| 몸을 처음 자세로 | 흐트러진 골반 → 처음 자리 (`body.ResetBody()`, 실습 1-1 이 맞아야 한다) |
| 관절 목표도 차렷으로 | 굽혀 둔 엉덩이 목표 → 0도 |
| 키보드 행동도 차렷으로 | 키보드에 남은 행동 → 0 (안 하면 Heuristic 일 때 1.2초 만에 다시 넘어진다) |
| 키보드가 없어도 된다 | 키보드 없음 **(경계)** → 오류 없음 (`_keyboard != null` 검사) |

## 실습 3-2 — 관측 `StandAgent.CollectObservations(sensor)`

**형태** — 처음부터

**하는 일** — AI에게 보여 줄 숫자 48개를 정해진 순서로 넣는다 (위 '관측 48' 표). 주어진 함수 `DownInBody` · `NormalizedAngle` · `Rate` 를 쓴다.

| 요구사항 | 테스트 상황 → 기대 |
|---|---|
| 관측 48개 | 넣은 개수 48 (Space Size 와 같아야 한다) |
| 골반 높이가 첫 번째 | 서 있을 때 첫 값 0.96 |
| 몸이 느끼는 아래쪽 | 2~4번째 (0, -1, 0) |
| 관절마다 각도 · 속도 순서 | 왼 엉덩이를 굽힘 → 27번째 = 그 각도 |
| 발 접촉이 마지막 두 칸 | 왼발만 닿음 **(경계)** → [1, 0] |

## 실습 3-3 — 행동 · 보상 · 판 끝 `StandAgent.OnActionReceived(actions)`

**형태** — 일부 코드 제공 (밀기 · 화면 표시 줄이 주어진다)

**하는 일** — 행동을 몸에 보내고(`body.SetActions`), 보상을 더하고(`AddReward(StepReward())`), 넘어졌으면 `EndEpisode()`.
강화학습 한 스텝의 중심이다. 넘어져도 벌점은 없다 — 앞으로 받을 보상이 사라지는 것이 벌이다.

| 요구사항 | 테스트 상황 → 기대 |
|---|---|
| 행동을 몸에 보낸다 | 왼 무릎 행동 -1 → 무릎 목표 -120도 |
| 서 있으면 보상 | 서 있는 한 스텝 → 보상 1 |
| 넘어지면 판을 끝낸다 | 몸통이 바닥에 닿음 → 끝난 판 수 +1 |
| 서 있으면 판이 계속된다 | 넘어지지 않음 **(경계)** → 판 계속 |

> 막히면 튜토리얼 창의 **💡 힌트**를 한 단계씩 연다 — ① 방향·핵심 개념 → ② 구조와 처리 순서 → ③ 핵심 로직 → ④ 기본 코드 + 빈칸 → ⑤ 완성 코드 + 해설.
> 빈칸 코드(④)와 정답(⑤)은 창에서만 보여 주고, [파일에 넣기]로 바로 넣을 수도 있다.

## 실행 및 검증

```
run_env.bat
mlagents-learn Assets/Humanoid/humanoid_config.yaml --run-id=stand
  → "Start training by pressing Play" 가 뜨면 Unity에서 Play
tensorboard --logdir results
```

`humanoid_config.yaml`의 `HumanoidStand`:

| 값 | 여기 | 왜 |
|---|---|---|
| `batch_size` / `buffer_size` | 2048 / 20480 | 넘어지는 모양이 매번 달라 편차가 크다 |
| `hidden_units` × `num_layers` | 256 × 2 | 관측 48 · 행동 18 |
| `gamma` | 0.99 | 약 2초 앞까지 본다 |
| `time_horizon` | 1000 | 한 판을 통째로 본다 |
| `max_steps` | 4,000,000 | 행동이 18개라 200만으로는 덜 배운다 (아래 표) |

**실측 학습 결과** (빌드 4개 × 영역 9개 = 에이전트 36개, `--num-envs=4`)

| 스텝 | 학습 중 평균 보상 |
|---|---|
| 20만 | 77 (처음엔 행동을 크게 흔들어 금방 넘어진다) |
| 60만 | 146 |
| 100만 | 297 |
| 140만 | 469 |
| 200만 | 618 ← 아직 오르는 중. 여기서 멈춘 모델은 30판 중 15판만 버텼다 |
| 300만 | 809 |
| 400만 | 약 860 (마지막 10만 스텝 평균) |

400만 스텝 = 약 15분 (에이전트 36개). 걸린 시간은 컴퓨터에 따라 다르다.
팔이 없던 초안(행동 12개)은 200만 스텝에 780이었다. **행동이 늘면 같은 점수까지 더 오래 걸린다.**

**학습 전후 비교** (같은 밀기 조건 · 30판 · 만점 1000)

| | 평균 보상 | 끝까지(1000스텝) 버틴 판 | 버틴 길이 중앙값 |
|---|---|---|---|
| 행동 0 (모터만, 2장 상태) | 343 | 1 / 30 | |
| 200만 스텝에서 멈춘 모델 | 692 | 15 / 30 | 999 스텝 |
| **400만 스텝 모델 (Inference Only)** | **927** | **28 / 30** | **999 스텝** |

학습 중 점수(약 860)보다 평가 점수(927)가 높은 이유: 학습 중에는 일부러 행동을 흔들며(탐험) 시험해 보기 때문이다.

**확인 체크리스트**

- [ ] Heuristic Only로 Play — 에러 없음, 밀려서 넘어지면 판이 다시 시작된다
- [ ] 실습 3-1 ~ 3-3 테스트 통과 (요구사항 전부 ✔)
- [ ] TensorBoard `Environment/Cumulative Reward`가 오른다
- [ ] `Environment/Episode Length`도 같이 오른다 (= 넘어지지 않고 오래 버틴다)
- [ ] 학습된 모델(`results/stand/HumanoidStand.onnx`, 직접 학습하지 않았으면 미리 학습해 둔 `Assets/Humanoid/results/HumanoidStand.onnx`)을 Model 칸에 넣고 `Inference Only`로 Play → 3초마다 밀려도 대부분 버틴다. `P`키로 직접 밀어 본다

## 자주 밟는 함정

| 증상 | 원인 |
|---|---|
| 실행 즉시 관측 에러 | Space Size(48)와 `AddObservation` 개수가 다르다 |
| 학습 초반 보상이 "가만히 있기"(343)보다 낮다 | 정상이다. 처음에는 행동을 무작위로 크게 흔들어 보기 때문에 금방 넘어진다 (실측: 20만 스텝에 77, 120만 스텝쯤에야 343을 넘었다) |
| 보상이 오르다 멈춘다 | 밀기가 너무 세다. `maxPush`를 줄여 먼저 배우게 하고 나중에 올린다 |
| 넘어졌는데 판이 안 끝난다 | 발 아닌 부품에 `BodyPart`가 없거나, 바닥에 Rigidbody를 붙였다 |
| 파이썬이 안 붙는다 | `Behavior Name`과 yaml의 키 이름이 다르다 |

## 이 장에서 배우는 것

1. **키보드 자리에 AI를 꽂는다.** 몸 입장에서는 숫자의 출처만 바뀐다.
2. **관측은 몸 기준으로.** 기울기는 "몸이 느끼는 아래쪽"으로 준다.
3. **곱하는 보상.** 조건 두 개를 동시에 만족해야 점수가 난다.
4. **판을 끝내는 것이 벌이다.** 벌점 없이도 넘어지기를 싫어하게 된다.
5. **일부러 어렵게 한다.** 밀지 않으면 "가만히 있기"만 배운다.
